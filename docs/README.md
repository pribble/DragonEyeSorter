# 文档索引

全仓文档的**唯一导航源**：设计文档与提交件在 `docs/`，代码侧说明在各目录 README，实测数据与决策沿革在 [log/](log/)。

## 怎么用这张表

- **事实裁决顺序**：板卡手册 / 原理图 / 实测数据 > [log/](log/) > 设计文档 > README。
- **唯一源**：同一事实只在该文档维护，其余文档引用它，不复制内容。
- **状态**：✅ 已实测可用 · 🟡 设计已定、待实物 · ⬜ 未做 / 待拍摄 · 草案 = 未拍板。
- 参数（型号、电压、bank、寄存器偏移、实测数字）一律查文档，不凭记忆复述；提方案时"待确认"要写明。

## 写作约定

1. **只写当前结论**：日期、决策沿革（「原来 X，后改为 Y」）、版本修正故事、复述踩坑经过一律写在 [log/](log/)；正文需要出处时给 log 链接。
2. **数字唯一源**：实测数字只维护在 [测试与验证](测试与验证.md)，明细给 log 链接；同一指标有新旧两次实测时写最新值，旧的放括号；未实测的标 ⚠。
3. **语言**：陈述句、列表、表格；不用口语、情绪、感叹与拟人表达（如"坑""血的教训""别忘了"）；一段只讲一件事，长句拆开。
4. **不写主机路径**：只允许仓库内相对路径、板端路径、`.env` 变量与 `<占位符>`（见 [AGENTS.md](../AGENTS.md) 硬性约定第 9 条）。
5. **一处维护**：同一事实只写一遍，其余改为链接；正文与本文地图的分工不一致时，先改本文声明，再改正文。

## 修订规则

| 变更类型 | 去处 |
|---|---|
| 设计意图 / 方案调整 | 直接改对应设计文档 |
| 实测 / 验证结果 | 新增 `log/YYYY-MM-DD-主题.md`，相关设计文档同步定性结论，数字汇总进 [测试与验证](测试与验证.md) |
| 结论被推翻 | 设计文档改写，log 留痕不删 |
| 决策沿革 / 被推翻的方案 | 只写 [log/](log/)，不写进正文 |
