# 06 · 软件与 UI

> PS 软件职责与 UI 方案。

## PS 职责边界

PS（双核 A35 + Linux）只做：调度状态机、物料跟踪队列维护、NPU 推理、UI、存储、网络。**不搬像素**——视频帧的搬运与处理都在 PL。

## 赛题解读

赛题要求"Linux 系统 + 基础交互界面；HDMI 可视化曲线 / 参数配置界面"。纯视频流展示不足以覆盖第二档要求，因此 UI 必须包含参数配置与曲线。

## 本地 UI（Qt，P0）

Qt over framebuffer/EGLFS，HDMI 输出。视频层直接用 PL 的 VDMA framebuffer，Qt 只画叠加层和控件。

| 区块 | 内容 |
|---|---|
| 实时画面 | 原始帧 + 检测框 + 类别 + 置信度 + 测得尺寸 |
| 实时状态 | 节拍、计数、良率、臂 / 拨叉 / 总线状态 |
| 参数配置 | 置信度阈值、图像算子参数、带速、类别→料盒映射、启停 / 急停、标定入口 |
| 曲线 | 良率趋势、节拍趋势、推理耗时、舵机电流 / 温度 |
| 告警 | 超限 / 失步 / 过载 / 总线异常，联动三色灯 |

## Web UI（P1）

复用上一届的 Vue 单页应用布局（原图 / 缺陷图列表 / 统计图表 / 手动控制 / 参数设置），改造点：

- 后端换成本项目的 REST + WebSocket；
- MJPEG 推流优先走板载 JPU 硬件编码器，尽量不占 A35。

职责分工：**本地屏管"实时 + 操作"，Web 管"历史 + 远程 + 报表"。**

## 语音 + LLM 助手（P2）

- 链路：麦克风 → 触发 → ASR → LLM（function calling）→ 结构化指令 → PS 校验 → AXI → PL。
- 三类能力：查询（产量 / 良率 / 分布）、控制（调速 / 暂停 / 改映射）、诊断（读舵机遥测历史）。
- **安全原则：LLM 不直接碰硬件**，只输出结构化指令，由 PS 调度层校验后才写寄存器。
- **必须有离线降级**：断网退回本地固定命令词表，核心指令照常可用。答辩现场网络不可赌。

## 存储

SQLite 记录 + NG 图片本地存储（eMMC/SD）。图片落盘策略（保留天数、容量上限）待定。
