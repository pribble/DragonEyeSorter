# 06 · 软件与 UI

> PS 软件职责、界面、存储与总线。开发与部署方法见 [09-开发环境与构建](09-开发环境与构建.md)。

## PS 职责边界

PS（双核 A35 + Linux）做：NPU 推理调度、视觉定位 (x, y, θ)、跟踪表与抓取调度、机械臂 IK、CAN、UI、存储、网络。**不搬整帧像素**；时序关键的脉冲、总线帧、IO 采样在 PL。

- PL 寄存器经 `/dev/mem` mmap 访问（已验证可用），寄存器偏移头文件放 `ps/common/`，与 [03-PL设计](03-PL设计.md) 同源。
- 板上已有：Qt 5.15.8、ArmNN + Alnpu、OpenCV 4.7、FFmpeg；没有 SQLite（把 amalgamation 编进应用）。
- 交叉编译用 FD 自带的 aarch64 工具链（glibc 2.25，与板上一致）。

## 赛题解读

赛题原文"Linux 系统 + 基础交互界面；HDMI 可视化曲线 / 参数配置界面"。纯视频流不够，界面必须有**参数配置**与**曲线**。初赛是线下审核材料（PPT + 技术文档 + 视频），每项硬性要求都要在视频里有看得见的镜头。

## 本地 HDMI 界面（Qt，P0）

视频层用 PL 的 VDMA framebuffer，Qt 只画叠加层和控件。

**显示通路实测（2026-10-10，以本段后半「更正」为准）**：`/dev/fb0` = anlogic `vdmafb`（寄存器 `0x8010_0000`，1920×1080，24bpp）。厂家 `vision/hdmi.cpp` 的 `hdmi_t::show()` **不拷贝整帧**：
刷缓存后把相机缓冲的物理地址写进 `0x8010_0800`（HDMI 读 DMA 基地址），等于翻页 → 60fps 显示可行：检测框 / 文字直接画进相机缓冲（只动小区域），再翻页。
厂家 demo 显示 28fps 是它的串行流水限制，不是显示通路限制。⚠ 待定：Qt 控件层怎么与 60fps 视频合成 —— 整帧由 PS 合成不现实（读 DMA 缓冲慢，见 [ps/README](../ps/README.md)），
可选「每帧往相机缓冲贴一块预渲染的侧边栏（约 400×1080，约 2~4ms）」或 PL 叠加（ERAM 余量很少）。另注意相机缓冲是 4 字节 / 像素，fb0 声明 24bpp，翻页前确认读 DMA 的像素格式设置。

**更正 + 实测（10-10 17:30）**：本比特流里 `0x8010_0000` 那组 HDMI 寄存器全读 0，`hdmi_t`（写死 32bpp）是给别的比特流用的。真正扫描输出的是 **`vdma@0x8020_0000`**：
V_SIZE 1080、H_SIZE = 行跨度 5760（**24bpp BGR**）、`START_1`（0x5C）= fb0 显存 `0x17D0_0000`；显示时序 1920×1080 @ **60.6Hz**（像素时钟 150MHz）。
相机是 32bpp BGRA，不能直接翻页 → **每帧 CPU 转一次 BGRA→BGR 进两块 CMA 显示缓冲之一，再写 `START_1` 翻页**：
`des_app display` 实测 **60fps 显示**，转换平均 6.2ms（OpenCV NEON）、刷缓存 0.6ms，8s 只在开头丢 1 帧（首帧缺页 22ms）；退出时恢复 `START_1`。
→ **60fps 显示不需要改 PL**；每帧占一个核约 7ms，定位（6.8ms）放另一个核。检测框 / 文字直接画进 BGR 显示缓冲（`cv::putText` 等，开销很小）。
Qt 控件层仍待定：可把侧边栏预渲染好，每帧贴进 BGR 缓冲（约 400×1080×3，约 1~2ms）。

**`des_app live`（10-10 晚）：带检测叠加的 60fps 显示已跑通**（20s 1200 帧 59.96fps；每帧显示 11.7ms = 转换 7.6 + 叠加 3.5 + 刷缓存 0.6）。踩过的坑，做 UI 时照此办：
- **显示缓冲（CMA）不走缓存**：OpenCV 在上面逐像素画大面积（填充矩形、粗线）每帧要好几毫秒 → 大块内容先在普通内存里画好，再按行 `memcpy` 贴进去（宽写，318KB 约 0.3ms）。
- **`putText` 线宽 2 很贵**（Hershey 笔画逐段画粗线，一行字 1~2ms）→ 状态文字 10Hz 重画、其余帧只贴图；框上标签用线宽 1。
- **OpenCV 用单线程**（`cv::setNumThreads(1)`），两个核由我们自己分：核 0 = SCHED_FIFO 取帧 + 显示，核 1 = 定位 / 跟踪。
- 一开始叠加层没优化时只有 40fps，而且取帧也跟着丢（显示循环超过 16.7ms，就赶不上在下一帧开始前重新提交 DMA）。
- **看峰值不看平均**：`run` 模式下平均 12ms 仍每秒丢约 8 帧——每 6 帧一次的状态栏文字重画把个别帧推到 18ms。状态栏改由核 1 的工作线程渲染（10Hz），核 0 只贴图后：`run` 20s 1201 帧 60.00fps（只启动时丢 1 帧），每帧最大 12.2ms。

## 工业总线

- **CAN（P0）**：PC 上的 USB-CAN 当"产线 PLC"，下发启停 / 调速，板子回报计数与状态。走 PS 的 SocketCAN（内核已有 `can0`/`can1`）。
- **RS485 Modbus（P1）**：如 485 继电器 + 三色灯报警，构成双总线。

### CAN 协议 v1（10-10 起草并在板上自测通过，PC 端按此写）

经典 CAN 2.0A（11 位 ID），500kbit/s（板载收发器 SN65HVD232 只支持经典 CAN），多字节**小端**。定义在 [ps/bus/can_proto.h](../ps/bus/can_proto.h)（编解码函数也在里面）。

| 方向 | ID | 长度 | 内容 |
|---|---|---|---|
| PLC→本机 | 0x100 CMD | 2 | [命令, 序号]：1 启动 / 2 停止 / 3 联锁暂停 / 4 恢复 / 5 复位报警 |
| PLC→本机 | 0x101 SPEED | 3 | [带速 ×10 (u16, 0.1mm/s), 序号] |
| PLC→本机 | 0x102 RECIPE | 2 | [配方号, 序号] |
| PLC→本机 | 0x103 PLC_HB | 1 | [计数]，≥2Hz；1s 收不到 → STATUS 里清掉「PLC 在线」位（应用可据此联锁暂停） |
| 本机→PLC | 0x180 ACK | 3 | [命令 ID 低字节, 序号, 结果 0 成功 / 1 状态不允许 / 2 数值不对 / 3 未知] |
| 本机→PLC | 0x181 STATUS | 8 | [状态 0 空闲 1 运行 2 暂停 3 急停 4 故障, 标志 b0 带在走 b1 臂忙 b2 报警 b3 PLC 在线 b4 已标定, 带速×10 (u16), 报警码, 心跳, 运行秒数 (u16)]，10Hz |
| 本机→PLC | 0x182 COUNTS | 8 | [总数, 良品, NG, 复检] 各 u16，1Hz + 变化时 |
| 本机→PLC | 0x183 PART | 8 | [件号 u16, 类别（0xFF 未知）, 去向 0 抓取 1 翻板 2 复检, 料盒 / 出口, 置信度 %, 主尺寸 ×100 (u16, 0.01mm；齿轮外径 / 齿条长度，几何测量值，0 = 没测到)] |
| 本机→PLC | 0x184 ALARM | 4 | [报警码, 级别, 细节 u16] |

**联动实测（10-11，`des_app run --can can0` + `canplc` 扮 PLC，回环）**：上电空闲 → 未启动时「恢复」被拒 → 启动（应答 10ms，皮带走、STATUS 带速 50）→ 设 80mm/s（运行中立即生效，PL 平滑过渡）→ 设 500 判「数值不对」→ 联锁暂停（皮带减速停）→ 恢复 → 停止，状态、标志位（皮带在走 / PLC 在线）全部正确。

**起接口**：`ps/bus/can_up.sh can0 normal`（接 PC 的 USB-CAN）或 `can_up.sh can0 loopback`（自测；控制器只有 FD 模式能回环，经典帧照样收发）。

**自测（`ps/tests/test_can.c`，回环，两个 socket 分别扮 PLC 和本机）**：编解码 6 项；命令→应答往返 1000/1000，**平均 356µs**（最大 429µs）；
按 200 / 1000 / 2000 帧/s 连续发，**零丢失、零错序**；接口错误计数 0。⚠ 不限速连发（约 9000 帧/s，超过总线物理上限）时回环会**无声丢帧**
（TX 计数齐、RX 少、错误计数不动）——应用只用每秒几十帧，不受影响，但 2h 稳定性测试要按实际速率发。

## 语音 + LLM 助手（P2）

- 链路：麦克风 → 触发 → ASR → LLM（function calling）→ 结构化指令 → PS 校验 → AXI → PL。
- **LLM 不直接碰硬件**，只输出结构化指令，由 PS 调度层校验后才写寄存器。
- **必须有离线降级**：断网退回本地固定命令词表。
- 不挤占 P0/P1 的任何时间。

## 存储

SQLite 记录每件的类别、分级、测量值、去向、时间戳 + NG / 复检件的 ROI 图片，存在 SD 卡根分区（已持久化）。容量不够时在 SD 剩余空间建数据分区。板上无 RTC，时间戳需开机对时。
