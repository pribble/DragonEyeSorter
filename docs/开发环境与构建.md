## 启动链与 `BOOT.bin`

```
上电 → BootROM 读拨码（SD = ON-OFF-OFF，eMMC = OFF-OFF-OFF）→ 从 SD 的 p1 分区读 BOOT.bin
     ├─ FSBL     初始化 DDR / 时钟 / PS 配置，把比特流烧进 PL
     ├─ 比特流    整个 PL 设计
     └─ U-Boot   执行 boot.scr：读入 uImage.lz4（内核）+ system.dtb（设备树）→ bootm
     → 内核挂载根分区 /dev/mmcblk0p2（ext4）→ /init → BusyBox init
```

| 想改什么 | 改哪个文件 | 位置（板上） |
|---|---|---|
| PL 逻辑 | `BOOT.bin` | `/mnt/mmcblk0p1/BOOT.bin` |
| 外设地址 / 中断（需内核驱动时） | `system.dtb` | `/mnt/mmcblk0p1/system.dtb` |
| 启动参数 | `boot.cmd` → `mkimage` → `boot.scr` | `/mnt/mmcblk0p1/boot.scr` |
| 内核 / 驱动 | `uImage.lz4` / `.ko` | 需开发包 |
| 应用、配置、数据 | 直接放文件 | 根分区任意位置（持久化） |

`BOOT.bin` 内部结构（BootGen `-read` 实测，**0 基命名**）：**P0** FSBL（载入 OCM 0x61000000）/ **P1** 比特流（`destination_device=pl`）/ **P2** U-Boot（载入并执行于 0x200000）；P1 一律接我们自己的比特流（`make_bootbin.ps1 -Bit` 必填）。

## SD 卡布局与烧卡

持久化改造只改了启动方式：根文件系统放 p2（ext4），p1 只放启动件；厂家 initramfs 启动方式留在 p1 的 `initramfs_backup/` 供回退。

| 分区 | 文件系统 | 板上挂载点 | 内容 |
|---|---|---|---|
| p1（252MB） | FAT32 | `/mnt/mmcblk0p1` | `BOOT.bin` `boot.scr` `system.dtb` `uImage.lz4` + `initramfs_backup/`（回退用） |
| p2（3.6GB，可用约 2.9G） | ext4 | `/`（另被 automount 再挂一次到 `/mnt/mmcblk0p2`，同一分区） | Buildroot 根文件系统（从 `uInitrd.lz4` 解出）+ 我们的全部文件 |

与厂家版的差别只在 `boot.scr`：不加载 initrd，`bootargs` 追加 `root=/dev/mmcblk0p2 rootwait rootfstype=ext4 rw init=/init`，`bootm 0x10000000 - 0x14000000`。

**现有持久化卡已做好并上板通过**（[log/2026-10-08](log/2026-10-08-持久化SD与BOOT.bin打包.md)），日常只换 `BOOT.bin`；要新做卡：用厂家预装的卡，或照本节布局手工复刻（`boot/` 取自厂家 NPU demo 的 `demo/boot/`），换卡后 `ssh-keygen -R $BOARD_IP`。

烧卡用 `scripts/sd_image/flash_to_disk.ps1`（Windows 管理员，先 `Get-Disk` 认准磁盘号）或 balenaEtcher / Rufus，见 [scripts/README](../scripts/README.md)「sd_image」。卡上剩余约 25GB 未分区，需要时 `fdisk` 建 p3 + `mke2fs` 作数据分区（板上无 `resize2fs`，不能直接扩 p2）。p1 上实际文件与根分区各类文件落点见 [板端布局](板端布局.md)。

## PL：构建与打包

1. **改源码**：TD 6.2.1 打开 `pl/soc_base/soc_prj.al`；自研模块放 `src/des/`，新模块在 `system_top.v` 例化；寄存器做成 AXI-Lite 从机挂 `design_0`；管脚加进 `src/constraint/`（CEP = BANK11，3.3V）。改动直接提交进 `pl/soc_base/`。
2. **编译**：界面依次 Synthesis → Place → Route → Bitstream；比特流产物 `pl/soc_base/soc_prj_Runs/phy_1/soc_prj.bit`。
3. **打包**：`scripts/bootbin/make_bootbin.ps1 -Bit <比特流>`，几秒钟，产物 `scripts/bootbin/BOOT.bin`。
4. **换比特流**：见「部署与运行」。**命令行编译**：在 `soc_prj_Runs/syn_1`、`phy_1` 下依次运行 `td_commands_prompt.exe $TD_ROOT/scripts/DefaultFlow.tcl < NUL>`（路径用正斜杠，反斜杠会被 Tcl 吃掉）。综合约 6 分钟、布局约 10 分钟、布线约 19.5 分钟（建议 16GB RAM + 4 核以上）；长时间编译用独立进程（如 `Start-Process`），免得被会话后台任务管理误停。**出错也返回 exit 0**：判断成败只能看 run 目录的 `.<step>.end.f` 标记与产物文件。

**run 目录里"能跑起来"的 4 份小文件已入库**（`syn_1/{soc_prj.prj,settings.cfg}`、`phy_1/{soc_prj.prj,settings.cfg}`，靠 `git add -f`；其余数据库、日志、比特流仍被 `**/*_Runs/` 忽略）：两个 `settings.cfg` 是 `DefaultFlow.tcl` 的流程参数（起止步骤 / 器件 / 封装 / speed；phy 那份多一行 `parent ../syn_1`）；两个 `soc_prj.prj` 是工程文件，`phy_1` 缺了报 `PRJ-8642 ERROR: Project file soc_prj.prj does not exist.` 并掉进 `td >`。详见 [pl/soc_base/soc_prj_Runs/README.md](../pl/soc_base/soc_prj_Runs/README.md)。

**合并后全量重编**（`soc_base/` 单工程布局）：四步标记齐全，自研各域 0 违例，违例端点全在厂家 VTC 域的跨域 recovery 路径；资源与时序数字见 [测试与验证](测试与验证.md)，过程见 [log/2026-10-13-合并后PL全量重编](log/2026-10-13-合并后PL全量重编.md)。

**什么时候要重编 FSBL**：只改 PL 逻辑不用；改了 `design_0` 的 PS 配置（增删 AXI 口、FCLK、MIO、DDR）要用 FD 按新 `.hpf` 重编（Platform `soc_base` + Application `soc_fsbl`，模板 FSBL、名字不能改），经 `-Fsbl` 传入；U-Boot 不需要重编。**AXI 地址窗口一次划够并固定**，之后只改模块内部，设备树不用动。

**打包与零件**：零件已入库 `scripts/bootbin/parts/`（`fsbl.elf` 与厂家原件逐字节相同、`u-boot.elf` 由厂家 BOOT.bin 解出，台账 [parts/MD5SUMS.txt](../scripts/bootbin/parts/MD5SUMS.txt)），脚本每次打包校验 `u-boot.elf` 的 MD5；命令见 [scripts/README](../scripts/README.md)「bootbin」，只有重建丢失的 `parts/u-boot.elf`、取厂家原始 `fsbl.elf` 时才需要 `-VendorDemo <厂家 demo 目录>`。

## PS：构建

```bash
# 1. 加载 .env：Bash / WSL 用 source scripts/env_loader.sh，PowerShell 用 . .\scripts\env_loader.ps1
# 2. 编 all 目标（des_app / des_tool / desreg / canplc / test_scheduler / test_calib /
```

**PS 产物分四层**（`des_app` / `des_tool` / `test_*` / `desreg`、`canplc`），只有 `des_app` 进部署清单；分层、构建目标与部署去向见 [ps/README](../ps/README.md)。

- **访问 PL 寄存器**：`/dev/mem` 可用（`devmem 0x80300000` → `0x1BB00000`），应用以 root 运行直接 `mmap`，不需要写驱动；调试直接用 `devmem <地址> [32 <值>]`。
- PL 中断通知应用需 UIO（改设备树，可能改内核配置）→ 届时再用米联客开发包；SQLite 板上没有，把单个 `sqlite3.c` 直接编进应用。

## 部署与运行

传文件三种方式：网线 + `scp`（所有文件，见下）、SD 卡插电脑（只能放 p1，Windows 看不到 ext4）、U 盘（所有文件，插板子 USB 自动挂载到 `/mnt/sdX`）。

网线插板子的 **PS 网口**；固定 IP、密钥与 `$BOARD_HOST` 别名都是一次性配置，见 [环境与上手](环境与上手.md) §4。板端命令一律写 `ssh $BOARD_HOST` / `scp <本地文件> $BOARD_HOST:<板端路径>`。

**产品件走部署器**（唯一清单）：

```powershell
.\scripts\deploy\deploy.ps1 -DryRun                 # 只对比，不传文件

```

清单在 [scripts/deploy/manifest.tsv](../scripts/deploy/manifest.tsv)（哪些文件属于板端产品运行时、分别上到哪），用法与 `-Stage` / `-Dest` 见 [scripts/deploy/README](../scripts/deploy/README.md)；板上落点、权限、行尾与相对引用见 [板端布局](板端布局.md)。测试与调试件（`des_tool`、`des_tool.sh`、`desreg`、`canplc`、`test_*`、`pl_check.sh` / `soak.sh` / `display_check.sh`）不进清单，要用时手动 `scp`。

**换 `BOOT.bin`**（只改 PL 逻辑时）：

```bash

scp scripts/bootbin/BOOT.bin $BOARD_HOST:/root/BOOT.bin.new
```

## 操作禁忌

本节是板上操作禁忌的唯一源（关机 / eMMC / 换 `BOOT.bin` / BitWriter）；AI 侧的摘要见 [AGENTS.md](../AGENTS.md)「红线」。

- **关机用 `/root/des/shutdown.sh`**（快捷方式「6_关机」），之后 **2 分钟内断电**。`halt` / `poweroff` 后板子必然自己复位重启（UG1214 第 12 / 29 章）：PS 看门狗 `dw_wdt` @0xF8410000 在芯片**永久在线域**、配置为始终使能（`WDT_CR` 写 0 读回仍 0x09），设备树没给复位线，软件关不掉——CPU 一停没人喂，约 32s 复位。`shutdown.sh` 先停 `des_app`，再把 `WDT_TORR` 调到最大档（约 127s）并重装计数器，最后 `halt`（文件系统已卸载，屏幕黑后即可断电）。板子没有软件可控的电源开关，断电只能拔电 / 关开关。
- **eMMC（`/mnt/mmcblk1p*`）是出厂救生艇系统，保持原样**。
- 换 `BOOT.bin` 前把原文件改名备份（如 `BOOT.bin.vendor`），起不来就改回。
- **BitWriter 已不用于 PL 上板**（会覆盖 MIPI / VDMA / NPU，只在停 Linux 时能调试）；上板一律走 `BOOT.bin`。
