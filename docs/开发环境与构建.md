## 启动链与 `BOOT.bin`

```
上电 → BootROM 读拨码 → 从 SD 的 p1 分区读 BOOT.bin
     ├─ FSBL     初始化 DDR / 时钟 / PS 配置，把比特流烧进 PL
     ├─ 比特流    整个 PL 设计
     └─ U-Boot   执行 boot.scr：读入 uImage.lz4（内核）+ system.dtb（设备树）→ bootm
     → 内核挂载根分区 /dev/mmcblk0p2（ext4）→ /init → BusyBox init
```

| 想改什么 | 改哪个文件 |
|---|---|
| PL 逻辑 | `BOOT.bin` |
| 外设地址 / 中断（需内核驱动时） | `system.dtb` |
| 启动参数 | `boot.cmd` → `mkimage` → `boot.scr` |
| 内核 / 驱动 | `uImage.lz4` / `.ko`，需开发包 |
| 应用、配置、数据 | 直接放根分区任意位置（持久化） |

`BOOT.bin` 内部结构（BootGen `-read` 实测，**0 基命名**）：**P0** FSBL（载入 OCM 0x61000000）/ **P1** 比特流（`destination_device=pl`）/ **P2** U-Boot（载入并执行于 0x200000）；P1 一律接我们自己的比特流（`make_bootbin.ps1 -Bit` 必填）。

## SD 卡布局与烧卡

持久化改造只改了启动方式（根文件系统放 p2）：

| 分区 | 文件系统 | 板上挂载点 | 内容 |
|---|---|---|---|
| p1（252MB） | FAT32 | `/mnt/mmcblk0p1` | `BOOT.bin` `boot.scr` `system.dtb` `uImage.lz4` + `initramfs_backup/`（厂家 initramfs 启动方式，回退用） |
| p2（3.6GB，可用约 2.9G） | ext4 | `/`（另被 automount 再挂一次到 `/mnt/mmcblk0p2`，同一分区） | Buildroot 根文件系统（从 `uInitrd.lz4` 解出）+ 我们的全部文件 |

与厂家版的差别只在 `boot.scr`：不加载 initrd，`bootargs` 追加 `root=/dev/mmcblk0p2 rootwait rootfstype=ext4 rw init=/init`，`bootm 0x10000000 - 0x14000000`。

**持久化卡已做好并上板通过**（[log/2026-10-08](log/2026-10-08-持久化SD与BOOT.bin打包.md)），日常只换 `BOOT.bin`；新做卡用厂家预装的，或照本节布局复刻（`boot/` 取自厂家 NPU demo 的 `demo/boot/`），换卡后 `ssh-keygen -R $BOARD_IP`。

烧卡用 `scripts/boot/flash_to_disk.ps1`（Windows 管理员，先 `Get-Disk` 认准磁盘号）或 balenaEtcher / Rufus，见 [scripts/README](../scripts/README.md)「boot」。卡上剩余约 25GB 未分区，需要时 `fdisk` 建 p3 + `mke2fs` 作数据分区（板上无 `resize2fs`，不能直接扩 p2）。

## PL：构建与打包

1. **改源码**：TD 6.2.1 打开 `pl/soc_base/soc_prj.al`；自研模块放 `src/des/`，新模块在 `system_top.v` 例化；寄存器做成 AXI-Lite 从机挂 `design_0`；管脚加进 `src/constraint/`（CEP = BANK11，3.3V）。改动直接提交进 `pl/soc_base/`。
2. **编译**：界面依次 Synthesis → Place → Route → Bitstream（同一会话内约束全程有效，等价于命令行单进程）；比特流产物 `soc_prj.bit` 在本次 run 目录。
3. **打包**：`scripts/boot/make_bootbin.ps1 -Bit <比特流>`，几秒钟，产物 `scripts/boot/BOOT.bin`。
4. **换比特流**：见「部署与运行」。

**命令行编译必须单进程**（`read_design`→`bitgen` 一个 TD 进程跑完）：在 `soc_prj_Runs/` 下新建 run 目录，放 **`phy_1` 的 `soc_prj.prj`**（含 `<opt_timing>high</opt_timing>` 与 `<compress>on</compress>`）与一份 `settings.cfg`——**以 `phy_1/settings.cfg` 为底**，只把 `start_step` 由 `opt_place` 改为 `read_design`、`end_step` 保持 `bitgen`，然后在该目录下运行 `td_commands_prompt.exe $TD_ROOT/scripts/DefaultFlow.tcl < NUL>`（路径用正斜杠，反斜杠会被 Tcl 吃掉）。综合约 8~10 分钟、布局 15~21 分钟、布线 25 分钟~（视拥堵，判据见下）；长时间编译用独立进程（如 `Start-Process`）免被会话后台任务管理误停。**出错也返回 exit 0**：判断成败只能看 run 目录的 `.<step>.end.f` 标记与产物文件。

**不要用两段式（`syn_1` 综合 + `phy_1` 布局布线）做正式构建**：两段式 phy 段重放 SDC 时 PLL 引脚时钟对象尚未建立，`timing.sdc` 里 `get_clocks {…u_DR1_PHY_PLL.clkc[N]}` 匹配为空、`set_clock_groups` 全部 no-op（两段式 phy 初始段 12 条 `USR-6001`，单进程 0 条），10-26 / 10-28 两次 route 不收敛皆由此（根因与修复见下）。两段式只作综合资源 / gate 估计的只读实验，其 place / route 结果不能作为时序签核证据。

**run 目录里"能跑起来"的 4 份小文件已入库**（`syn_1/`、`phy_1/` 各一份 `soc_prj.prj` 与 `settings.cfg`，`git add -f`；缺 `soc_prj.prj` 报 `PRJ-8642` 掉进 `td >`；其余文件被 `**/*_Runs/` 忽略）。单进程正式构建的 run 目录同样只需要这两份文件。详见 [pl/soc_base/soc_prj_Runs/README.md](../pl/soc_base/soc_prj_Runs/README.md)。

**合并后全量重编**（`soc_base/` 单工程布局）：四步标记齐全，自研各域 0 违例，违例端点全在厂家 VTC 域的跨域 recovery 路径；数字见 [测试与验证](测试与验证.md)，过程见 [log/2026-10-13-合并后PL全量重编](log/2026-10-13-合并后PL全量重编.md)。

**什么时候要重编 FSBL**：只改 PL 逻辑不用；改了 `design_0` 的 PS 配置（增删 AXI 口、FCLK、MIO、DDR）要用 FD 按新 `.hpf` 重编（Platform `soc_base` + Application `soc_fsbl`，模板 FSBL、名字不能改），经 `-Fsbl` 传入；U-Boot 不需要重编。**AXI 地址窗口一次划够并固定**，之后只改模块内部，设备树不用动。

**打包与零件**：零件已入库 `scripts/boot/parts/`（`fsbl.elf` 与厂家原件逐字节相同、`u-boot.elf` 由厂家 BOOT.bin 解出，台账 [parts/MD5SUMS.txt](../scripts/boot/parts/MD5SUMS.txt)），打包时校验 `u-boot.elf` 的 MD5；命令见 [scripts/README](../scripts/README.md)「boot」，仅重建丢失的 `parts/u-boot.elf`、取厂家原始 `fsbl.elf` 时才需要 `-VendorDemo <厂家 demo 目录>`。

### 编译时间与拥堵排查

**10-28 route 不收敛的根因与修复**：两段式构建在 phy 段丢失 `timing.sdc` 的全部 clock group（**判据看最终 STA**：VTC 三个跨域 path group 消失，不看运行期重放告警），叠加 `timing.sdc` 缺 VTC ↔ NPU / 150M 异步组，25 个厂家 CDC 端点被当同步路径优化，高拥堵下 R&R 不收敛。修复 = 构建改单进程 + `timing.sdc` 追加 2 条异步组；修复后单进程构建 59m16s（place 14m56s + route 33m32s，默认 `high`，Routed 0 违例）。见 [log/2026-10-28-PL第六轮构建收敛](log/2026-10-28-PL第六轮构建收敛.md)。

**怎么判断是拥堵 R&R 不收敛、不是普通慢**：

- **步骤标记**：run 目录按步产生 `.<step>.begin.f` / `.<step>.end.f`（如 `.opt_place.end.f`）；缺 `.opt_route.end.f` 就是没跑完。TD **出错也返回 exit 0**，只能看标记与产物。
- **place 后拥堵**：读 run 目录 `place.qor` 的 `Setup WNS/TNS/Num of violated S-EP`（**第一判据**）、`Over 100% util #tile` / `Top1% tile` / `Max level` / `Congestion Window` / `Wire length`。**约束生效时 place 的 S-EP 应为 0**；不能只看 tile 数——S-EP 为 0 的好布局也可能有数百个 >100% tile，单看 tile 数会误杀（历史对照见 log）。
- **route 日志**：run 目录 `td_*.log` 里 `Stage 2.5.x` 的 `Rip-up And ReRoute`——看每轮 `over cnt` 与单轮耗时；数值降不到 0、单轮 100~300s、阶段反复重做即判不收敛。
- **归因**：把违例端点按时钟域 / 模块归类（自研域、厂家明文域、厂家加密 IP，加密 IP 内部改不了）；历史各版域划分与端点归属见 [测试与验证](测试与验证.md)（阶段验证）与 [log](log/README.md)。

**重编要点**：

- **布局检查点**：单进程跑到 `opt_place` 结束（`.opt_place.end.f` 出现、`place.qor` 刚写出）立刻读 QoR（先看 S-EP 是否 0，再看拥堵 / 线长是否比历史差太多）；不达标就杀进程重跑（损失约 28 分钟，含综合）。**不要**把检查点做成「place 一段 + route 一段」——那正是约束丢失的路径。
- **机器与内存纪律**：跑前 `wsl --shutdown`、停仿真与其他会话；free RAM < 6GB 不进 route（route 峰值约 5.5GB）；同一时间只跑一个 TD。
- **工程文件不是杠杆**：删文件收益≈0 且有断链风险——维持现状（数据见 [log](log/README.md)）。
- **约束与构建档**：`timing.sdc` 里 VTC ↔ NPU 为异步组；**VTC ↔ 150M 是双向 `set_max_delay 5.0 -datapath_only`**（视频异步 FIFO 的格雷码指针，整组声明异步会让比特流偶发黑屏重连，见 [PL设计](PL设计.md)）；不加 VTC↔TMDS（该组需 5× 相位关系）。新比特流上板除 `pl_check.sh` 外要同屏目视（同一台屏与线，≥20 分钟或照常使用 1 小时）。`opt_timing` high→medium 仍是布局不达标时的**候选构建档**（scratch 目录实测 40m04s 收敛），最终时序不如 v16，采用前必须上板复核，不改仓库工程文件。
- **后备 recipe（不推荐，仅应急）**：两段式 phy 阶段不能在 SDC 上签核，但可在 phy 里 `update_timing` 后用 Tcl 对完整时钟名 `set_clock_groups -asynchronous` 当场生效。代价是「place 无约束 / route 有约束」混合口径，结果不能与单进程构建直接对比（实测见 [log](log/README.md)）。

bash pl/sim/equiv/run_equiv.sh <test>    # 单目标

### 主机快速回归（WSL，免交叉、免板）

不碰 SDK 的三个测试用宿主 g++ 直接编跑（改 sched / 纯逻辑、Modbus-TCP、RS485 PDU 后的快车道；编译参数与 `ps/Makefile` 一致）：

```bash
cd ps
g++ -std=c++17 -O2 -Wall -Wextra -Isrc/app -Isrc/hw -Isrc/sched -Isrc/measure -Isrc/ui -Isrc/vision -Itests \
    -o /tmp/test_scheduler tests/test_scheduler.cpp src/sched/*.cpp && /tmp/test_scheduler
g++ -std=c++17 -O2 -Wall -Wextra -Isrc/app -Isrc/hw -Isrc/sched -Isrc/measure -Isrc/ui -Isrc/vision -Itests \
    -o /tmp/test_modbus tests/test_modbus.cpp src/hw/modbus_tcp.cpp -lpthread && /tmp/test_modbus
gcc -O2 -Isrc/app -Isrc/hw -Itests -c -o /tmp/des_hw.o src/hw/des_hw.c && \
g++ -std=c++17 -O2 -Wall -Wextra -Isrc/app -Isrc/hw -Isrc/sched -Isrc/measure -Isrc/ui -Isrc/vision -Itests \
    -o /tmp/test_rs485 tests/test_rs485.cpp src/hw/modbus_rtu.cpp src/app/rs485_io.cpp src/app/util.cpp /tmp/des_hw.o -lpthread && /tmp/test_rs485
```

退出码 = 失败项数（与板端一致）；跑之前不用停任何服务、不碰相机 / 总线。

CAN 链路层（`test_can`）也能在 WSL 主机跑：root 建一块虚拟 CAN 口（WSL 重启后重做）：

```bash
wsl -u root ip link add dev vcan0 type vcan && wsl -u root ip link set vcan0 up   # WSL 内：sudo 同效
gcc -O2 -Ips/src/app -Ips/src/hw -Ips/tests -o /tmp/test_can ps/tests/test_can.c && /tmp/test_can vcan0 500
```

vcan 不需要 `can_up.sh` 的比特流配置位（SocketCAN 回环默认开），覆盖命令→ACK 往返、三种速率流与接口错误计数。

**PS 产物分四层**（`des_app` / `des_tool` / `test_*` / `desreg`、`canplc`），只有 `des_app` 进部署清单；分层、构建目标与部署去向见 [ps/README](../ps/README.md)。

- **访问 PL 寄存器**：`/dev/mem` 可用（`devmem 0x80300000` → `0x1BB00000`），应用以 root 运行直接 `mmap`，不需要写驱动；调试直接用 `devmem <地址> [32 <值>]`。
- PL 中断通知应用需 UIO（改设备树，可能改内核配置）→ 届时再用米联客开发包；SQLite 板上没有，把单个 `sqlite3.c` 直接编进应用。

## 部署与运行

传文件三种方式：网线 + `scp`（见下）、SD 卡插电脑（只能放 p1，Windows 看不到 ext4）、U 盘（插板子 USB 自动挂载到 `/mnt/sdX`）。网线插板子的 **PS 网口**；固定 IP、密钥与 `$BOARD_HOST` 别名都是一次性配置，见 [环境与上手](环境与上手.md) §4。

**产品件走部署器**（唯一清单）：

```powershell
.\scripts\deploy\deploy.ps1 -DryRun                 # 只对比，不传文件
.\scripts\deploy\deploy.ps1                         # 部署：刷新 out/ → 差异 → 传输 → 校验
.\scripts\deploy\deploy.ps1 -WithService            # 要更新 des_app 时加上：脚本自己停 / 起自启服务
.\scripts\deploy\deploy.ps1 -Dest /root/des/test    # 整份另装到该目录，试新版而不动生产件
```

## 操作禁忌

本节是板上操作禁忌的唯一源（关机 / eMMC / 换 `BOOT.bin` / BitWriter）；AI 侧的摘要见 [AGENTS.md](../AGENTS.md)「红线」。

- **关机用 `/root/des/shutdown.sh`**（快捷方式「6_关机」），之后 **2 分钟内断电**。`halt` / `poweroff` 后板子必然自己复位重启（UG1214 第 12 / 29 章）：PS 看门狗 `dw_wdt` @0xF8410000 在芯片**永久在线域**、配置为始终使能（`WDT_CR` 写 0 读回仍 0x09），设备树没给复位线，软件关不掉——CPU 一停没人喂，约 32s 复位。`shutdown.sh` 先停 `des_app`，再把 `WDT_TORR` 调到最大档（约 127s）并重装计数器，最后 `halt`（文件系统已卸载，屏幕黑后即可断电）。
- **eMMC（`/mnt/mmcblk1p*`）是出厂救生艇系统，保持原样**。
- 换 `BOOT.bin` 前把原文件改名备份（如 `BOOT.bin.vendor`），起不来就改回。
- **BitWriter 已不用于 PL 上板**（会覆盖 MIPI / VDMA / NPU，只在停 Linux 时能调试）；上板一律走 `BOOT.bin`。
