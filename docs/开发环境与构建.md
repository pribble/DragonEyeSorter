## 启动链与 `BOOT.bin`

```
上电 → BootROM 读拨码（SD = ON-OFF-OFF，eMMC = OFF-OFF-OFF）
     → 从 SD 的 p1 分区读 BOOT.bin
          ├─ FSBL     初始化 DDR / 时钟 / PS 配置，把比特流烧进 PL（日志 "PL init done"）
          ├─ 比特流    整个 PL 设计
          └─ U-Boot   执行 boot.scr：读入 uImage.lz4（内核）+ system.dtb（设备树）→ bootm
     → 内核挂载根分区 /dev/mmcblk0p2（ext4）→ /init → BusyBox init
```

| 想改什么 | 改哪个文件 | 位置（板上） |
|---|---|---|
| PL 逻辑 | `BOOT.bin` | `/mnt/mmcblk0p1/BOOT.bin` |
| 外设地址 / 中断（需内核驱动时） | `system.dtb` | `/mnt/mmcblk0p1/system.dtb` |
| 启动参数 | `boot.cmd` → `mkimage` → `boot.scr` | `/mnt/mmcblk0p1/boot.scr` |
| 内核 / 驱动 | `uImage.lz4` / `.ko` | 需开发包 |
| 应用、配置、数据 | 直接放文件 | 根分区任意位置（持久化） |

`BOOT.bin` 内部结构（BootGen `-read` 实测，**0 基命名**）：**P0** FSBL（载入 OCM 0x61000000）/ **P1** 比特流（`destination_device=pl`）/ **P2** U-Boot（载入并执行于 0x200000）。P1 一律接我们自己的比特流（`make_bootbin.ps1 -Bit` 必填）。

## SD 卡布局与烧卡

持久化改造只改了启动方式：根文件系统放 p2（ext4），p1 只放启动件；厂家自带的 initramfs 启动方式（`uInitrd.lz4` + 它自己的 `boot.scr`）留在 p1 的 `initramfs_backup/`，用于回退。

| 分区 | 文件系统 | 板上挂载点 | 内容 |
|---|---|---|---|
| p1（252MB） | FAT32 | `/mnt/mmcblk0p1` | `BOOT.bin` `boot.scr` `system.dtb` `uImage.lz4` + `initramfs_backup/`（回退用） |
| p2（3.6GB，可用约 2.9G） | ext4 | `/`（另被 automount 再挂一次到 `/mnt/mmcblk0p2`，同一分区） | Buildroot 根文件系统（从 `uInitrd.lz4` 解出）+ 我们的全部文件 |

与厂家版的差别只在 `boot.scr`：不加载 initrd，`bootargs` 追加 `root=/dev/mmcblk0p2 rootwait rootfstype=ext4 rw init=/init`，`bootm 0x10000000 - 0x14000000`；写法照抄官方 Ubuntu demo。

**现有持久化卡已做好并上板通过**（[log/2026-10-08-持久化SD与BOOT.bin打包.md](log/2026-10-08-持久化SD与BOOT.bin打包.md)）：日常只换 `BOOT.bin`，不需要重做卡。镜像生成脚本 `make_sd_image.sh` 已删除（一次性工具，且要厂家 demo 的 `uInitrd.lz4`）；要新做一张卡时：① 直接用厂家预装的卡；② 或照本节布局手工复刻——`boot/` 目录取自厂家 NPU demo 的 `demo/boot/`（`uInitrd.lz4` 根文件系统、`uImage.lz4` 内核、`system.dtb` 设备树），`boot.scr` 的改动照上段。换卡后 SSH 主机密钥变了，首次连接前用 `ssh-keygen -R $BOARD_IP` 清掉旧记录。

烧卡用 `scripts/sd_image/flash_to_disk.ps1`（Windows 管理员，先 `Get-Disk` 认准磁盘号）或 balenaEtcher / Rufus，见 [scripts/README](../scripts/README.md)「sd_image」。

卡上剩余约 25GB 未分区；需要时 `fdisk` 建 p3 + `mke2fs` 作数据分区（板上无 `resize2fs`，不能直接扩 p2）。

p1 上实际有哪些文件（四份 `BOOT.bin` 的命名约定与取舍）、根分区各类文件落在哪，见 [板端布局](板端布局.md)。

## PL：构建与打包

改源码 → 编译 → 打包：

1. **改源码**：TD 6.2.1 打开 `pl/soc_base/soc_prj.al`；自研模块放 `src/des/`，新模块在 `system_top.v` 例化；PS 读写的寄存器做成 AXI-Lite 从机挂 `design_0`；管脚加进 `src/constraint/`（CEP = BANK11，3.3V）。改动直接提交进 `pl/soc_base/`。
2. **编译**：界面依次 Synthesis → Place → Route → Bitstream；比特流产物 `pl/soc_base/soc_prj_Runs/phy_1/soc_prj.bit`。
3. **打包**：`scripts/bootbin/make_bootbin.ps1 -Bit <比特流>`，几秒钟，产物 `scripts/bootbin/BOOT.bin`。
4. **换比特流**：见「部署与运行」。

**命令行编译**（无图形界面）：在 `soc_prj_Runs/syn_1`、`phy_1` 下依次运行
`td_commands_prompt.exe $TD_ROOT/scripts/DefaultFlow.tcl < NUL`（`$TD_ROOT` 为 `.env` 里的 TD 安装目录；路径用正斜杠，反斜杠会被 Tcl 吃掉）。
综合约 6 分钟、布局约 10 分钟、布线约 19.5 分钟，峰值内存约 5GB（建议 16GB RAM + 4 核以上）；原样重编厂家工程的比特流与厂家逐位一致，时序 SWNS −4.120ns / HWNS −2.594ns 也与厂家相同——**原设计本身有时序违例**，加模块以此为基线、不劣化即可。长时间编译建议作为独立进程（如 `Start-Process`），避免被会话后台任务管理误停。

**run 目录里"能跑起来"的 4 份小文件已入库**（`syn_1/{soc_prj.prj,settings.cfg}`、`phy_1/{soc_prj.prj,settings.cfg}`；其余综合 / 布局数据库、日志、比特流仍被 `**/*_Runs/` 忽略）：靠 `git add -f` 强制入库，忽略规则不作用于已跟踪文件、改动照常提交；见 [pl/soc_base/soc_prj_Runs/README.md](../pl/soc_base/soc_prj_Runs/README.md)。

| 文件 | 作用 | 缺了会怎样 |
|---|---|---|
| 两个 `settings.cfg` | `DefaultFlow.tcl` 的流程参数（起止步骤 / 器件 / 封装 / speed；phy 那份多一行 `parent ../syn_1`） | 该脚本第一步即 `source ./settings.cfg`，缺了直接失败 |
| 两个 `soc_prj.prj` | 工程文件（源文件表 / 器件 / 顶层）；phy 那份另带 `<compress>on</compress>` 与 `<PlaceProperty><opt_timing>high</opt_timing>` | `phy_1` 缺了报 `PRJ-8642 ERROR: Project file soc_prj.prj does not exist.` 并掉进 `td >`；属性不同则 bitgen 产物与布局质量不可比 |

⚠ **`td_commands_prompt.exe` 出错也返回 exit 0**（报错后掉进 `td >`、stdin 是 NUL 就退出）。判断成败只能看 run 目录的 `.<step>.end.f` 标记与产物文件，不能看退出码。

**合并后全量重编**（`soc_base/` 单工程布局）：流程跑通，资源与 v8 一致（slice 82.41% / ERAM 261~280 / DSP 65%），**自研各域 0 违例**（`clk_mipi` +0.108ns、75MHz +0.176ns、150MHz +0.191ns），18 个违例端点全在厂家 VTC 域的跨域 recovery 路径——见 [log/2026-10-13-合并后PL全量重编](log/2026-10-13-合并后PL全量重编.md)。

**什么时候要重编 FSBL**：只改 PL 逻辑不用；改了 `design_0` 的 PS 配置（增删 AXI 口、FCLK、MIO、DDR）要用 FD 按新 `.hpf` 重编（Platform `soc_base` + Application `soc_fsbl`，模板 FSBL、名字不能改），经 `-Fsbl` 传入。U-Boot 不需要重编。

**AXI 地址窗口一次划够并固定**：之后只改模块内部，设备树不用动。

**打包与零件**：零件已入库 `scripts/bootbin/parts/`（`fsbl.elf` 与厂家原件逐字节相同、`u-boot.elf` 由厂家 BOOT.bin 解出，台账 [parts/MD5SUMS.txt](../scripts/bootbin/parts/MD5SUMS.txt)），脚本每次打包校验 `u-boot.elf` 的 MD5。命令与外部依赖见 [scripts/README](../scripts/README.md)「bootbin」；只有重建丢失的 `parts/u-boot.elf`、取厂家原始 `fsbl.elf` 时才需要 `-VendorDemo <厂家 demo 目录>`。

## PS：构建

```bash
# 1. 加载 .env：Bash / WSL 用 source scripts/env_loader.sh，PowerShell 用 . .\scripts\env_loader.ps1
# 2. 编 all 目标（des_app / des_tool / desreg / canplc / test_scheduler / test_calib /
#    test_measure / test_belt_hil / test_can）→ ps/build/；test_npu 与 test_servo_gap 要单独点名
make -C ps all
make -C ps build/des_app      # 只编主程序
```

命令行也能覆盖配置（`ps/Makefile` 不留任何主机路径默认值，缺了直接报错并提示怎么配）：`make -C ps CROSS=<工具链前缀> ARMNN_LIB=<armnn_lib 目录> OPENCV_LIB=<ffmpeg_opencv4.7.0_aarch64 目录>`。

`make -C ps all` 结束时会让部署器刷一次 `scripts/deploy/out/`（脚本与 `des.env` 就地不动，只有编出来的二进制不入库；Linux / WSL 上这行会提示找不到 powershell，可忽略）。库目录的准备见 [环境与上手](环境与上手.md) §3，链接期报错见 §6。

**PS 产物分四层**（`des_app` 产品运行时 / `des_tool` 运维 / `test_*` 自动测试 / `desreg`、`canplc` 底层调试），只有 `des_app` 进部署清单；分层、构建目标与部署去向见 [ps/README](../ps/README.md)。

- **访问 PL 寄存器**：`/dev/mem` 可用（`devmem 0x80300000` → `0x1BB00000`），应用以 root 运行直接 `mmap`，不需要写驱动：
  ```c
  int fd = open("/dev/mem", O_RDWR | O_SYNC);
  volatile uint32_t *reg = mmap(NULL, 0x1000, PROT_READ | PROT_WRITE, MAP_SHARED, fd, PL_BASE);
  ```
  调试可直接用 `devmem <地址> [32 <值>]`。
- PL 中断通知应用需 UIO（改设备树，可能改内核配置）→ 届时再用米联客开发包。
- 界面是 OpenCV 自绘 + FreeType，不用 Qt（见 [软件与UI](软件与UI.md)）；板上 Qt 5.15.8 运行库不参与我们的构建。
- SQLite：板上没有，把 amalgamation（单个 `sqlite3.c`）直接编进应用。
- 摄像头 / NPU 参考：厂家 `demo/sdk/face_detection.tar.gz`（`yolo_demo_hdmi_camera` 源码），运行脚本在 `/opt/scripts/`。

## 操作禁忌

完整清单见 [AGENTS.md](../AGENTS.md)「操作禁忌」；本节只补细节。

- **BitWriter 往 SRAM 下载只在不跑 Linux 时进行**：PL 里是 Linux 依赖的 MIPI / VDMA / NPU 软核，运行时下载会覆盖。独立测试 bit（如 [pl/test/step_test](../pl/test/step_test/)）测完断电重启，`BOOT.bin` 恢复。
- **关机用 `/root/des/shutdown.sh`**（快捷方式「6_关机」调它），之后 **2 分钟内断电**。`halt` / `poweroff` 之后板子必然自己复位重启（UG1214 第 12 / 29 章）：PS 看门狗 `dw_wdt` @0xF8410000 在芯片**永久在线域**、配置为始终使能（`WDT_CR` 写 0 读回仍 0x09），设备树也没给复位线，软件关不掉；CPU 一停没人喂，默认档位 TOP=13（2^29 周期、计数约 16.9MHz）约 32s 后复位。`shutdown.sh` 先停 `des_app`，再把 `WDT_TORR` 调到最大档 15（约 127s）并重装计数器，最后 `halt`（完整关机流程，文件系统已卸载，屏幕黑后即可断电）。板子没有软件可控的电源开关，真正断电只能拔电 / 关开关。
- **eMMC（`/mnt/mmcblk1p*`）是出厂救生艇系统，保持原样**。
- 换 `BOOT.bin` 前把原文件改名备份（如 `BOOT.bin.vendor`），起不来就改回。
