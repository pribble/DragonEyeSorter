# 软件与 UI

> PS 软件职责、界面、存储与总线；开发与部署见 [开发环境与构建](开发环境与构建.md)。

## PS 职责边界

PS（双核 A35 + Linux）做：NPU 推理调度、视觉定位 (x, y, θ)、跟踪表与抓取调度、机械臂 IK、CAN、UI、存储、网络。**不搬整帧像素**；时序关键的脉冲、总线帧、IO 采样在 PL。

- PL 寄存器经 `/dev/mem` mmap 访问（已验证可用），寄存器偏移头文件放 `ps/src/hw/`，与 [PL设计](PL设计.md) 同源。
- 板上已有：Qt 5.15.8、ArmNN + Alnpu、OpenCV 4.7、FFmpeg；没有 SQLite（把 amalgamation 编进应用）。
- 交叉编译用 FD 自带的 aarch64 工具链（glibc 2.25，与板上一致）。

## 赛题解读

赛题原文"Linux 系统 + 基础交互界面；HDMI 可视化曲线 / 参数配置界面"。纯视频流不够：界面必须有**参数配置**与**曲线**。初赛交线下材料（PPT + 技术文档 + 视频），每项硬性要求都要在视频里有镜头。

## 本地 HDMI 界面（P0，✅ OpenCV 自绘 + FreeType 中文，`app/hmi`）

**为什么不用 Qt**：官方 Qt 资料（`05-1_QT环境搭建及demo演示`）是独立系统镜像（自带 BOOT.bin / 内核 / vdmafb 设备树 / 460MB rootfs），换掉就丢现在的 NPU 镜像、自编比特流与 60fps 直写显示 VDMA；板上 Qt 只有 offscreen / vnc / directfb 插件，无交叉编译头文件。用户同意改自绘。

**布局**：60fps 视频全屏；底部 **1920×300 条带**为操作界面（零件在皮带中线 ±30mm 内，条带只盖皮带远侧）；左上角状态栏保留。条带下的视频行不再转换，转换 7.7→5.7ms，正好抵掉贴图。实测（板上，无零件）：60fps、每帧显示 9.2ms、工作线程处理 99.7% 的帧。
- **四页**（鼠标点左侧标签，或键盘 F1~F4 / Tab / ←→）：
  - **总览**：总数 / 良品 / NG / 复检 / 良率 / 产量（件/分），8 类计数条，最近 7 件（件号、类别、去向、出口、尺寸、置信度），右上角运行状态 + 带速。
  - **曲线**：齿轮外径、齿条长度趋势（最近 80 件，公差线 = 参数页，绿 OK 红 NG，均值 / σ / **Cpk**）；近 60s 工作线程耗时、NPU 耗时、带速。
  - **参数**：带速、齿轮外径名义 / 公差、齿条长度名义 / 公差、尺寸判废开关、置信度门限、存图模式（−/+ 按钮）、PL 显示模式 / 二值阈值，**立即生效**（工作线程改跟踪表规则 / 存储 / Runner 带速）并存 `ui_params.json`（启动时载入，覆盖 des_app.json）；**运行控制**：启动 / 停止 / 暂停 / 恢复 / 复位报警（run 模式，与 PLC 的 CAN 命令同一套规则 `Runner::command`）。
  - **记录**：最近 9 件（时间、件号、类别、置信度、去向、原因、尺寸），点一行看该件裁切图 + 全部测量值。
- **输入**：evdev（`app/ui_input`），USB 鼠标 / 键盘 / 触摸屏热插拔（每 2s 扫描 `/dev/input`）。内核有 usbhid + hid-generic（⚠ 待插上实测）。**脚本输入**：往 `/tmp/des_ui` 写 `click X Y` / `move X Y` / `wheel N` / `key CODE` / `snap`（存下一帧到 `/tmp/des_snap_N.png`）—— 远程测试、演示脚本用（板上没有 uinput）。
- **中文**：板上自带文泉驿正黑 `/usr/share/fonts/wqy-zenhei/wqy-zenhei.ttc` + `libfreetype.so.6`（`app/text_ft`，字形缓存）。交叉编译要 FreeType 头文件 + 板上 libfreetype / libpng16 / libz（Makefile 变量 `FREETYPE_INC` / `BOARD_LIBS`，路径在本机 `.env`，见 [环境与上手](环境与上手.md)）。ArmNN 与 OpenCV 同理走 `ARMNN_LIB` / `OPENCV_LIB`。
- 全部在核 1 的工作线程渲染（约 8Hz），核 0 只贴图 + 画光标。

原方案（保留作对照）：视频层用 PL 的 VDMA framebuffer，Qt 只画叠加层和控件。

**fb0 / vdmafb 通路**：`/dev/fb0` = anlogic `vdmafb`（寄存器 `0x8010_0000`，1920×1080，24bpp）。厂家 `vision/hdmi.cpp` 的 `hdmi_t::show()` **不拷贝整帧**：
刷缓存后把相机缓冲的物理地址写进 `0x8010_0800`（HDMI 读 DMA 基地址），等于翻页。
厂家 demo 的 28fps 是它串行流水限制，不是显示通路限制。⚠ 待定：Qt 控件层如何与 60fps 视频合成 —— 整帧由 PS 合成不现实（读 DMA 缓冲慢，见 [ps/README](../ps/README.md)），也可 PL 叠加（ERAM 余量很少）；或把侧边栏预渲染好逐帧贴进 BGR 缓冲（约 400×1080×3，约 1~2ms），或先贴进相机缓冲（约 2~4ms）。注意相机缓冲 4 字节 / 像素、fb0 声明 24bpp，翻页前确认读 DMA 的像素格式设置。

**扫描输出（本比特流）**：`0x8010_0000` 那组 HDMI 寄存器全读 0，`hdmi_t`（写死 32bpp）是给别的比特流用的；真正扫描输出的是 **`vdma@0x8020_0000`**：
V_SIZE 1080、H_SIZE = 行跨度 5760（**24bpp BGR**）、`START_1`（0x5C）= fb0 显存 `0x17D0_0000`；显示时序 1920×1080 @ **60.6Hz**（像素时钟 150MHz）。
相机是 32bpp BGRA，不能直接翻页 → **每帧 CPU 转一次 BGRA→BGR 进两块 CMA 显示缓冲之一，再写 `START_1` 翻页**：
`des_app display` 实测 **60fps 显示**，转换平均 6.2ms（OpenCV NEON）、刷缓存 0.6ms，8s 只在开头丢 1 帧（首帧缺页 22ms）；退出时恢复 `START_1`。

⚠ **翻页要同时写 `V_SIZE`**：扫描 VDMA 工作在停驻模式（`0x00` = `0x00017001`，帧同步接常数 0），只改 `START_1` 不会被装载，显示器一直是 fb0 控制台（两只企鹅），而寄存器读回的却是新地址；写一次 `V_SIZE`（同值 1080）就提交。`hdmi_out.cpp` 每次翻页「写 `START_1` → 写 `V_SIZE`」，退出恢复 fb0 时同样处理；目视确认 60fps 流畅、无撕裂 / 噪点。
→ **60fps 显示不需要改 PL**；每帧占一个核约 7ms，定位（5.9ms）放另一个核。检测框 / 文字直接画进 BGR 显示缓冲（`cv::putText` 等，开销很小）；Qt 控件层仍待定（见上「fb0 / vdmafb 通路」）。

**`des_app live`：带检测叠加的 60fps 显示已跑通**（20s 1200 帧 59.96fps；每帧显示 11.7ms = 转换 7.6 + 叠加 3.5 + 刷缓存 0.6）。做 UI 照此办：
- **显示缓冲（CMA）不走缓存**：OpenCV 在其上逐像素画大面积（填充矩形、粗线）每帧要好几毫秒 → 大块内容先在普通内存画好，再按行 `memcpy` 贴入（宽写，318KB 约 0.3ms）。
- **`putText` 线宽 2 很贵**（Hershey 笔画逐段画粗线，一行字 1~2ms）→ 状态文字 10Hz 重画、其余帧只贴图；框上标签用线宽 1。
- **OpenCV 用单线程**（`cv::setNumThreads(1)`），两个核由我们自己分：核 0 = SCHED_FIFO 取帧 + 显示，核 1 = 定位 / 跟踪。
- **显示循环不能超过 16.7ms**：超了就赶不上在下一帧开始前重新提交 DMA，叠加层未优化时取帧会连带丢。
- **看峰值不看平均**：`run` 下平均 12ms 仍每秒丢约 8 帧——每 6 帧一次的状态栏文字重画把个别帧推到 18ms。状态栏改由核 1 工作线程渲染（10Hz）、核 0 只贴图后：`run` 20s 1201 帧 60.00fps（只启动时丢 1 帧），每帧最大 12.2ms。

## 工业总线

- **CAN（P0）**：PC 上的 USB-CAN 当"产线 PLC"，下发启停 / 调速，板子回报计数与状态。走 PS 的 SocketCAN（内核已有 `can0`/`can1`）。
- **RS485 Modbus（P1）**：如 485 继电器 + 三色灯报警，构成双总线。

### CAN 协议 v1（板上自测通过，PC 端按此写）

经典 CAN 2.0A（11 位 ID），500kbit/s（板载收发器 SN65HVD232 只支持经典 CAN），多字节**小端**。定义在 [ps/src/hw/can_proto.h](../ps/src/hw/can_proto.h)（编解码函数同在此文件）。

| 方向 | ID | 长度 | 内容 |
|---|---|---|---|
| PLC→本机 | 0x100 CMD | 2 | [命令, 序号]：1 启动 / 2 停止 / 3 联锁暂停 / 4 恢复 / 5 复位报警 |
| PLC→本机 | 0x101 SPEED | 3 | [带速 ×10 (u16, 0.1mm/s), 序号] |
| PLC→本机 | 0x102 RECIPE | 2 | [配方号, 序号] |
| PLC→本机 | 0x103 PLC_HB | 1 | [计数]，≥2Hz；1s 收不到 → STATUS 里清掉「PLC 在线」位（应用可据此联锁暂停） |
| PLC→本机 | 0x104 TIME（v1.1） | 6 | [unix 秒 u32, 毫秒 u16]，不回 ACK；板子无 RTC，零件记录的时间 = 本机时钟 + 最近一次 TIME 的偏移（不改系统时间） |
| 本机→PLC | 0x180 ACK | 3 | [命令 ID 低字节, 序号, 结果 0 成功 / 1 状态不允许 / 2 数值不对 / 3 未知] |
| 本机→PLC | 0x181 STATUS | 8 | [状态 0 空闲 1 运行 2 暂停 3 急停 4 故障, 标志 b0 带在走 b1 臂忙 b2 报警 b3 PLC 在线 b4 已标定, 带速×10 (u16), 报警码, 心跳, 运行秒数 (u16)]，10Hz |
| 本机→PLC | 0x182 COUNTS | 8 | [总数, 良品, NG, 复检] 各 u16，1Hz + 变化时 |
| 本机→PLC | 0x183 PART | 8 | [件号 u16, 类别（0xFF 未知）, 去向 0 抓取 1 翻板 2 复检, 料盒 / 出口, 置信度 %, 主尺寸 ×100 (u16, 0.01mm；齿轮外径 / 齿条长度，几何测量值，0 = 没测到)] |
| 本机→PLC | 0x184 ALARM | 4 | [报警码, 级别, 细节 u16] |

**联动实测（`des_app run --can can0` + `canplc` 扮 PLC，回环）**：上电空闲 → 未启动时「恢复」被拒 → 启动（应答 10ms，皮带走、STATUS 带速 50）→ 设 80mm/s（运行中立即生效，PL 平滑过渡）→ 设 500 判「数值不对」→ 联锁暂停（皮带减速停）→ 恢复 → 停止，状态、标志位（皮带在走 / PLC 在线）全部正确。

**起接口**：`ps/board/can_up.sh can0 normal`（接 PC 的 USB-CAN）或 `can_up.sh can0 loopback`（自测；控制器只有 FD 模式能回环，经典帧照样收发）。

**自测（`ps/tests/test_can.c`，回环，两个 socket 扮 PLC 与本机）**：编解码 6 项；命令→应答往返 1000/1000，**平均 356µs**（最大 429µs）；
按 200 / 1000 / 2000 帧/s 连续发，**零丢失、零错序**；接口错误计数 0。⚠ 不限速连发（约 9000 帧/s，超过总线物理上限）时回环会**无声丢帧**
（TX 计数齐、RX 少、错误计数不动）——应用只用每秒几十帧，不受影响，但 2h 稳定性测试要按实际速率发。

## 语音 + LLM 助手（P2）

- 链路：麦克风 → 触发 → ASR → LLM（function calling）→ 结构化指令 → PS 校验 → AXI → PL。
- **LLM 不直接碰硬件**，只输出结构化指令，由 PS 调度层校验后才写寄存器。
- **必须有离线降级**：断网退回本地固定命令词表；不挤占 P0/P1 的任何时间。

## 存储

✅ **已实现（`app/part_log`）**：每件判定后一行 CSV（`/root/des/data/log/<日期>/parts_<会话>.csv`，39 列：时间、件号、帧号、类别 / 置信度、去向 / 出口 / 原因、全部测量值、带坐标 / 姿态、PL 粗测（v6）、图片名、NPU 投票次数 / 推理耗时 / 帧完成→结果延迟）+ 零件裁切图（`img/<会话>_<件号>_<类别>.jpg`，与 NPU 输入同一个裁切函数 `roi_crop`，默认只存翻板 / 复检件）。后台线程写盘，工作线程不等 SD 卡，队列满就丢弃并计数。板上无 sqlite 库，列与将来 SQLite 表一致；界面历史查询再定（Qt 自带 QtSql 可读 CSV 导入）。
⚠ 板上无 RTC（实测时钟 1970-01-01）：记录时间 = 本机时钟 + PC 端「PLC」经 CAN TIME 帧（0x104）下发的偏移，不改系统时间。
**出数**：`pc/report/part_stats.py` 读这些 CSV → 节拍、处置 / 去向、NPU 耗时与延迟分布、已知类别时的准确率 / 混淆矩阵、尺寸统计 + Cpk、同一件重复性与卡尺误差、PL 粗测对比（Markdown + JSON，直接贴进测试报告）。SD 卡根分区 3.75GB（余 3.2GB），整卡还有约 25GB 未分区，采集整帧训练图前新建数据分区。
