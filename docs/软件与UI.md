## PS 职责边界

PS（双核 A35 + Linux）做：NPU 推理调度、视觉定位 (x, y, θ)、跟踪表与抓取调度、机械臂 IK、CAN / Modbus、UI、存储、网络；**不搬整帧像素**，时序关键的脉冲、总线帧、IO 采样在 PL。PL 寄存器经 `/dev/mem` mmap 访问（头文件 `ps/src/hw/`，与 [PL设计](PL设计.md) 同源）；板上已有 ArmNN + Alnpu、OpenCV 4.7、FFmpeg、FreeType（无 SQLite）；交叉编译见 [环境与上手](环境与上手.md)。

## 本地 HDMI 界面（OpenCV 自绘 + FreeType 中文，`app/hmi`）

界面用 OpenCV 自绘：官方 Qt 资料是独立系统镜像，换用会丢 NPU 镜像与自编比特流，板上无交叉编译头文件。

**布局**：相机画面等比缩到 **1440×780**，**不被任何界面遮挡**；右侧 **480×780 状态栏**（顶部常驻**运行控制**：一行 `启动|停止|暂停|恢复`（配对相邻）+ 一行皮带点动 `正转|反转`，任意页可见、状态色条随动；**复位报警只在急停 / 故障时出现**为宽按钮——平时无报警可复位。下方为**标签 / 数值两列对齐**的状态行（显示 / 处理 / 产线三组、细线分隔），最后是连接状态与最近命令（机械臂、PLC / Modbus / RS485，`·` 分隔）；底部 **1920×300 操作条**。

**显示**：1080p60 每帧须进 16.7ms；缩放用 `ui/display` 的 `scale34_bgra_to_bgr`（横 4 出 3、纵 4 出 3，中间行先平均），目标必须是普通内存；状态栏 / 操作条由核 1 渲染（约 8~10Hz），核 0 只贴图 + 画光标。`/dev/fb0` 是厂家 `vdmafb`，本比特流真正扫描输出的是 **`vdma@0x8020_0000`**（`V_SIZE` 1080、行跨度 5760、**24bpp BGR**、`START_1` 指向 fb0 显存）；相机 BGRA → 每帧 CPU 转 BGR 进两块 CMA 显示缓冲再切帧存，翻页用**停驻指针**（`PARK_PTR`）帧边界切换，开机写好帧存地址与 `V_SIZE`（退出还原）。中文标注用 `TextFT::draw_solid`（只写不读）；核 0 = SCHED_FIFO 取帧 + 显示，核 1 = 定位 / 跟踪 / 界面渲染（OpenCV 单线程）。每帧耗时与丢帧见 [测试与验证](测试与验证.md)。

**界面风格**：白底浅色主题（`ui_text.hpp` 颜色按用途命名），全中文，只保留 DragonEyeSorter 与 NPU / PLC / Modbus / RS485 / PL。

## 工业总线

- **CAN（P0）**：PC 的 USB-CAN 当「产线 PLC」下发启停 / 调速 / 换型 / 对时，板子回报状态与逐件结果；走 SocketCAN（`can0` / `can1`），协议见下。
- **Modbus-TCP 从站（领域 3 高级「网口对接 PLC」，✅ 板上实测）**：同一套命令 / 状态走 PS 网口，规则与 CAN 完全相同，可同时在线。
- **RS485 Modbus-RTU（第二条工业总线）**：从站 = 4 路 Modbus-RTU 继电器（地址 1，9600 8N1）+ 24V 三色灯：绿 运行 / 黄 暂停 / 红 急停或 PLC 掉线；故障红灯亮 `fault_s` 秒（默认 10）后熄灭，空闲按 `rs485.idle`（off / green / blink）不亮，报警蜂鸣 `buzzer_s` 秒。同一条总线上第二个从站 = **温湿度变送器**（SHT30，地址 `rs485.th_addr` 2，每 `th_period_s` 1 s 读保持寄存器 0 / 1 = 温度 / 湿度 × 10；协议见 [到货联调清单](到货联调清单.md) §7b）：右侧状态栏「环境温湿度」，每 10 s 一行写 `env.csv`（与零件记录同目录），超限 / 掉线开工单 19 / 20。两个从站的在线状态分开算：变送器在答不会掩盖继电器模块掉线，反之亦然。`th_addr` 0 = 没有变送器（行为与以前相同）。
  - 硬件（SP3485EN、J11 第 5 / 6 位、BANK33：TX L17 / RX N16 / DE N15）见 [硬件与接线](硬件与接线.md)。
  - **PL `des_485`（v16 已上板；寄存器与行为见 [PL设计](PL设计.md)）**：寄存器窗口 `0x6xx`，硬件 DE、CRC16 自动补 / 校验、3.5 字符判帧、应答超时；PS 接口 `des_485_config` / `des_485_xfer`（请求 = [地址, 功能码, 数据]，不含 CRC）/ `des_485_listen`，调试命令 `desreg 485`。
  - **PS（`src/hw/modbus_rtu` + `src/app/rs485_io`）**：主站 PDU 编解码（01~06 / 0F，应答逐项核对、异常码）；独立线程每 50ms 按线体状态算灯，**逐路 FC 05** 只写与现状不同的路灯（实物 bestep 板不认 FC 0F、FC 01 只应答 8 路 → `rs485.coils` 8，怪癖见 [到货联调清单](到货联调清单.md) §7b），每 `poll_ms` 读回线圈（FC 01，可选 FC 02），不符下周期补写；统计成功 / 超时 / CRC 错 → 报告「总线稳定性」。`rs485` 已打开；比特流 < v16 时只少一个灯；无 `DES_VERSION_485` 时报「无驱动」。
  - **协议转换**：PLC 经 CAN `0x105 LAMP` 或 Modbus-TCP `HR7` 接管灯 → 板子在 RS485 写继电器；RS485 链路状态进 CAN STATUS b5 与 Modbus `IR24~29`。
  - PC 工具见 [pc/README](../pc/README.md)（`rs485_tool.py` / `mb_client.py`）；测试 `ps/tests/test_rs485`（模拟继电器，68 项）。

### CAN 协议 v1.2（v1.1 板上自测通过，PC 端按此写）

经典 CAN 2.0A（11 位 ID），500kbit/s（收发器 SN65HVD232 只支持经典 CAN），多字节**小端**。定义在 [ps/src/hw/can_proto.h](../ps/src/hw/can_proto.h)（编解码函数同在此文件）。

| 方向 | ID | 长度 | 内容 |
|---|---|---|---|
| PLC→本机 | 0x100 CMD | 2 | [命令, 序号]：1 启动 / 2 停止 / 3 联锁暂停 / 4 恢复 / 5 复位报警 |
| PLC→本机 | 0x101 SPEED | 3 | [带速 ×10 (u16, 0.1mm/s), 序号] |
| PLC→本机 | 0x102 RECIPE | 2 | [配方号 1~255, 序号]：配方表见 `scripts/deploy/out/recipes.json`；未知号 → ACK 2，运行中 → ACK 1；接受后切换尺寸判定规格并记入每件记录的 `recipe` 列 |
| PLC→本机 | 0x103 PLC_HB | 1 | [计数]，≥2Hz；1s 收不到 → STATUS 里清掉「PLC 在线」位（应用可据此联锁暂停） |
| PLC→本机 | 0x105 LAMP（v1.2） | 3 | [模式 0 跟随线体 / 1 接管, 灯 b0 绿 b1 黄 b2 红 b3 蜂鸣, 序号]；在 RS485 上写继电器模块（CAN → RS485）；RS485 没在跑回 ACK 1 |
| PLC→本机 | 0x104 TIME（v1.1） | 6 | [unix 秒 u32, 毫秒 u16]，不回 ACK；板子无 RTC，零件记录的时间 = 本机时钟 + 最近一次 TIME 的偏移（不改系统时间）；不足 6 字节或早于 2023 年（unix 秒 < 1700000000）的帧丢弃，与 Modbus 对时同一规则 |
| 本机→PLC | 0x180 ACK | 3 | [命令 ID 低字节, 序号, 结果 0 成功 / 1 状态不允许 / 2 数值不对 / 3 未知] |
| 本机→PLC | 0x181 STATUS | 8 | [状态 0 空闲 1 运行 2 暂停 3 急停 4 故障, 标志 b0 带在走 b1 臂忙 b2 报警 b3 PLC 在线 b4 已标定 b5 RS485 在线（v1.2） b6 有活动运维工单（v1.3）, 带速×10 (u16), 报警码, 心跳, 运行秒数 (u16)]，10Hz |
| 本机→PLC | 0x182 COUNTS | 8 | [总数, 良品, NG, 复检] 各 u16，1Hz + 变化时 |
| 本机→PLC | 0x183 PART | 8 | [件号 u16, 类别（0xFF 未知）, 去向 0 抓取 1 `Flap`（现为侧边导流挡板）2 复检, 料盒 / 出口, 置信度 %, 主尺寸 ×100 (u16, 0.01mm；几何测量值，0 = 没测到)] |
| 本机→PLC | 0x184 ALARM | 4 | [报警码, 级别, 细节 u16]：急停 = [1, 2, 0]；运维工单（v1.3）= [故障代码, 级别 1 提示 2 警告 3 故障, 工单号]，见下「设备运维」 |

- **起接口 / 自测**：`scripts/deploy/out/can_up.sh can0 normal`（接 PC 的 USB-CAN）或 `can_up.sh can0 loopback`（自测；FD 模式才能回环，经典帧照常收发）；`des_app run --can can0` + `canplc` 扮 PLC 回环。
- 流程与往返耗时、丢帧见 [测试与验证](测试与验证.md)；PC 端 PLC 模拟器见 [pc/plc_sim](../pc/plc_sim/README.md)。

### Modbus-TCP（板子 = 从站，端口 502）

`des_app run` 起 Modbus-TCP 从站（`des_app.json` 的 `plc.modbus_port`，0 = 关），最多 4 客户端。实现：[ps/src/hw/modbus_tcp.cpp](../ps/src/hw/modbus_tcp.cpp)（poll 线程，MBAP 分帧，FC 03 / 04 / 06 / 16，异常码 01 / 02 / 03）；寄存器表 [ps/src/hw/modbus_tcp.hpp](../ps/src/hw/modbus_tcp.hpp)。写入只排队，由控制循环（每帧 ≤17ms）按 CAN 同一规则执行，结果写回 RESULT、SEQ +1。地址从 0 起（按 1 起算的组态软件显示 40001.. / 30001..），32 位值高字在前。

| 保持寄存器（FC 03 读 / 06、16 写） | 含义 |
|---|---|
| HR0 CMD | 写命令：1 启动 / 2 停止 / 3 联锁暂停 / 4 恢复 / 5 复位报警；读回 0 |
| HR1 SPEED | 带速设定 ×10（0.1mm/s，1~2000）；读回当前设定 |
| HR2 RECIPE | 配方号（只在非运行状态接受）；读回当前配方 |
| HR3 RESULT | 上一次写入的结果：0 成功 / 1 状态不允许 / 2 数值不对 / 3 未知（只读） |
| HR4 SEQ | 每执行一次写入 +1（只读）。PLC：写 → 等 SEQ 变 → 读 RESULT |
| HR5 / HR6 TIME | PLC 时钟 unix 秒（高字 / 低字），**一次 FC 16 写两个**，写低字时生效；板子无 RTC，同 CAN TIME 帧 |
| HR7 LAMP（v1.1） | 三色灯：bit 8 = 接管，bit 0~3 = 绿 / 黄 / 红 / 蜂鸣；0 = 跟随线体；同 CAN LAMP（以太网 → RS485）；读回当前接管值 |
| HR8 WO_ACK（v1.2） | 确认运维工单：写工单号（0xFFFF = 全部；0 → 结果 2）；读回 0 |

| 输入寄存器（FC 04，每个控制周期刷新） | 含义 |
|---|---|
| IR0 状态 / IR1 标志 | 同 CAN STATUS：0 空闲 1 运行 2 暂停 3 急停 4 故障；b0 带在走 b1 臂忙 b2 报警 b3 PLC 在线（CAN 心跳或 Modbus 请求在 1s 内） b4 已标定 b5 RS485 在线 |
| IR2~9 计数 | 总数 / 良品 / NG / 复检，各 32 位（高、低字，计到 2^32 才回绕）；CAN COUNTS 帧的同名计数按协议 v1 截 u16、65535 回绕，超过后两者分叉 |
| IR10 零件序号 | 每判定一件 +1；PLC 发现跳号 = 两次轮询之间来了不止一件（计数仍准） |
| IR11~16 最近一件 | 件号、类别（0xFFFF 未知）、去向（0 抓取 1 挡板 2 复检）、料盒 / 出口号、主尺寸 ×100（0.01mm）、置信度 % |
| IR17 实际带速 ×10、IR18 心跳（每周期 +1）、IR19 运行秒数、IR20 报警码、IR21 当前配方、IR22 映射版本 0x0103 | |
| IR24~29 RS485（v1.1） | 标志（b0 在跑 b1 在线 b2 PLC 接管）、继电器读回的灯、模块输入、成功次数、失败次数、最近应答时间 ×100（0.01ms） |
| IR32~37 运维工单（v1.2） | 活动工单数、待确认数、活动工单最高级别（0 无 1 提示 2 警告 3 故障）、最新未关闭工单号、其故障代码、变化序号（任一工单变化 +1）；共 40 个输入寄存器（v1.1 32 个、v1.0 24 个，IR30~31 空） |

- **监视单元号 250**（映射 0x0103）：从站不看单元号，只有 250（`MB_UNIT_MONITOR`，Modbus 保留区、PLC 不会用）例外——它的请求照常应答和执行，但**不计入「PLC 在线」**，也就不会在请求停下后开「PLC 通信中断」工单。板上的监视程序（`des_4g`）用它读状态、写命令；寄存器表本身没有变化。
- **PC 端客户端**：[pc/modbus/mb_client.py](../pc/modbus/mb_client.py)（只用标准库；电脑主动连，不动防火墙）。
- 本地 / 板上测试与经网线读寄存器的往返耗时、实物启停结果见 [测试与验证](测试与验证.md)。

## 设备运维：故障检测 → 运维工单 → 远程运维站（`app/ops`，2026-11-01）

对应赛题拓展 4「AI 智能运维」高级档「工单推送」、拓展 5「网络、远程运维」（以太网上的远程运维站在本节；4G 见下一节「4G 远程监控与第二条链路」）。

**故障检测**（`HealthMonitor`，每个控制周期，只用线上已有的测量，不加传感器）：

| 代码 | 故障 | 判据（`des_app.json` 的 `ops` 段可调，全部可选） | 级别 |
|---|---|---|---|
| 1 | 急停按下 | 线体进入急停（PL 锁存） | 故障（已停） |
| 2 | 皮带速度异常（卡滞 / 打滑） | 步进指令 ≥ `belt_min_mm_s` 10，计米轮实测 < `belt_ratio` 30% 持续 `belt_s` 1.5 s | **故障 → 停机** |

## 4G 远程监控与第二条链路（`des_4g`，`src/uplink`）

对应赛题拓展 5「4G 远程监控」与拓展 3「链路冗余」。**已上板跑通**（11-16，见 [log](log/2026-11-16-4G上报上板.md)）：EM05-CN（USB `2c7c:0125`，AT 口 = 接口 2，固件 `EM05CNFDR08A03M1G_ND`，带 `AT+QMT*`）+ 联通卡，信号 25~27 / 31（−59 ~ −63 dBm），经 4G 连上公共服务器 `broker.emqx.io:1883`；电脑端订阅收到每 10 s 一条状态；`ping` 往返约 0.6 s；签错名的命令被拒（`bad signature`）、同一条命令重发被拒（`replayed`）、签名正确的 `stop` 经单元号 250 写进 `des_app` 并返回执行结果。开机自启：`scripts/deploy/out/des_4g_service.sh`（`/etc/init.d/S91des4g` 指向它，排在主程序 S90des 之后；没有 `des_4g.json` 就不启动）。

**做法**：底板 M.2 位插移远 EM05-CN（LTE Cat 4）。板上内核没有 USB 串口和 USB 网卡驱动，模组的 AT 口不会出现成 `/dev/ttyUSB*`，也拨不了号；所以 `des_4g` 是一个独立进程，经 usbfs（`/dev/bus/usb`）直接和模组的 AT 口收发字节，联网和 MQTT 都交给**模组自带的协议栈**（`AT+QMT*`）。不改内核。它从 `des_app` 取数据有两条路：网口上传口（`storage.feed_port`）只旁听、一个字节都不发；配置了 `board.modbus_port` 时再用监视单元号 250 读寄存器、写命令（需要 `des_app` 的映射版本 ≥ 0x0103，见上文 Modbus-TCP 一节）。

| 文件 | 职责 |
|---|---|
| `uplink/usbfs_port` | 从 sysfs 找模组、解析描述符列出接口；认领一个接口，批量 OUT 发、一个常挂的批量 IN 请求收（异步请求，同步调用在超时瞬间会丢字节）；打开时拉高 DTR / RTS，整包长度后补零长包 |
| `uplink/at_chan` | 一次一条 AT 命令：按 `OK` / `ERROR` / `+CME ERROR` 收尾或超时；区分应答与模组主动上报（`+QMTSTAT` / `+QMTRECV` 等）；`> ` 提示后发定长数据 |
| `uplink/quectel` | 模组开机检查（卡、信号、注册）、激活数据连接、MQTT 配置 / 连接 / 订阅 / 发布（`AT+QMTPUBEX`，老固件自动退回 `AT+QMTPUB`）、上报行解析 |
| `uplink/board_link` | 上传口客户端：`W` / `w` 帧维护工单表，`R` 帧（每件一行）累计件数与最近一件，`S` 帧当心跳，`I` 帧（图片）不读直接跳过 |
| `uplink/mb_client` | 极简 Modbus-TCP 主站（回环）：读输入 / 保持寄存器、写单个寄存器，固定用监视单元号，短超时、出错重连 |
| `uplink/board_env` | 读 `des_app` 会话目录里最新的 `env.csv` / `vib_*.csv` 末行（只取写完整的行、按表头找列）和 `/proc` 的 CPU / 内存 / 开机时长、SD 卡剩余，给状态的 `env` / `vib` / `sys` |
| `uplink/sha256` | SHA-256 与 HMAC-SHA256（头文件），给远程命令验签 |
| `uplink/uplink` | 状态机 init → sim → register → data → mqtt → up，失败按 2 s 起翻倍到 60 s 退避重试；状态 / 工单发布、有线链路监视、每秒读一次线体寄存器、命令验签与执行 |
| `tools/des_4g.cpp` | 命令行入口 |

**主题**（前缀 `topic_prefix` 在配置里，取一串别人猜不到的字符）：

| 主题 | 方向 | 内容 |
|---|---|---|
| `<前缀>/state` | 板 → 云，保留消息 | 线体状态 JSON：`online`、`app`（`des_app` 在不在）、`session`、`total / ok / ng / recheck`、`last`（最近一件的类别 / 去向 / 置信度 / 外径）、`wo`（活动工单数 / 待确认数 / 最高级别 / 最高级别那张的编号与标题）、`eth`（网线 1 通 0 断 -1 未知）、`net`（信号 `csq` / `dbm`、运营商、制式）、`tx`（发布成功 / 失败 / 连接次数）、`counts`（件数来源：`feed` = 从上传口累计，`app` = `des_app` 自己的计数器）；读得到寄存器时另有 `line`（运行状态 0 停 1 运行 2 暂停 3 急停 4 故障、实际带速、`set` 设定带速、报警码、配方），开放了命令时另有 `cmds`（允许的命令）、`nonce` 和 `seq`（上一条被接受的命令序号）；`sys`（板子 CPU 占用 %、内存可用 %、SD 卡剩余 MB 与 %、开机秒数），`des_app` 写了温湿度 / 振动文件时另有 `env`（`t` °C、`h` %RH、`age` 距文件最后写入的秒数）和 `vib`（`rms` g、`hz` 主频、`age`）——`des_4g` 每 5 s 读一次 `board.log_dir`（默认 `/root/des/data/log`）下最新的 `env.csv` / `vib_*.csv` 末行，不向 `des_app` 要任何东西。有变化时最快 `state_min_s` 2 s 发一次，无变化每 `state_period_s` 10 s 发一次。模组掉线时由运营商侧代发遗嘱 `offline`；程序正常退出时自己发 `offline` |
| `<前缀>/wo` | 板 → 云 | 每张工单每次变化一条，内容就是 `des_app` 推给运维站的那份 JSON；超过 1400 字节时依次去掉处理建议、详情等长字段 |
| `<前缀>/cmd` → `<前缀>/reply` | 云 → 板 → 云 | `{"cmd":"ping","id":n}` 总是应答（测下行通不通、量往返时间）。会动线体的命令见下面「远程命令」；应答 `{"id","cmd","ok"[,"err"][,"result"]}` |
| `<前缀>/meta` | 板 → 云，保留消息 | 开放了命令时，每次连上服务器发一次：`speeds`（可选带速档位，mm/s）、`recipes`（可切的配方 `{"id","name"}`），看板据此画按钮；不放进每 10 s 一条的状态里，省流量 |

**远程命令**：`ack`（确认工单，`arg` = 工单号，65535 = 全部）、`stop`、`pause`、`resume`、`start`、`reset`（复位报警）、`speed`（`arg` = 带速 ×10；配了 `commands.speeds` 时只接受其中的档位）、`recipe`（`arg` = 配方号；配了 `commands.recipes` 时只接受其中的配方；运行中 `des_app` 会拒绝，要先暂停或停止）。一条命令被执行要同时满足：配置了 `board.modbus_port` 且 `des_app` 映射 ≥ 0x0103；配置了 `commands.key`（至少 8 个字符）；命令在 `commands.allow` 里（默认只有 `ack` / `stop` / `pause`，**不含任何会让线体动起来的命令**）；消息带 `seq` 和 `sig`，其中 `sig` = HMAC-SHA256(密钥, `"<nonce>|<seq>|<cmd>|<arg>"`)，`seq` 比之前接受过的都大。`nonce` 每次启动随机生成并放在状态里，所以截获的旧命令在程序重启后作废，重启前则被 `seq` 挡住；密钥只在板上的配置文件和操作者的浏览器里，不上网。执行方式是写 `des_app` 的保持寄存器（与 PLC 走同一条规则），等它的序号寄存器加一后读回结果码，原样放进应答。

**第二条链路**：`eth` 取自 `eth_if`（默认 `eth0`）的载波状态。`mode` = `always`（默认）时不管网线通断都按上面的节奏发；`backup` 时网线通着只每 `idle_period_s` 60 s 发一次状态，网线一断立刻发一条并恢复全速，工单两种模式下都照发。网线断开时电脑上的运维站会显示设备离线，手机端的状态和工单不受影响。

**命令**：`des_4g probe`（列出模组各 USB 接口、逐个试 `AT` 找到 AT 口，打印型号 / 卡 / 信号 / 注册 / 固件有没有 MQTT 命令）、`des_4g at "<命令>" [超时秒]`（发一条 AT 命令）、`des_4g feed [秒]`（不要模组：只连上传口，打印将要上报的状态，可在现在的板子上跑）、`des_4g run [配置] [-v]`（正式运行，默认读 `/root/des/des_4g.json`；`-v` 打印 AT 收发）。配置示例 [des_4g.example.json](../ps/tools/des_4g.example.json)。`des_4g` 不进部署清单，手动 `scp`。

**手机看板**（[des_4g_view.html](../pc/uplink/des_4g_view.html)）：一个网页文件，不依赖任何外部库，自己实现 MQTT over WebSocket（只用 QoS 0），订阅 `<前缀>/#`。

| 区域 | 显示 |
|---|---|
| 顶部横幅 | 只显示当前最该看的一条：板子离线 / 数据停止更新 / 主程序没有响应 / 警告或故障工单 / 网线已断开 |
| 线体 | 板子在线或离线（离线来自遗嘱或正常退出时发的 `offline`；超过 150 s 没有新状态另行提示）、主程序、有线网、活动工单、上报程序已运行多久 |

| 远程操作 | 只在板子声明了可用命令时出现：填操作密钥（扫控制二维码自动填好），按钮只有板子允许的那几条，分三排：线体（确认全部工单 / 暂停 / 停止 / 继续 / 启动 / 复位报警）、处理零件时的带速（`meta` 里的档位，当前设定高亮，下面实时显示实际带速）、配方（当前配方高亮，运行中整排变灰）；每条都先弹确认；签名在浏览器里算，不依赖外部库；结果显示「已执行」或被拒绝的原因。`seq` 取「本机时钟毫秒数」与「状态里的 `seq` + 1」中较大的，几部手机轮流操作不会因为时钟不齐被当成重放 |
| 工单、事件 | 页面打开之后收到的工单变化（级别、标题、详情、处理建议、状态）；按时间倒序的事件（上线 / 离线、网线断开 / 恢复、新工单、工单状态变化） |

服务器的 WebSocket 地址和主题前缀在页面底部「连接设置」里填，只保存在这个浏览器里；也可以写在网址的 `#b=<WebSocket 地址>&p=<前缀>` 里（`#` 后面的内容不会发给网页服务器）。没有开放命令时看板只读，除了 `ping` 不向板子发任何东西；密钥同样只保存在这个浏览器里。工单消息不是保留消息，页面打开前发生的工单只能从「线体」一栏的活动工单数看到。

**二维码**：公开码 = `<看板网址>#p=<前缀>`，扫了只能看；控制码再加 `&k=<密钥>`，看板读到后存进本机浏览器并立即从地址栏去掉。所以**不能用浏览器「为此页面创建二维码」做控制码**（那时地址里已经没有 `k`），要用 [make_qr.py](../pc/uplink/make_qr.py)（OpenCV 生成 PNG 并解码回读核对）：`python pc/uplink/make_qr.py <输出目录> <文件名> <网址> [...]`。控制码只在演示时出示，演示后换密钥（改 `des_4g.json` 的 `commands.key` 并重启服务），旧码随即作废。

[fake_board.py](../pc/uplink/fake_board.py) 冒充板子，按 90 s 一圈的剧本（过件 → 警告工单 → 网线断开 → 恢复 → 故障停线 → 关闭）发同样格式的状态和工单，状态里带 `sim`，看板会标「模拟数据」，用于模组到货前预演；加 `--key <密钥>` 时它也接受带签名的命令（确认 / 暂停 / 停止 / 继续），用来预演「远程操作」；自检 `python pc/uplink/test_fake_board.py`（40 项，不需要网络）。

已验证（11-16，真实板子 + 4G）：看板放在 GitHub Pages 上（网址不入库），安卓手机走流量扫码打开，收状态、往返约 0.6 s；扫控制码自动填密钥，手机上启动 / 暂停 / 停止 / 确认工单 / 调速都生效，电脑上切配方 1→2→1、调速 50→30→50 生效（「继续」「复位报警」还没在实机上点过）（见 [log](log/2026-11-16-4G上报上板.md)）。⚠ 没验证：苹果手机、深色模式的显示。苹果手机一般不能直接运行本地网页文件，要放到网页空间上访问（现在的 GitHub Pages 即可）。

**边界**：

- 没配 `board.modbus_port`（或 `des_app` 是映射 0x0102 的旧版）时：件数是「`des_4g` 连上之后判定的件数」，没有线体运行状态和带速，没有远程命令。遇到旧版 `des_app`，`des_4g` 读到版本号后立即停用 Modbus 并记日志——那一次读取会被旧版算作 PLC，最多造成一张「PLC 通信中断」工单。
- 远程命令经公共服务器明文传输（没有 TLS）：别人看得到命令内容，但没有密钥伪造不了、重放不了。主题前缀和密钥都要换成自己的，不要用示例值。知道前缀的人还能往状态主题发假消息干扰看板显示（控制不了板子）。
- 远程调速设的是 `des_app` 的设定带速，自适应带速（`belt.adapt`）照常起作用：带上没有要处理的零件时按 `fast_mm_s`（现 80 mm/s）提速，有零件要抓或要分流时才回到设定速度、机械臂没准备好时再降。所以空带时改 50 / 70 看不出差别，看板在档位下面写明了这一点。
- 一条消息最多 1500 字节（模组限制）；发布用 QoS 1、一次一条，连续两条失败或收到 `+QMTSTAT` 就重连。没有 TLS。
- 现场要再确认的：场馆里的信号、公共 MQTT 服务器能否连通（到场后 `des_4g_service.sh status` 看日志里有没有 `connected to`）。
- 进程被重启（或强制结束）后，模组里上一条 MQTT 连接要过一会儿才释放，期间 `AT+QMTOPEN` 回「标识已占用」（result 2），按退避重试约 30 s 后连上；板子整机重启不受影响。同一块板上只能跑一份 `des_4g`：两份用同一客户端名会互相挤下线（服务脚本启动前会检查）。

**测试**：`ps/tests/test_uplink`（主机 / 板上，172 项，对端是脚本化的假模组和真实的 Modbus 从站代码）：SHA-256 / HMAC 标准向量、Modbus 主站读写与异常、状态里的线体数据与 `des_app` 计数、命令的验签 / 重放 / 白名单 / 参数 / `des_app` 拒绝的传递、旧版映射下自动停用、监视请求不计入 PLC；以及描述符解析、应答与主动上报的区分、提示符后发数据、联网 / 连接 / 订阅 / 发布（含老固件退回）、上传口帧解析（逐字节喂入、跳过图片）、工单统计、状态与工单长度上限、配置校验、状态机全流程（无卡 → 无网 → 上线 → 工单转发 → 拔网线 → 命令 → 断线重连 → 退出）与模组无应答 / 端口丢失。

## P2 草案

- **Web UI**：主线只做 HDMI；若做，复用上一届 Vue SPA（历史 / 远程 / 报表），MJPEG 走板载 JPU 硬编码。
- **语音 + LLM 助手**：麦克风 → ASR → LLM（function calling）→ 结构化指令 → PS 校验 → AXI → PL；LLM 不碰硬件，断网退回本地命令词表。

## 存储

**已实现（`src/app/part_log`）**：每件判定后一行 CSV（`/root/des/data/log/<日期>/parts_<会话>.csv`，44 列）+ 裁切图（`img/<会话>_<件号>_<类别>.jpg`，与 NPU 输入同一裁切函数 `roi_crop`，默认只存挡板 / 复检件）。关键列：时间、判定、测量、带坐标 / 姿态、PL 粗测、NPU 耗时 / 延迟、配方、颜色（完整定义见 `src/app/part_log`）。后台线程写盘、不等 SD 卡，队列满丢弃并计数；列与将来 SQLite 表一致；记录时间 = 本机时钟 + TIME 偏移（见上 CAN 0x104）。

**网口实时上传**（拓展 5，`part_log` 的 `NetFeed`）：`storage.feed_port`（默认 9500）> 0 时板子监听，电脑端 `python pc/feed/des_feed.py [--host <板子 IP>]` 或远程运维站 `pc/ops/ops_station.py` 实时收到每件记录（与 CSV 同一行）、零件图和运维工单（`W` / `w` 帧），存 `received/<会话>/parts.csv + img/`，断线自动重连。板子是服务端，电脑不用开入站防火墙；客户端队列有上限，慢或断开的只丢帧计数，**永不阻塞存储和产线**（帧格式见 `part_log.hpp` 文件头）。

**出数**：`pc/report/part_stats.py` 读这些 CSV 出报告数据（见 [pc/report](../pc/report/README.md)）。采集整帧训练图前在 SD 卡新建数据分区（见 [开发环境与构建](开发环境与构建.md)）。
