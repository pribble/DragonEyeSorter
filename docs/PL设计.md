# PL 设计

> 构建方法见 [开发环境与构建](开发环境与构建.md)；实测数据见 [测试与验证](测试与验证.md) 与 [log/](log/README.md)。

## 基线

在官方 NPU demo 工程 `soc_prj`（MIPI RX + ISP + VDMA + HDMI + NPU 软核，已过 P&R）上叠加自研模块；顶层 `src/system_top.v`，PS 与 AXI 互联在块设计 `design_0`。

**板端当前 v17b2c**（BOOT `08ec06c4` / 比特流 `f55ac9bf`，`VERSION` 17：v16 + `des_bpi` + `des_vib`，不含 `des_ptrig`；`pl_check.sh` 0 失败、同屏目视不闪，见 [log](log/2026-11-15-视频异步FIFO约束与黑屏重连.md)）；退路 v16 留在卡上 `BOOT.bin.v16`。v16 （BOOT `71f41a20` / 比特流 `f0f63c91`；`pl_check.sh` 0 失败）：新增 `des_485`（RS485 Modbus-RTU，窗口 `0x6xx`，J11 第 5 / 6 位）与帧起始锁存的编码器计数（`CAP_ENC0/1`），`VERSION` 16；对原有全部输出的整顶层等价回归逐拍一致。回退点 tag `v15-board-20261024`。逐版上板台账见 [pl/soc_base/README](../pl/soc_base/README.md)；逐轮重构与构建收敛明细见 [log/](log/README.md)。

**CAN 管脚**：底板 CAN 收发器接 PL 管脚 F20（TX）/ F19（RX），LVCMOS33、RX 上拉；RS485 接 L17（TX）/ N16（RX）/ N15（DE，1 = 发送；与 /RE 并联，原理图 p14）（硬件手册 p21），v16 起由 PL `des_485` 驱动。官方 demo 块设计没开 PS CAN（`CAN0_Available=0`，收发脚未约束）→ 把 PS 硬核 `can0_tx_out` / `can0_rx_in` 经块设计引到 `system_top`，再到 F20 / F19。J11 接 PC USB-CAN 双节点实测通过（240/240，见 [测试与验证](测试与验证.md)）。注意：① `ipms_canfd` 驱动的错误帧把 ACK 位置码 0x19 写进 data[2]，candump 显示成 bit-error，别被误导；② 驱动只支持 FD 模式，`ip link … fd off` 直接 EINVAL，收发经典帧不受影响（`can_up.sh` 照用）；③ 底板 B2B 管脚表把 CAN / HDMI 管脚写反，以硬件手册 + 实测为准。

### 官方源码可复用性（`soc_prj/src/` 清点）

- **我们的贡献点**：运动控制（步进脉冲 + 加减速、舵机总线主机、QEI、帧锁存、IO 同步）、图像处理（二值 / 形态学 / CCL / 投影测量 / ROI 缩放 / 张量打包）、AXI 寄存器堆、同步 / 去抖公共原语（`pl/soc_base/src/des/des_common.vh`，被 `des_regs` / `des_io` 纯 `include` 引用，不占寄存器地址）。

### 实现约束

- 寄存器读多路选择须为组合逻辑：`fvdma_ctrl` 桥按 1 拍取数，打 1 拍则 `0x3xx` 读回全是 THR。
- `clk_mipi` 在 `timing.sdc` 里约束到 `U_io_clk_div_1.clkdivout`（8.0ns，像素时钟 111.1MHz）；厂家原 SDC 写硬 MIPI PHY 引脚名，对本设计（LVDS IO）不生效。
- 跨时钟域用「翻转 + 两级同步」（像素域 ↔ 75MHz 已在 `set_clock_groups -exclusive`），不直接跨域采样。
- **构建必须单进程**（`read_design`→`bitgen`）：`timing.sdc` 的 `set_clock_groups` 只在单进程里全程有效；两段式 phy 段重放 SDC 时 PLL 引脚时钟对象尚未建立，全部 group no-op（phy 日志 12 条 `USR-6001`）。见 [开发环境与构建](开发环境与构建.md)「PL：构建与打包」。
- **VTC pclk ↔ 150M PLL 用 `set_max_delay 5.0 -datapath_only`（双向），不能声明异步**：两者之间是厂家 AXI4S→Video Out 异步 FIFO 的格雷码指针（`primary_addr_gray_reg → sync_r1_reg`）与复位，共 11 个端点。整组声明异步后这些路径完全不受约束，指针各位走线差可超过一个周期 → 偶发读错指针 → 视频丢同步 → 显示器整屏黑一下并重新识别「HDMI1」（第六轮起的比特流都有，v16 与限定后的 v17b2c 没有，见 [log](log/2026-11-15-视频异步FIFO约束与黑屏重连.md)）。5 ns 按厂家 Soft FIFO IP 的写法取（小于两边周期 6.666 / 6.734 ns），核对看 `soc_prj_exception.timing` 的 MCP/SMD 汇总：两条各 6 / 5 个端点、0 违例。VTC pclk ↔ NPU PLL 仍是 `-asynchronous`（只有 VTC 锁定信号去复位厂家 `pwm_0_1`，不进视频数据）；VTC → TMDS（`PLL_3` = 5×VTC）按同步分析，**不要**加异步组。HDMI 串行时钟另有 `set_clock_uncertainty -setup 0.15`，报告里 clk10 的余量已扣掉这 0.15 ns。
- **HDMI 像素时钟由内核按设备树设定，不是 IP 里的静态参数**：时序发生器参数 行 1920/88/44/148（总 2200）、场 1080/4/5/36（总 1125）；像素时钟 PLL 在每次开机时被内核 `anlogic-dynclk` 驱动经 DRP 重配成设备树 `axi_dynclk/expclk` 的值（`dmesg | grep dynclk` 可见）。厂家设备树原值是 **150 MHz → 实际 60.61 Hz、比 CEA-861 的 148.5 MHz 高 1.0%**（容差 ±0.5%），挑时序的显示器会偶发失锁重连，与比特流版本无关；板上启动分区的 `system.dtb` 已用 `scripts/boot/patch_dtb_pixclk.py` 改成 148.5 MHz（实测 148,498,535 Hz、误差 9 ppm，小数分频 M = 17.8198），原件留 `system.dtb.orig`。串行时钟随之为 742.5 MHz，与时序约束一致（改之前实际跑 750 MHz）。见 [log](log/2026-11-16-HDMI像素时钟150MHz改标准148.5MHz.md)。

### 资源

- 官方 demo 基线见 [pl/README](../pl/README.md)（LUT6 79% / slice 85.8% / ERAM 92.5% / DSP 59.6%，WNS −4.12ns；NPU 软核独占 2.24 万 LUT + 156 ERAM；LUT6 与 slice 是两个口径）。
- 现 v16：slice 84.22%、LUT 80.15%、ERAM 93.21%（261/280，剩 19 块）、DSP 65%（[log/2026-10-24 v16](log/2026-10-24-v16-RS485与帧锁存编码器.md)）；自研各域时序 0 违例；自研 `des_vision` 约 1k LUT + 2 ERAM + 13 DSP，`servo_bus` / `stepper_ctrl` 各数百 LUT，`des_485` 约 640 slice。单个新模块控制在几百 LUT 以内，不再加大模块；仍不够时 `des_vision` 用 `LANES=2`（滤波逻辑减半）。
- 自研与厂家明文 RTL 已做多轮零行为精简：**寄存器偏移、位域与复位值始终未变**，与 `ps/src/hw/des_regs.h` 同一次提交；逐轮行数与综合资源 A/B 数字见 [log](log/README.md)「PL 自研模块与逐版上板」。当前结论：自研域已到局部最优，后续只在实物联调反馈后再议；最近一次全流程重编 59m16s 收敛、Routed 0 违例但余量很薄 ⚠（见 [测试与验证](测试与验证.md)「阶段验证」）。
- ISP 白平衡两个「每时钟出一个商」的流水线除法器改为背靠背逐位除（`pl/soc_base/src/des/awb_seq_div.v`，改 `ui_isp/awb_1_1/awb.v`）：每 49 时钟一个新增益、增益差 ≤1 步、不再每帧开头复位；对照仿真 `run_sim.sh awb` 逐拍一致，省约 4k LUT + 5k FF。
- NPU 软核里的 YOLO 后处理 / 缩放单元理论上可省（我们是 ROI 分类 + PS 预处理），但 ArmNN Alnpu 后端依赖不确定，不动。

## 寄存器通道（已实现）

不改块设计：借用 GP0 上 `fvdma_ctrl`（`mipicam`）的 64KB 窗口 `0x8030_0000~0x8030_FFFF`，把地址线从 4 位加宽到 16 位，**偏移 `0x1000~0x1FFF` 引出到 PL 顶层的寄存器总线**（`des_clk` 75MHz / `des_wr` 单周期写脉冲 / `des_waddr` / `des_wdata` / `des_raddr` / `des_rdata`）。`0x0000~0x0FFF` 仍是厂家寄存器，`mipicam` 驱动照常使用；厂家寄存器写入已排除我们的地址段。改动见 [pl/soc_base](../pl/soc_base/)，仿真 [pl/sim/tb_des_axi.v](../pl/sim/tb_des_axi.v)。

**`PL_BASE` = `0x8030_1000`**，`des_regs` 寄存器（在 `system_top.v` 里）：

| 偏移 | R/W | 名称 | 说明 |
|---|---|---|---|
| 0x000 | R | `DES_ID` | 固定 `0x44455301`（"DES" + 版本 01） |
| 0x004 | R | `DES_VERSION` | v16 板上 16（编码见下） |
| 0x008 | R/W | `SCRATCH` | 读写测试 |
| 0x00C | R | `FREE_CNT` | 75MHz 自由计数器（硬件时间戳 / 延迟测量） |
| 0x010 | R/W | `LED_CTRL` | b0 = 接管 LED1，b1 = LED1 亮灭 |
| 0x014 | R | `FRAME_CNT` | ISP 输出帧起始计数（只看 tuser 上升沿） |
| 0x018 | R | `FRAME_TS` | 最近一次帧起始时的 `FREE_CNT` |
| 0x01C | R | `FRAME_PERIOD` | 最近两次帧起始的间隔（75MHz 计数；60fps ≈ 1,250,000） |
| 0x020 | R | `CAP_SEQ` | 已完成的 DMA 取帧次数 |
| 0x024 | R | `CAP_FCNT` | 写模块开始写这一帧时的 `FRAME_CNT` |
| 0x028 / 0x02C | R | `CAP_T0` / `CAP_T1` | 开始写 / 完成中断时的 `FREE_CNT` |
| 0x030 / 0x034 | R | `CAP_POS0` / `CAP_POS1` | 开始写 / 完成中断时的带位置（步进 `POS`） |
| 0x038 / 0x03C | R | `CAP_ENC0` / `CAP_ENC1` | 同一时钟沿的计米轮编码器计数（v16）：图像、步进、编码器三路同刻锁存 |
| 其余 | R | — | 读回 `0xDEADBEEF` |

`DES_VERSION` 编码：17 = v17 第 1 批（`des_bpi` + `des_ptrig` + `des_pwm` 的 `SLEW`，源码里已是 17，候选比特流已编出、**未上板，板上仍读 16**；这版比特流里 `SLEW` 关掉、`des_ptrig` 2 路；第 2 批加 `des_vib` 不改 `VERSION`，PS 按 `0x90C` 的 ID 判断有没有）；16 = v16（`CAP_ENC0/1` + `des_485`）；12 = v12~v15（重构 / 重编未改寄存器接口）；v8~v10 未改寄存器接口（v10 只去光源输出、未单独上板）。PS 只需判断 5 / 6 / 7 / 11 / 16（拍摄锁存 / `des_vision` / `des_pwm` / `des_io` / `des_485` 与 `CAP_ENC`）。

**拍摄锁存**：厂家帧写模块 `uidbuf_write` 开始写一帧、完成中断 `f2p_irq` 上升沿各翻转一次，经两级同步进 75MHz 域；开始时锁暂存、完成时整组更新 `CAP_*`，PS 在 `WaitFinish` 返回后有整帧时间读。PS 用 `CAP_POS0/1` 按件所在图像行插值，得该行读出时刻的带位置（卷帘快门）。

### 舵机总线主机 `servo_bus`（`PL_BASE + 0x100`）

[pl/soc_base/src/des/servo_bus.v](../pl/soc_base/src/des/servo_bus.v)：115200 8N1 单线半双工，**开漏发送**（只拉低，高电平靠 BSS138 模块上拉），发送期间关闭接收，每次传输后强制留 1 字节时间（约 87µs）的总线换向间隔。PS 只填帧主体，`FF FF` 帧头和校验和由硬件补。

| 偏移 | R/W | 说明 |
|---|---|---|
| 0x100 | W | `CTRL`：b0 发送（自清零）/ b1 等应答 / b2 清状态和计数 / b[14:8] 帧主体字节数（≤64） |
| 0x104 | R | `STATUS`：b0 忙 / b1 完成 / b2 超时 / b3 接收错（校验、长度、帧错）/ b4 应答正确 / b[14:8] 收到字节数 / b[23:16] 舵机状态字节 |
| 0x108 | R/W | 应答超时，单位 µs（默认 3000，从发送结束起算） |
| 0x10C / 0x110 / 0x114 | R | 时间戳（75MHz 计数）：首个起始位 / 最后停止位结束 / 应答收完 |
| 0x118 / 0x11C / 0x120 | R | 计数：超时次数 / 接收错误次数 / 已发帧数 |
| 0x140~0x17F | W/R | 发送缓冲 64 字节：帧主体 `[ID, LEN, INSTR, 参数…]`，字节 i 在第 i/4 个字的 `[8*(i%4)+:8]` |
| 0x180~0x19F | R | 接收缓冲 32 字节：应答去掉 `FF F5` 后的 `[ID, LEN, STATUS, 参数…, CHK]` |

- 仿真 [pl/sim/tb_servo_bus.v](../pl/sim/tb_servo_bus.v)（`run_sim.sh servo_bus`）用协议文档原例当标准答案，全过；SYNC WRITE 帧线上时长与理论一致（数字见 [测试与验证](测试与验证.md)）。

### 步进控制 `stepper_ctrl`（`PL_BASE + 0x200`）

[pl/soc_base/src/des/stepper_ctrl.v](../pl/soc_base/src/des/stepper_ctrl.v)：

- **模式**：速度模式（传送带连续走、改速度自动平滑过渡）+ 位置模式（梯形加减速，停在精确步数）。
- **速度表示**：每时钟前进的步数，Q0.32 定点；`inc = v[步/s] × 2^32 / 75e6`，单位换算由 PS 做；升降速节拍 10kHz。
- **输出极性**：按 TB6600 共阳接法（PUL 低有效、脉冲 5µs；换向后等 10µs 再发脉冲；ENA 使能时输出高）；顶层 `STEP_COMMON_CATHODE=1` 反相为共阴直驱（PUL 高有效，ENA 高 = 脱机），见 [硬件与接线](硬件与接线.md)。
- **运动中改写 `TARGET`**：传送带「停在某步」的做法（减速点自动重算）；目标落在运动方向身后（写得太晚）时减速停在目标之后（`AT_TARGET` = 0），不卡在 moving；改写成恰好等于当前位置则就地停（`AT_TARGET` = 1）。
- **停止**：`estop` 输入或写 HALT 立即停脉冲（不减速），置 HALTED。**速度上限**按每秒 5 万步用（5µs 脉冲需 10µs 周期）。
- **速度比例修正 `vscale`**（v17，来自 `des_bpi`）：有符号 Q0.16，实际脉冲频率 = 设定频率 ×（1 + `vscale`），只作用在相位累加器上；加减速斜率、刹车距离（`BRAKE`）和到位判断仍按设定频率算，所以修正怎么变都不影响停在哪一步。`vscale` = 0 时与 v16 逐拍一致。另输出 `cruise_o`（运动中、不在减速、当前速度 = `VMAX_INC`）给 `des_bpi` 判断这一段能不能调。

### RS485 `des_485`（`PL_BASE + 0x600`，v16）

[pl/soc_base/src/des/des_485.v](../pl/soc_base/src/des/des_485.v)。板载 SP3485EN（J11 第 5 位 485_A、第 6 位 485_B，板上 R121 120Ω 终端）。PS 只写 PDU（地址、功能码、数据，不含 CRC），其余全在 PL：

- 发前等总线静默 t3.5（`T35_US`，PS 按波特率设：3.5 × 11 bit，>19200 时固定 1750µs）；DE 提前 1 bit 拉高，PDU 后补 CRC16（初值 0xFFFF、反射多项式 0xA001、低字节在前），最后一个停止位结束即放 DE。
- 要应答时从发完起计 `TIMEOUT_US` 等第一个起始位；收到的帧以 t3.5 静默判结束，CRC 对全部字节（含 CRC）求余为 0 才算对；8 位数据、校验位 无 / 偶 / 奇、1 停止位；校验位或停止位错、超过 64 字节都单独标出。
- 空闲时总线上出现的帧（PC 当主站）存为监听帧，PS 读后应答清标志；`CTRL` 的 go / 长度和 `TX_BUF` 在传输进行中写入被忽略（不会像 `servo_bus` 那样改到正在发的帧）；`CTRL` b4 中止：A/B 接反或终端无偏置时总线可能一直不静默，PS 驱动超期后中止并报错。
- 仿真 [pl/sim/tb_des_485.v](../pl/sim/tb_des_485.v)（`run_sim.sh rs485`）60 项：CRC 金标准（01 05 00 00 FF 00 → 8C 3A；01 03 00 00 00 0A → C5 CD）、校验位、DE 提前 1 bit / 停止位结束释放，以及应答、超时（误差 <1%）、溢出、广播、监听帧、t3.5 间隔、忙时写保护、总线卡低中止，全过。

### 带速 PI `des_bpi`（`PL_BASE + 0x700`，v17 第 1 批，未上板）

[pl/soc_base/src/des/des_bpi.v](../pl/soc_base/src/des/des_bpi.v)。对应拓展 2「高级工业控制算法硬件实现 · PID 闭环」。上电默认关（`CTRL.b0` = 0，输出 0，皮带按 v16 开环走）。

- **测速（测周法）**：只认「计数到达 4 的倍数」这一种边沿（始终是同一个电气边沿，A/B 相位误差与占空比误差抵消）。距上一次取样满 `PERIOD` 后的第一个这种边沿结束一个窗口：速度 = 计数差 × 2³² ÷ 时钟数（Q0.32 计数 / 时钟），时间分辨率 1 个时钟。`TIMEOUT` 内没有边沿 = 皮带没动：`MEAS` 置 0、`STALL` 置位。
- **PI**：相对误差 e =（`SET` − `MEAS`）÷ `SET`（Q0.16，带死区 `DB`）；输出 = 限幅（e × `KP` >> 12 + 积分 >> 16，±`SMAX`），积分 += e × `KI`，积分同样限幅（抗饱和）。用相对误差，所以增益与带速、时钟频率无关。输出送步进的 `vscale`。
- **什么时候调**：只有整个窗口都处在步进巡航段（`cruise_o`），且巡航后已跳过 `SETTLE` 个窗口，才走一步；起步、减速、停在抓取线、改带速的过渡期间积分和输出保持不动。
- 资源：一个 48 / 24 位逐位除法器（两次除法复用，被除数与商共用一个移位寄存器）、一个 18 × 17 乘法器（两次乘法复用）。为了布得进去按器件收过一次：时间与速度量只保留 24 位（窗口最长 223ms；带速上限 2⁻⁸ 计数 / 时钟 ≈ 29 万计数 / 秒，实际带速约 1000 计数 / 秒），窗口时钟数直接用「距参考边沿的时钟计数」（`FREE_CNT` 每拍加一，不再存时间戳），每窗口计数差 16 位，两个计数器 16 位，除 `SET` / `SMAX` 外的配置寄存器只写不读。布局布线后 297 个逻辑 LUT + 276 个进位链 LUT、430 个寄存器、1 个 DSP（收之前 466 + 414 / 811 / 1）。
- 仿真 [pl/sim/tb_des_bpi.v](../pl/sim/tb_des_bpi.v)（`run_sim.sh bpi`，接真实 `stepper_ctrl` 与皮带 / 编码器模型，时钟缩到 1MHz）45 项全过：打滑 4% 时开环测得 48.00mm/s（±0.3%，编码器四相不等宽）、闭环回到 50.00mm/s（±0.3%）且修正量 4.17%；负载阶跃 0.6s 内恢复；超出限幅时输出恰好停在限值、解除后 0.7s 内恢复（无积分饱和拖尾）；停带 / 起步 / 改带速期间输出不变；堵转置 `STALL`；位置模式下带着 PI 仍停在精确步数；`BRAKE` 在连续修正 3s 后不变。⚠ 这些是仿真里的模型数字，不是实测，实物数字上板后进 [测试与验证](测试与验证.md)。

### 带位置比较触发 `des_ptrig`（`PL_BASE + 0x800`，v17 第 1 批，未上板）

[pl/soc_base/src/des/des_ptrig.v](../pl/soc_base/src/des/des_ptrig.v)。2 路；上电全部未布防，任何输出都不动。布防后的一路在位置源（步进 `POS` 或编码器计数）到达阈值的那一拍触发一次：锁存 `FREE_CNT`、自动撤防，并按配置执行动作。比较用低 24 位的差值，计数器回绕不受影响，阈值须在位置源前后 838 万个计数以内（步进约 175m 带长）；布防时阈值已经过了就立即触发并置 `LATE`。为了布得进去按器件收过一次：原先是 4 路、32 位比较、另锁存触发时的位置、`TRIG_OUT` 脉冲长度可调；现在不锁存位置（准时触发的位置就是阈值本身）、脉冲固定 100µs。口径是「位置同步输出」，不是电子齿轮。

- 动作：1 / 2 = 把配置里的脉宽装进 `des_pwm` 通道 0 / 1（并提前重启周期，见 `des_pwm`）；另可同时在 `TRIG_OUT` 出一个脉冲。
- 管脚：`TRIG_OUT` = J12 PIN21（V8，空闲脚；⚠ 按 [硬件与接线](硬件与接线.md) 空闲脚表的顺序对应，上板前用万用表核对）。
- 资源：布局布线后 151 个逻辑 LUT + 29 个进位链 LUT、210 个寄存器（收之前 434 + 56 / 578）。
- 仿真 [pl/sim/tb_des_ptrig.v](../pl/sim/tb_des_ptrig.v)（`run_sim.sh ptrig`，后面接真实 `des_pwm`）37 项全过：触发时间戳 = 位置读到阈值的那一拍、两个方向、跨 `0x7FFFFFFF→0x80000000` 与跨 24 位比较宽度（`0x00FFFFFF→0x01000000`）的回绕、编码器作位置源、迟到标志、两路同拍触发、脉宽装载与周期重启的时延、无截短脉冲、`SLEW` 逐周期序列（测试台里 `SLEW_EN` = 1）、撤防。

### 振动采集 `des_vib`（`PL_BASE + 0x900`，v17 第 2 批，未上板）

[pl/soc_base/src/des/des_vib.v](../pl/soc_base/src/des/des_vib.v)。对应拓展 1「频谱分析」、拓展 2「振动特征提取」、拓展 4「故障分级」。上电不采集：`CS` 高、`SCLK` 高、`SDIO` 释放，对其他模块没有影响。

- **接口**：ADXL345 三线 SPI（`SDIO` 一根线双向，模式 3，`SCLK` 3.75 MHz；ADXL345 上限 5 MHz）+ `INT1`（数据就绪）。传感器的全部设置由 PS 经 `XFER` 单字节读写完成，先写 `DATA_FORMAT` 的三线位；没写之前传感器在四线模式，读回全是 `0xFF`。
- **采样与时间戳**：使能后，`INT1` 为高且引擎空闲就一次读出 `DATAX0`~`DATAZ1` 六个字节（多字节读，传感器保证六个字节属于同一次转换）。时间戳 = `INT1` 上升沿那一拍的 `FREE_CNT`（两级同步，晚 2 拍），所以每个样本的时刻精确到 13 ns，与相机帧起始、编码器、对射边沿用同一个时间基准。`INT1` 按电平处理：使能时已经在等的样本也会读；每次读完 255 拍内不看 `INT1`，让它落下去。
- **FIFO**：512 × 64 位（块 RAM），每项 `{FREE_CNT[19:4], z, y, x}`；时间戳 16 位、分辨率 213 ns、14 ms 回绕一次，PS 按相邻样本还原连续时间。满了丢新样本并计数。
- **窗口统计（PL 时域特征提取）**：每 `WIN` 个样本（0 = 2048，复位 1024）锁存一次每轴的和（24 位）与平方和 >> 10（平方和 36 位）。三轴共用一个乘法器和一组加法器：每轴的寄存器轮转，一个样本 6 拍算完，不需要多路选择器。PS 用 `和 / N` 得均值、`平方和 × 1024 / N − 均值²` 得交流有效值。位宽按 ADXL345 数据最多 13 位有效（全分辨率 ±16 g，|x| ≤ 4096）、窗口最多 2048 定。为了布得进去去掉了最小 / 最大值（第一版有）。
- 仿真 [pl/sim/tb_des_vib.v](../pl/sim/tb_des_vib.v)（`run_sim.sh vib`，ADXL345 行为模型：四线 / 三线切换、多字节读期间数据不变、读 `DATAZ1` 清数据就绪；模型同时检查 `CS` 边沿时 `SCLK` 为高、半周期、`CS` 高电平时间 ≥150 ns、两边从不同时驱动 `SDIO`）21 项全过：读 `DEVID`（三线前 0xFF、三线后 0xE5）、写配置寄存器、半周期 133.3 ns、使能时已在等的样本被读到、100 个样本数值与时间戳逐个相符（时间戳 = 数据就绪沿 + 2 拍）、16 样本窗口的和与平方和与模型逐轴相符、采样中插入寄存器读写不丢样本、溢出时保留最早 512 个并计数、关闭 / 清除。
