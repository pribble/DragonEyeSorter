## 3. 新 PL 模块的规矩

读写时序那两条血泪教训——**读多路选择必须是组合逻辑**（`fvdma_ctrl` 桥在同一时钟给地址、下一沿取数）、**像素时钟域已加 `clk_mipi` 约束**（挂到 `u_rx_clk_gen/U_io_clk_div_1.clkdivout`，8.0ns）——结论已经写进 [03-PL设计](03-PL设计.md)「实现状态」与「PL 视觉」两节，踩坑过程见 [log/2026-10-11](log/2026-10-11-软件闭环_NPU_界面_PL视觉.md) §6~§9，这里不复述。新模块另外守这几条：

1. **跨时钟域**：像素域 ↔ 75MHz 用「翻转 + 两级同步」（两域已在 `set_clock_groups -exclusive` 里），不要直接跨域采样。
2. **控制资源**：单模块控制在几百 LUT 以内（v8 已 slice 约 82%、ERAM 93%，只剩 19 块），大块图像算法放 PS。
3. **每次换比特流**：上一个能用的版本留作 `BOOT.bin.prev`；跑一次 `pl_check.sh` 回归；改动提交进 `pl/soc_base/`——`soc_prj_Runs/syn_1/soc_prj.prj` 被 `*_Runs/` 忽略规则挡住，要 `git add -f`。

- **数字带日期和来源；同一指标有新旧两次实测，用新的、旧的放括号**。例：PS 定位耗时 10-11 2h 浸泡平均 5.9ms（7091 个采样），10-10 首测 6.8ms——上次你把 docs/07 改回了 6.8ms，已更正。

## 5. Git

- 推送前 `git pull --rebase`。
- `pl/soc_base/` 里 3 个文件（两个 `DR1_PHY_PLL_WRAPERR_*.v`、`proc_sys_reset_*.v`）因 CRLF 永远显示「已修改」，不入库：先 `git update-index --assume-unchanged <这 3 个文件>`（否则 `rebase --autostash` 会失败），rebase 完再 `--no-assume-unchanged`。
- Windows Git Bash 里 heredoc / `printf` 会吞反斜杠（`\b` `\t` 被转义）：含 Windows 路径或 `\n` 的脚本用编辑器写成文件再执行。
