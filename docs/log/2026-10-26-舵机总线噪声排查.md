# 2026-10-25~26 机械臂接 6.8V 后舵机轮流「无应答」：步进驱动器噪声与软件兜底

## 现象

机械臂改由新的 300W 降压模块供 6.8V 后，界面机械臂页几个舵机轮流闪「无应答」。PL 计数：开机 3 分钟、约 30 帧/s 里坏帧约 5%、超时约 1.3%。界面每轮读 6 个舵机位置各一次，读失败一次就闪一下。

## 排查（每组：停服务，6 个舵机各连读 150 次，或 300 次读）

| 条件 | 失败率 | 说明 |
|---|---|---|
| 6.8V，扭矩开 | 11% | 1~5 号 10~17%，夹爪约 5%；链路前后均匀 |
| 5.9V，扭矩开 | 9% | 电压不是主因 |
| 5.9V，扭矩关 | 7.7% | 电机电流不是主因 |
| 临时切回 v15 比特流 | 7.8% | 比特流不是原因（随后切回 v16） |
| PIN2（PL 地）↔ 6.8V 地，直流 | 2.4mV | 不是直流地电位差 |
| BSS138 GND 直拉舵机地 | 5.6% | 略好 |
| **步进驱动器 TB6600 失能 / 使能**（交替 3 轮） | **0 / 6~8%** | **噪声源** |
| 6.8V 模块挪到常电 24V（对照） | 关 3.3% / 开 5% | ⚠ 当时 ENA+ 线断了，驱动器其实一直使能 → 作废 |
| ENA+ 修好后 | 关 0 / 开 2% | 结论成立 |
| 信号线与地线绞 + TB6600 降到 2.0A | 关 0 / 开 6% | 走线细节影响大，难稳定压零 |

- 错法：舵机应答里「0 被读成 1」（位置随机），另有约一半是完全没应答。负极接线本来就是星形（电源三个 −V 分别接 TB6600、6.8V 模块、5V 模块），所以剩下的耦合是空间感应或经 TB6600 的 PUL−/DIR−/ENA− 回到 PL 地。
- 4.9V 时代没出现：当时舵机与 BSS138 用同一个 5V 模块（常电 24V 那一路），离 TB6600 远。

## 软件兜底（用户 10-26 同意；`des_hw` / `arm_io` / `belt_ctl`）

- **读重试**：`des_servo_read` / `ping` 超时或坏帧后重试 2 次，重试前先给该舵机 20ms 静默窗口（它可能听到了请求、只是回复丢了；坏帧里的 ID 也可能错位）。`desreg sread` 仍是一次原始收发（诊断用），`DES_SB_RETRIES=0` 可关重试。
- **动作命令读回校验**：`des_servo_sync_pos_checked` = SYNC WRITE 后逐个读目标寄存器 0x2A（只能读 2 字节；读 4 字节舵机不应答；上电未写过时读 0），不符的只对它们重发，最多 3 轮，仍不符返回 `DES_E_VERIFY`（抓取按失败处理，不当成已动）。`ArmExec` 的每帧、界面微调 / 复位都走它。扭矩开关同样读 0x28 校验（`des_servo_torque_checked`）。
- **界面去抖**：连续 2 次读不到才显示「无应答」。
- **皮带停稳释放驱动器**：`belt.release_idle`（默认开）停稳超过 `release_after_ms` 300 → ENA 关；要起步时先使能、等 `enable_settle_ms` 50 再发脉冲。停带抓取期间总线干净；皮带靠摩擦不动。

## 板上验证（v16，TB6600 2.0A，驱动器使能保持）

- `desreg sstress 100`：600 次读 **全部成功**，用掉重试 26 次（底下原始坏帧 26）。
- `desreg svsync 100`：5 个舵机 × 100 条原地校验命令 **全部确认、0 次重发**，读回重试 21 次；前后位置 ±1 计数（没动）。→ 之前的「无应答」主要是回复被打坏，下行命令基本不丢。
- `test_belt_hil` 50 / 100 / 150：每档 6/6，最坏 0.040 / 0.050 / 0.080mm，节拍 22.7 / 39.1 / 48.8 件/min（改前 0.030 / 0.050 / 0.050、22.8 / 39.1 / 48.9）。
- 2.0A 丢步核对：150mm/s 一轮发 47737 步，编码器 20425 计数 → 0.4279 计数/步（标定正转 0.4250，+0.7%，编码器多不是少）→ 不丢步。
- 主程序空闲时步进状态无使能位（驱动器已释放）。

## 程序退出时释放驱动器（10-26 晚）

用户 halt 关机后 24V 电源风扇转快：`des_step_stop` / `des_step_halt` 写控制寄存器时总带使能位，`Runner` 析构（停服务 / 关机）最后调 `des_step_stop` → 驱动器被重新使能、电机保持电流一直通着（停服务前状态 0x4、停后 0x14，复现）。直接 `halt` 后看门狗约 30s 重启板子，自启的 des_app 又把它释放，所以风扇随后会降回去。

- 新 `des_step_stop_release(h, timeout_ms)`：在动就减速（最多等 timeout，超时急停），停稳后 ENA 关。`Runner` 析构、`live --belt` 收尾、des_tool 退出（驱动器开着时）都改用它。
- 板上：空闲时停服务 → 仍 0x4；皮带 50mm/s 运行中停服务 → 约 0.25s 减到 0、状态 0x2（不动、未使能）；`desreg step stop` 使能（0x12）后跑一次 des_tool → 退出后 0x2。des_app `8cc3df12`、des_tool `3f8d0218`（旧版 `.prev`），服务 60fps。

## 仍值得做（硬件，根治）

TB6600 电源输入端并 470~1000µF；PUL / DIR / ENA 各与回线绞、套磁环；舵机信号线远离电机线。皮带转动时（机械臂回料盒途中、不停带夹取）总线仍有噪声，靠读重试 + 命令校验兜住。
