# 2026-10-13 合并后 PL 全量重编（soc_base）

## 背景

`b2360c0` 把 `pl/rtl/`（7 个自研模块）与 `pl/soc_patch/`（11 个改动文件）合并进 `pl/soc_base/`，引用改成 `src/des/*.v`、`src/constraint/{io.adc,timing.sdc}`。合并后没人在新布局下重编过——本次验证「还编不编得出比特流」，顺带核对资源 / 时序是否与 v8 一致；本机 `.env` 也刚改为真实路径，是换机后首次重编。

### 三个坑（照 docs/开发环境与构建.md 的命令在干净克隆里跑一定失败）

1. **`settings.cfg` 没入库**：`**/*_Runs/` 被忽略规则挡住，当初只 `git add -f` 了 `syn_1/soc_prj.prj`；而 `DefaultFlow.tcl` 第一步是 `source ./settings.cfg`。本次从厂家 demo 包取 `soc_prj_Runs/{syn_1,phy_1}/settings.cfg`（同器件 `dr1_90.db`、同封装 `DR1M90GEG400`、speed 2）。
2. **`phy_1` 还要有自己的 `soc_prj.prj`**：只放 `settings.cfg` 会报 `PRJ-8642 ... does not exist.` 并掉进 `td >` 提示符。厂家 phy 那份比 syn 多 `<compress>on</compress>` 与 `<PlaceProperty><opt_timing>high</opt_timing>`（GUI 里设的 bitgen 压缩与布局 effort），本次按厂家补齐，否则产物不可比。
3. **`td_commands_prompt.exe` 出错也返回 exit 0**：第一跑打印 `SYN exit=0 PHY exit=0`，实际 PHY 一行没跑。判断成败只能看 run 目录里的 `.<step>.end.f` 标记与产物文件。

## 结论

1. **合并后的新布局编得出比特流**：综合 / 布局 / 布线 / bitgen 四步 `.<step>.end.f` 标记齐全，资源与 v8 记录逐项一致 → `b2360c0` 的目录重构没有改变实现；自研各域（`clk_mipi`、75MHz、150MHz、NPU、PS AXI 口）全部 0 违例端点。
2. 18 个违例端点全部来自**厂家 VTC 域的跨域 recovery 检查**（VTC → NPU PLL / 75M PLL），是厂家设计固有的；本次 SWNS 比 10-10 记录的 −4.222 / 厂家 −4.120 差 0.2~0.3 ns（同一条厂家路径的布局差异），**HWNS 与基线完全一致（−2.594 ns）**。要压这条得改厂家 VTC 域复位同步结构，不在自研范围内。
