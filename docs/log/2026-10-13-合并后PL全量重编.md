# 2026-10-13 合并后 PL 全量重编（soc_base）

## 背景

`b2360c0` 把 `pl/rtl/`（7 个自研模块）与 `pl/soc_patch/`（11 个改动文件）合并进 `pl/soc_base/`，`soc_prj.prj` 的引用改成新路径（`src/des/*.v`、`src/constraint/{io.adc,timing.sdc}`）。合并后**没有人在新布局下重编过**——本次验证"还编不编得出比特流"，顺带核对资源与时序是否与 v8 记录一致。

同时本机 `.env` 从指向并不存在的 D 盘改为真实路径（工具链在 C 盘、厂家资料放在仓库外 `des-deps/`），所以这也是**换机后的首次重编**。

## 流程（TD 6.2.1 Build 6.2.175876，命令行，不开 GUI）

| PHY | 21:29:13 → 22:06:44 | opt_place → opt_route → bitgen | `soc_prj.bit`、`soc_prj_compress.bit`、`soc_prj_pr.timing`、`soc_prj_phy.area` |

### 三个坑（照 docs/09 的命令在干净克隆里跑一定失败）

1. **`settings.cfg` 没入库**：`**/*_Runs/` 被忽略规则挡住，当初只 `git add -f` 了 `syn_1/soc_prj.prj`；而 `DefaultFlow.tcl` 第一件事就是 `source ./settings.cfg`。每个 run 目录都要有自己的那份。本次从厂家 demo 包取 `soc_prj_Runs/{syn_1,phy_1}/settings.cfg`——内容通用（同器件 `dr1_90.db`、同封装 `DR1M90GEG400`、speed 2、相对路径正好匹配我们的布局）。
2. **`phy_1` 还要有自己的 `soc_prj.prj`**：只放 `settings.cfg` 会报 `PRJ-8642 ERROR: Project file soc_prj.prj does not exist.`，然后掉进 `td >` 提示符。厂家的 phy 那份比 syn 多一个 `<Property>` 块：`<compress>on</compress>` 与 `<PlaceProperty><opt_timing>high</opt_timing>`（GUI 里设的 bitgen 压缩与布局 effort）——本次按厂家补齐，否则 bitgen 产物与布局质量不可比。
3. **`td_commands_prompt.exe` 出错也返回 exit 0**：第一跑打印 `SYN exit=0 PHY exit=0`，实际 PHY 一行没跑。判断成败只能看 run 目录里的 `.<step>.end.f` 标记与产物文件。

## 结论

1. **合并后的新布局编得出比特流**：综合 / 布局 / 布线 / bitgen 四步 `.<step>.end.f` 标记齐全，资源与 v8 记录逐项一致 → `b2360c0` 的目录重构没有改变实现。
2. **自研模块零违例**：`clk_mipi`、75MHz、150MHz、NPU 各域与 PS AXI 口全部 0 违例端点，余量为正。
3. 18 个违例端点全部来自**厂家 VTC 域的跨域 recovery 检查**（VTC → NPU PLL / 75M PLL），是厂家设计固有的（docs/09 记录的厂家基线本身 SWNS −4.120 / HWNS −2.594）。本次 SWNS 比 10-10 记录的 −4.222 / 厂家 −4.120 差 0.2~0.3 ns，属同一条厂家路径上的布局差异；**HWNS 与基线完全一致（−2.594 ns）**。要压这条得改厂家 VTC 域的复位同步结构，不在自研范围内。

## 干净导出复现（同日，验证"仓库不缺东西"）

起因：有人问"是不是仓库里缺东西，导致跑不起来编译"。查证确认：缺的正是 TD run 目录里那几份小文件，已入库（commit `ae71b74`：`syn_1/{soc_prj.prj,settings.cfg}`、`phy_1/{soc_prj.prj,settings.cfg}` 加一份说明 README，均 `git add -f`；生成的 `*.db`/`*.log`/`*.bit` 等仍不入库）。

随后把 **HEAD 导出到临时目录**（`git checkout-index`，623 个跟踪文件、0 缺失）当作干净克隆，只补上本机不入库的 `.env` / `.env.make`，重跑：

|---|---|
| PL 综合（`DefaultFlow.tcl`，导出目录） | ✅ `read_design` / `opt_rtl` / `opt_gate` 三个 end 标记齐全，出 `soc_prj_gate.db`（28.1 MB）；**`soc_prj_gate.area` 的 MD5 与仓库内那次完全相同**（`2147C63A99A53F2CE2A79C8B59A6D515`）→ 综合结果逐位可复现 |
