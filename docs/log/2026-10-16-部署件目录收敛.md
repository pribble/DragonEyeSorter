# 2026-10-16 部署件目录收敛：板端脚本的唯一源 = `scripts/deploy/out/`

## 决定（2026-10-16，用户拍板）

原先上板脚本有两份、逐字节相同：`ps/board/`（`des.env`、`des_app.sh`、`can_up.sh`、`des_service.sh`、`pl_check.sh`、`soak.sh`、`display_check.sh`）是「源」，人改这里；`scripts/deploy/out/` 是 `deploy.sh --stage` 每次 `rm -rf` 重建的副本。于是「改一次提交两次」，且 `out/` 不能手改、不能手放东西。当天上午的盘点已确认「板上比 `out/` 多」的那几个文件其实都在 `ps/board/`（见 [板端布局盘点](2026-10-16-板端布局盘点.md) 第五节）。

**删掉 `ps/board/`，7 个文件移入 `scripts/deploy/out/`；板端脚本与 `des.env` 的唯一源就是 `out/`。** 配置与主程序不变，仍是「别处是源、`out/` 是刷进来的那一份」：

| 类别 | 唯一源 | `out/` 里的身份 |
|---|---|---|
| `des.env` + 6 个 `.sh` | **`scripts/deploy/out/`（就地改、就地提交）** | 源本体 |
| `des_app.json` / `recipes.json` / `label_list.json` | `ps/src/`、`models/` | 刷进来的副本 |
| `des_app` | `ps/build/`（编译产物，不入库） | 刷进来的副本 |
| `MD5SUMS.txt` | 生成 | 生成物 |

## 改了哪些

- 文件：`git mv` 7 个（4 个与 `out/` 同名同内容 → 只落删除；3 个测试脚本 → 重命名进 `out/`）。
- `scripts/deploy/manifest.tsv`：自启链 4 条的「源」列 `ps/board/…` → `scripts/deploy/out/…`；表头与「手动上板」一节的 `scp` 行同步。
- `scripts/deploy/deploy.sh`：`stage_payload()` 由 **`rm -rf` 重建** 改成 **「刷 + 清」** ——
  - 刷：源在 `out/` 之外的清单条目（`ps/build/des_app`、`ps/src` 与 `models` 的配置、模型）；
  - 不动：源就是 `out/` 自己的条目（脚本与 `des.env`）；
  - 清：不在清单、也不在新增变量 `manual_files`（`pl_check.sh` `soak.sh` `display_check.sh`）里的文件，以及「本地已缺的旧产物」，清的时候打印文件名与原因 —— 这是原来 `rm -rf` 顺带做到的防混版本效果，不能丢；
  - `MD5SUMS.txt` 增加一节「手动上板：测试 / 回归脚本」，左列哈希、右列仍是 `/root/des/<名>`（这三份确实上板，只是部署器不传）。
- 路径文字：4 个脚本里「缺 `des.env`，源文件见 …」的报错、`runner.cpp` / `test_can.c` / `canplc.c` 的提示、`ps/README.md`、`ps/Makefile`、`scripts/deploy/README.md`、`docs/板端布局.md`、`docs/环境与上手.md`、`docs/软件与UI.md`、`docs/测试与验证.md`、`pc/report/README.md`、`AGENTS.md` 第 7 条全部改指 `scripts/deploy/out/`。`docs/log/` 里的旧路径按「log 是当时快照」保留。

## 验证（本机 + 一次只读对板）

| 项 | 命令 | 结果 |
|---|---|---|
| 语法 | `bash -n` × 7 个 `.sh` | 全 exit 0 |
| 暂存刷新 | `bash scripts/deploy/deploy.sh --stage` | 「从仓库别处刷入 4 个文件，板端脚本与 des.env 就地不动，清掉 0 个」；`out/` 里 12 个文件（含 `des_app`）齐全 |
| 清理 | 手放 `junk_old_version.sh`、`stray_note.txt` 后 `--stage` | 两个都被清掉并打印原因；另放 `part_cls.json` 时打印「清掉本地已缺的旧产物」 |
| 缺文件不炸 | 临时移走 `out/display_check.sh` 后 `--stage` | exit 0，`MD5SUMS.txt` 手动节里少列它一行（`set -e` 下用 `if` 而非 `&&`，避免「最后一个文件不在」时整个刷新中断） |
| 对板只读比对 | `.\scripts\deploy\deploy.ps1 -DryRun` | 跑通：板子 `des`、清单 10 条、本地有 8 缺 2（两个 NPU 模型本地没导出，板上有） |

`-DryRun` 报的三处「需要更新」都不是本次结构改动引起的，**没有上板**（板子在跑自启服务，覆盖要 `-WithService`，留给用户决定）：

- `/root/des/des_app.sh`、`/root/des/des_service.sh`：本次改了一行「缺 `des.env` 时的报错文字」，下次部署会一起更新；
- `/root/des/des_app`：本地 `ps/build/` 那份（`d2f0a4f5`）比板上跑的（`279d3239`，见提交 `a108482`）新，属于既有差异。

## 顺带：`des_app` 命令盘点（回答「哪些用得上」）

按「谁在跑它」分成六档：产品链（`run` / `live`）、每次改动回归（`probe` / `display`）、到货标定（`calib-cam` → `calib-belt` → `calib-arm`）、验收出数（`measure -n` / `collect` / `soak.sh`）、舵机与臂上电（`arm …` / `home` / `goto` / `pick`）、排障备用（`locate` / `track` / `ik`）。逐档命令与依据清单已写进 [ps/README.md](../../ps/README.md)「命令速查」与[到货联调清单](../到货联调清单.md)。

结论：**没有「用不上」的子命令**，但 `locate` / `track` / `display` 三条只在特定场合跑（一次只看一件事），别指望它们是日常入口。
