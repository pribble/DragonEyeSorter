# 2026-10-14 PS 目录分层重组

## 结论

- `ps/` 从「8 个目录并排」改为**「1 个产品目录 + 5 个支撑目录」**：`src/`（产品源码，按角色分 `app` / `hw` / `sched` / `measure` / `ui` / `vision`）、`board/`、`tools/`、`tests/`、`kernel/`、`vendor/`。
- **全量重编通过**：`make -C ps all` 退出码 0，8 个产物齐全。`des_app` 19,660,656 B（重组前 19,660,240 B，差 416 B 来自 `-g` 调试信息里的源文件路径与行号，**无逻辑改动**）。
- 重组只动文件位置与引用路径。全仓库唯一一处跨目录 include（`tools/desreg.c` 的 `"../common/des_hw.h"`）改为平铺 `"des_hw.h"`，其余 `#include` 都是纯文件名、靠 `ps/Makefile` 的 `INC` 解析 —— 零 `#include` 改动。

## 清理

- 删 `common/pl_map.{c,h}`（已废弃：指针非 volatile，轮询会被优化掉；无引用）与 `common/label_list.{c,h}`（无调用者，类别表实际由 `src/app/config.cpp` 解析 `models/label_list.json`；要恢复从 git 历史取）。
- `mipicam_module.h` 原有两份（`kernel_modules/` 与 `vision/`，MD5 同为 `EABFA9B868E1`）：**合一到 `kernel/`**，`src/vision/mipi_camera.cpp` 经 `-Ikernel` 用同一份，ioctl ABI 不再分叉。

## 复现与验证

```powershell
& '<FD_ROOT>/toolchain/build-tools/bin/make.exe' -C ps clean
& '<FD_ROOT>/toolchain/build-tools/bin/make.exe' -C ps all      # 退出码 0
# 产物：desreg / test_scheduler / test_calib / test_measure / test_belt_hil / test_can / canplc / des_app
```

途中撞到一次：`json.hpp` 挪到 `vendor/third_party/` 后 `test_calib` 报 `json.hpp: No such file or directory` —— `INC` 漏了 `-Ivendor/third_party`，补上即过。**教训**：平铺 include 的项目里，搬动任何被 include 的头都要同时改 `ps/Makefile` 的 `INC`。
