# 2026-11-12 4G 上报程序 `des_4g`（源码 + 主机测试，未上板）

> 决赛前追加的拓展项（拓展 5「4G 远程监控」、拓展 3「链路冗余」）。分支 `ps/4g-uplink`，从主线拉出，与 PL v17 分支互不依赖。
> 结论同步在 [软件与UI](../软件与UI.md)「4G 远程监控与第二条链路」。

## 1. 为什么这样做

- 底板 4G 位是 M.2 Key-B，厂家配套模组是移远 EM05-CN。厂家的 4G 例程用 `GobiNet.ko` + `quectel-CM` 拨号。
- 我们 SD 系统用的是 NPU 演示的内核，离线比对导出符号：没有 USB 网卡框架（usbnet）、没有 USB 串口（option）、没有 PPP / TUN。厂家的驱动装不上，模组的 AT 口也不会变成 `/dev/ttyUSB*`；厂家 4G 例程的内核又没有 NPU 驱动，不能互换。
- usbfs 属于 USB 核心，不需要额外驱动；模组自带 TCP/IP 和 MQTT 客户端。所以走「用户态经 usbfs 发 AT 命令 + 模组自带 MQTT」，内核和 `des_app` 都不动。

## 2. 依据的资料

移远 EM05 系列规格书 V1.7、EM05 硬件设计手册 V1.1、EC2x&EG9x&EM05 MQTT 应用手册 V1.1、TCP/IP AT 手册 V1.0、AT 手册 V2.0、Linux USB 驱动手册 V1.8，底板原理图第 9 页。用到的结论：

- 模组开机脚在底板上经 1 kΩ 上拉，上电自动开机；卡座无插卡检测，先插卡再上电。
- EC2x 系列 USB 接口 0 诊断、1 定位输出、2 AT、3 调制解调器、4 网卡；主动上报默认只从 AT 口出。驱动手册没单列 EM05-CN，所以程序逐个接口试 `AT`。
- 串口驱动打开端口时会发 `SET_CONTROL_LINE_STATE`（DTR / RTS），整包长度的批量 OUT 后要补零长包；程序照做。
- MQTT：`AT+QMTPUBEX` 定长发布，单条 ≤ 1500 字节，在途 ≤ 5 条；`AT+QMTOPEN` / `QMTCONN` / `QMTSUB` / `QMTPUBEX` 的网络结果在 `OK` 之后另起一行上报；`+QMTSTAT` 报断线。激活数据连接最长 150 s。

## 3. 一个设计取舍：不走 Modbus

最初打算让 `des_4g` 从 Modbus-TCP 读状态、写命令。读代码发现 `des_app` 把每个 Modbus 请求都计为「PLC 在线」（1 s 窗口），在线过又停掉会在 1 s 后开「PLC 通信中断」工单并亮黄灯。也就是说 `des_4g` 只要发一个请求就会制造一张假工单。

本版因此只旁听上传口（只收不发）。代价：没有线体运行状态和带速，件数从连上那一刻起算，远程命令只留了 `ping`。要补齐，需要 `des_app` 一处小改：给监视用的请求一个专用单元号，不计入「PLC 在线」。这处改动没有做，等定。

## 4. 验证

- 主机（WSL，g++ 11）：`test_uplink` **132 passed, 0 failed**，`-Wall -Wextra` 无警告。假模组在 socketpair 另一端按移远的应答格式回话。
- 交叉编译（板子的工具链）：`make -C ps build/des_4g build/test_uplink` 通过，无警告。
- 主机上 `des_4g probe` 在没有模组时报「找不到厂商号 2c7c 的 USB 设备」并返回 1。

以上全部不是板上实测。usbfs 这一层（认领接口、异步批量 IN、DTR）只有编译通过，没有任何设备跑过。

## 6. 手机看板与模拟板子（同日补）

- `pc/uplink/des_4g_view.html`：单文件看板，自带 MQTT over WebSocket 实现（CONNECT / SUBSCRIBE / PUBLISH QoS 0 / PINGREQ），不引用外部库。
- `pc/uplink/fake_board.py`：冒充板子发同格式数据（标准库，TCP 直连服务器）；`test_fake_board.py` **27 passed**（编解码、剧本、对本机极简服务端的全流程）。
- 实测（电脑浏览器 + 公共 MQTT 服务器，数据来自 `fake_board.py`，两端都在这台电脑上、走家里的宽带）：看板经 WebSocket 加密端口连上并收到保留状态；一圈剧本里的警告工单、网线断开 / 恢复、故障工单、工单关闭都出现在横幅、工单和事件栏；`fake_board.py` 结束后看板显示「板子离线」；「测往返时间」得到 871 ms（1 次）。这个数字是「电脑 → 公共服务器 → 电脑」的往返，**不是 4G 链路的数字**，不能写进测试报告。
- 宽屏（1100 px）与手机宽度（456 px）两种布局都看过。深色模式、真手机、真板子没有测。
