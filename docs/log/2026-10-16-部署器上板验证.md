## 两处「板上比仓库新」

`--dry-run` 报的两处差异，方向都是板上更新，直接部署会回退：

1. **`/root/des/des_app`**：板上 `271ce618…` 19,931,128 B（板子无 RTC，mtime 显示 `1970-01-01 00:51:06`）；本机 `make -C ps all` 后 `8534cda9…` 19,850,984 B。两者相差 **80,144 B**，不是同一次构建；本机换新前的 `ps/build/des_app` 停在 10-15 01:18，比源码最新改动（10-16 01:12）还旧——**没重编就部署会拿旧二进制覆盖板上那份**。板上那份为何差 80 KB 未查（选项差异或未提交改动都没排除）。用户 10-16 补充：板上那份**比当前提交新**，新在哪些改动、有没有入库未查——在弄清之前别把本机构建覆盖到 `/root/des`。本机随后又重编一次，落盘修复后的构建 = `39b16c37…` 19,851,048 B。
2. **`/root/des/des_app.json`**：板上带 10-16 尺量的皮带参数——`belt_comment` 写「主动轴 4 圈（12800 步）皮带走约 265mm → 0.0207（有效辊径约 21mm）；dir = -1（前进 = 步进位置递减）」，`belt = { mm_per_step: 0.0207, dir: -1 }`；仓库里仍是估计值 `0.0098 / dir 1`。**这组实测值只存在于板上**，在收回仓库之前，任何一次正式部署都会把它覆盖掉。

## 第三轮：路径全部搬进 `des.env`（用户拍板「修脚本，不砍脚本」）

板端部署目录新增 `des.env`（**唯一含路径的文件**），所有 `.sh` 与 `des_app` 从它取，代码里的绝对路径全部删除：

| 谁 | 原来写死 | 现在 |
|---|---|---|
| `des_service.sh` | `DIR=/root/des`、`CONF`、`LOG`、`PIDF=/var/run/des_service.pid` | `readlink -f $0` → `DES_HOME` → source `des.env`；四个变量全取自 env，**PID 文件进 `<目录>/data/des_service.pid`**（每份目录一个，不全局抢）；`log()` 的 `mkdir` 也改按 `$LOG` 所在目录建 |
| `des_app.sh` | `cd $(dirname $0)`、`exec ./des_app -c ./des_app.json`、`insmod /opt/bin/mipicam.ko`、报错里 `/root/des/…` | 同一套 readlink/source；`exec "$DES_APP" -c "$DES_CONFIG"`、`insmod "$DES_MIPICAM_KO"`、报错信息用 `$DES_HOME` |
| `pl_check.sh` | `cd $(dirname $0)`、`R=/root/bin/desreg` | source `des.env`、`R=$DES_TOOLS/desreg` |
| `soak.sh` | `OUT=/root/des/data/soak-…`、`/root/bin/canplc` ×2、`df -k /root`、`/root/bin/desreg` | `$DES_DATA/soak-…`、`"$DES_TOOLS/canplc"`、`df -k "$DES_HOME"`、`"$DES_TOOLS/desreg"` |
| `main.cpp` | `-c` 缺省 `/root/des/des_app.json`；`collect` 只有 `--out` | 缺省 = `$DES_CONFIG`，没设就是**当前目录**的 `des_app.json`；`collect` 输出 = `--out` 或 `$DES_COLLECT` |
| `collector.hpp/cpp` | `out = /root/des/data/collect` | 缺省 `data/collect` 按配置所在目录解析（`dir_of` 同一条规矩），env 可覆盖 |

（`display_check.sh` 代码本来全相对，只把注释里的用法路径改成相对写法。）

**系统件保持绝对值、登记在 `des.env` 里**（跨目录，换镜像只改一处）：`$DES_MIPICAM_KO=/opt/bin/mipicam.ko`、`$DES_TOOLS=/root/bin`。`/dev/*`、`/tmp/*`、`/etc/init.d/S90des`（装机步骤）是系统接口，不算板端布局路径。

板上实测（`--dest /root/des/test`，4/4 更新 + `des.env`、`des_service.sh` 两个新件）：

- 落地的 `.sh` 与 `des.env`：**CR=0、`sh -n` 全过**，**代码行里 `/root/des`、`/root/bin`、`/var/run` 一个都没有**；`source` 自己的 `des.env` → `DES_HOME=/root/des/test`、`DES_CONFIG=…/des_app.json`、`DES_PIDF=…/data/des_service.pid`、`DES_COLLECT=…/data/collect`，`DES_TOOLS=/root/bin`、`DES_MIPICAM_KO=/opt/bin/mipicam.ko`。
- **测试目录的服务真的管测试那份**（本轮要证的核心）：`des_service: started (pid 1737, log /root/des/test/data/service.log)`；`ps` 里 `/bin/sh /root/des/test/des_service.sh _supervise` + `/root/des/test/des_app -c /root/des/test/des_app.json run --can can0`；PID 文件 = `/root/des/test/data/des_service.pid`（1737）；**`/var/run/des_service.pid` 全程不存在**。测试服务运行期间生产 `service.log` 一字节未动（420029 → 420029）；收尾起回生产服务（pid 1840、log 指回 `/root/des/data/service.log`），生产件哈希仍 `271ce618…` / `e187be80…`。
- `-c` 缺省三种情形（离线 `measure --image` 探，不碰相机）：A 无 `-c` 无环境、CWD=/tmp → **`config: cannot open des_app.json (using defaults)`**（响亮失败，不再静默读生产配置）；B 给 `DES_CONFIG` → 加载测试配置；C 走启动器 → 被单主保护拒绝，报错里带的就是测试目录自己的 `des_service.sh` 路径。
- 部署器加护栏：**正式部署**（非 `--dest`）发现监督进程在跑又要在传 `des_service.sh` → 直接拦下要求 `--with-service`（新旧 PID 文件位置不同，必须让旧脚本停、新脚本起）；无板自测第 3 段改为断言「全套进测试目录 + 落地脚本无写死路径」，四段全过。
- `.gitattributes` 补 `*.env text eol=lf`：`des.env` 是被 source 的，checkout 成 CRLF 会让值尾带 `\r`（`DES_HOME=/root/des\r` → 建出 `autostart.conf\r` 之类），与 `*.sh` 同一条理由。板上实测该文件 2636 B、去 CR 后仍 2636 B（无 CR）。
