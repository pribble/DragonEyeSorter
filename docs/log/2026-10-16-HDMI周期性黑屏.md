# 2026-10-16 HDMI 周期性黑屏排查

## 现象（用户报）

整个屏幕（含底部界面条）约**每分钟黑 1 秒**，显示器**不提示无信号 / 输入源** → HDMI 同步还在、送出的像素是黑的。正常运行（`des_app run`）下更频繁（用户：「一闪一闪」）。

## 排除

| 怀疑 | 结果 |
|---|---|
| des_app 崩溃重启 | 否：本次开机服务日志无退出 |
| 程序停止出画面 | 否：显示每秒 ≥39.7 帧（30 分钟 1815 行 fps 记录）；掉到 40 帧的时段与跟踪框多（27~42 个误检）的时段吻合，非每分钟一次 |
| 控制台自动息屏 | 否：`/sys/module/kernel/parameters/consoleblank` = 0 |
| 整板掉电 | 否：21 分钟时只有 USB WiFi 模块断开重连，同一集线器上的鼠标没掉 |
| PL 75MHz `FREE_CNT` 回绕（2³²/75MHz = 57.3s） | 否：显示 / 取帧路径不用它算时间差 |
| 显示 VDMA 报错 | 否：3 分钟每 ~20ms 读一次 `SR`（0x04）无错误位，只偶尔闪一下 bit12（帧计数中断，驱动清掉） |

## 对照实验（`ps/board/display_check.sh`，三段各 180 s，用户目视）

| 段 | 屏幕 | 用户看到 | VDMA SR 变化 |
|---|---|---|---|
| 1 停掉 des_app | fb0 控制台（vdmafb 开机初始化失败，实际是黑的） | 一直黑（无法判断） | bit12 闪 5 次 |
| 2 `des_app display`（只做相机 → HDMI） | 全屏相机 | **偶尔黑，每分钟 1~2 次** | 无 |
| 3 `des_app run` | 相机 + 叠加 + 界面 | **一闪一闪**（更频繁） | bit12 闪 8 次 |

→ 和界面 / 处理线程无关，最简单的显示程序也会黑。

## 原翻页方式与改法

原来每帧「写 `START_1`（0x5C）→ 写 `V_SIZE`（0x50）提交」：10-11 发现只写地址不生效、写 `V_SIZE` 才装载 —— 但这是**每帧重新提交整套参数**，提交时刻落在扫描的哪里由相机帧（60.02fps）决定，可能打断正在读的帧。

厂家 VDMA 参数 `NUM_FSTORES = 3`、`USE_MM2S_FSYNC = 0`、`GENLOCK_MODE = 0`（`design_0/ip/design_0_VDMA_0`），寄存器排布与赛灵思 VDMA 一致。板上手动验证 `PARK_PTR`（0x28）：写 `RdFrmPtrRef`（[4:0]）= 1 / 2 / 0，40ms 后 `RdFrameStore`（[20:16]）跟着变成 1 / 2 / 0，`SR` 无错误。

**改法**（`ps/src/ui/hdmi_out.cpp`）：`open()` 一次写好 3 个帧存地址（0 / 1 = 两块显示缓冲，2 = 原 fb0 地址），写一次 `V_SIZE` 提交，停在 2；之后每次 `flip()` 只写 `PARK_PTR.RdFrmPtrRef`，VDMA 在下一帧边界切换，不再每帧提交；`close()` 先停回 2 再还原寄存器。板上：`des_app display` 59.68fps，`PARK_PTR` 在 0 / 1 间交替且 `RdFrameStore` 滞后一帧跟随；退出后寄存器还原；`run` 60.0fps。

⚠ **周期没解释通**：文档记的显示时序是 60.6Hz（像素时钟 150MHz），与相机 60.02fps 的拍频约 1.7s，不是一分钟。新翻页方式是否消除黑屏**待用户目视确认**；若仍黑：① 正常运行中 `kill -STOP` des_app（画面静止、不再翻页）看静止画面是否也黑 → 区分软件与 PL / 显示器；② 换 v8 / 厂家比特流对比。

## 第二轮（同日）

停驻指针版上板后用户报：**每 1~3 秒黑一次**（比原来更频繁）—— 正好对上相机 60.02fps 与显示 60.6Hz 的拍频（约 1.7s）。结论：这块板的扫描 VDMA 在帧边界附近被切换 / 重新提交就会让整屏黑，换法不同只是撞上的概率不同。

**改为单缓冲、不翻页**（`hdmi_out.cpp`）：`open()` 提交一次地址（帧存 0 / 1 = 唯一的显示缓冲，2 = 原 fb0），第一帧画好后停驻指针切到 0，**之后再也不写 VDMA**，每帧直接写进正在扫描的缓冲（可能有撕裂线，带速下基本看不出）。板上 run 60.0fps，寄存器 PARK=0、S1=S2=显示缓冲。⚠ 待用户目视确认。


## 第三轮：单缓冲的副作用 → 改回双缓冲 + 画面缩小（同日）

用户确认单缓冲下仍 **1~3 秒黑一次** → 黑屏与我们写 VDMA 无关（首帧后一个寄存器都不写也照黑），待做：关光源控制器 → 换 HDMI 线 / 关显示器 FreeSync → v8 比特流对比。
同时用户报：底部界面盖住画面下沿，**检测框、线、字从上到下闪动** —— 单缓冲时每帧直接画进正在扫描的缓冲，扫描线追上画笔就看到半帧旧叠加。

**改法**：`hdmi_out` 恢复停驻指针双缓冲（显示缓冲开机清零）；`live` 布局改为相机画面等比缩到 1280×720 放左上（自写 NEON 缩放 `ui/scale23`），状态栏移到右侧 640×780，底部条带不再盖画面。板上实测：转换 12.8ms + 叠加 4.8ms，**每帧 18.2ms → 屏幕 40fps**（取帧 / 定位 60fps 不变）；截屏核对画面、颜色、框位置正确。⬜ 回到 60fps：面板 / 条带只在变化时贴（见 docs/软件与UI.md「布局」）。
