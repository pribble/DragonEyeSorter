# 2026-10-16 HDMI 周期性黑屏排查

## 现象（用户报）

整个屏幕（含底部界面条）约**每分钟黑 1 秒**，显示器**不提示无信号 / 输入源** → HDMI 同步还在、送出的像素是黑的。正常运行（`des_app run`）下更频繁（用户：「一闪一闪」）。

## 排除

| 怀疑 | 结果 |
|---|---|
| des_app 崩溃重启 | 否：本次开机服务日志无退出 |
| 程序停止出画面 | 否：显示每秒 ≥39.7 帧；掉到 40 帧的时段与跟踪框多（27~42 个误检）的时段吻合，非每分钟一次 |
| 控制台自动息屏 | 否：`/sys/module/kernel/parameters/consoleblank` = 0 |
| 整板掉电 | 否：21 分钟时只有 USB WiFi 模块断开重连，同一集线器上的鼠标没掉 |
| PL 75MHz `FREE_CNT` 回绕（2³²/75MHz = 57.3s） | 否：显示 / 取帧路径不用它算时间差 |
| 显示 VDMA 报错 | 否：3 分钟每 ~20ms 读一次 `SR`（0x04）无错误位，只偶尔闪 bit12（帧计数中断，驱动清掉） |

## 对照实验（`ps/board/display_check.sh`，三段各 180 s，用户目视）

| 段 | 屏幕 | 用户看到 | VDMA SR 变化 |
|---|---|---|---|
| 1 停掉 des_app | fb0 控制台（vdmafb 开机初始化失败，实际是黑的） | 一直黑（无法判断） | bit12 闪 5 次 |
| 2 `des_app display`（只做相机 → HDMI） | 全屏相机 | **偶尔黑，每分钟 1~2 次** | 无 |
| 3 `des_app run` | 相机 + 叠加 + 界面 | **一闪一闪**（更频繁） | bit12 闪 8 次 |

→ 和界面 / 处理线程无关，最简单的显示程序也会黑。

## 翻页方式与两次改法

- 原来每帧「写 `START_1`（0x5C）→ 写 `V_SIZE`（0x50）提交」：10-11 发现只写地址不生效、写 `V_SIZE` 才装载——但这是**每帧重新提交整套参数**，提交时刻落在扫描的哪里由相机帧（60.02fps）决定，可能打断正在读的帧。
- 厂家 VDMA 参数 `NUM_FSTORES = 3`、`USE_MM2S_FSYNC = 0`、`GENLOCK_MODE = 0`（`design_0/ip/design_0_VDMA_0`），寄存器排布与赛灵思 VDMA 一致。板上手动验证 `PARK_PTR`（0x28）：写 `RdFrmPtrRef`（[4:0]）= 1 / 2 / 0，40ms 后 `RdFrameStore`（[20:16]）跟着变成 1 / 2 / 0，`SR` 无错误。
- **第一次改法（停驻指针）**：`ps/src/ui/hdmi_out.cpp` 的 `open()` 一次写好 3 个帧存地址（0 / 1 = 两块显示缓冲，2 = 原 fb0 地址），写一次 `V_SIZE` 提交，停在 2；之后每次 `flip()` 只写 `PARK_PTR.RdFrmPtrRef`，VDMA 在下一帧边界切换，不再每帧提交；`close()` 先停回 2 再还原寄存器。板上：`des_app display` 59.68fps，`PARK_PTR` 在 0 / 1 间交替且 `RdFrameStore` 滞后一帧跟随；退出后寄存器还原；`run` 60.0fps。
- ⚠ **周期没解释通**：文档记的显示时序是 60.6Hz（像素时钟 150MHz），与相机 60.02fps 的拍频约 1.7s，不是一分钟。上板后用户报**每 1~3 秒黑一次**（比原来更频繁）——正好对上这个拍频。结论：这块板的扫描 VDMA 在帧边界附近被切换 / 重新提交就会让整屏黑，换法不同只是撞上的概率不同。
- **第二次改法（单缓冲、不翻页）**：`open()` 提交一次地址（帧存 0 / 1 = 唯一的显示缓冲，2 = 原 fb0），第一帧画好后停驻指针切到 0，**之后再也不写 VDMA**，每帧直接写进正在扫描的缓冲（可能有撕裂线，带速下基本看不出）。板上 `run` 60.0fps，寄存器 PARK=0、S1=S2=显示缓冲。
- 用户确认单缓冲下仍 **1~3 秒黑一次** → 黑屏与我们写 VDMA 无关（首帧后一个寄存器都不写也照黑）。待做：关光源控制器 → 换 HDMI 线 / 关显示器 FreeSync → v8 比特流对比。

## 同日的布局改动（副作用与新需求）

- 单缓冲下用户报：底部界面盖住画面下沿，**检测框、线、字从上到下闪动** —— 每帧直接画进正在扫描的缓冲，扫描线追上画笔就看到半帧旧叠加。
- **改回停驻指针双缓冲**（显示缓冲开机清零）；`live` 布局改为相机画面等比缩到 1280×720 放左上（自写 NEON 缩放 `ui/scale23`），状态栏移到右侧 640×780，底部条带不再盖画面。板上实测：转换 12.8ms + 叠加 4.8ms，**每帧 18.2ms → 屏幕 40fps**（取帧 / 定位 60fps 不变）；截屏核对画面、颜色、框位置正确。
- 用户要求等比放大填满、右栏缩短，**40fps 不能接受**；黑屏最近没再出现。
- 板上基准（`ps/tests/bench_scale.cpp`）：读相机缓冲 4.7ms、OpenCV 整帧 BGRA→BGR 4.6ms，2/3 缩放 11.2ms → 瓶颈是 NEON 运算，不是内存映射（writecombine / nocached 映射读要 151ms，不可用）。
- 改为 3/4 缩放（`ui/scale34`）：1440×780，源图上下各裁 20 行，右栏 480 宽；中间行先竖向平均再横向缩放 → 8.7ms。
- 状态栏 / 操作条改为内容变了才贴、光标单独补贴 → 叠加 4.5 → 2.2ms。
- 结果：`run` 模式每帧 13.0~13.9ms，**60fps**；截屏核对布局、换行、光标无残影。

## 10-22 后续

- 用户报：10-16 之后基本没再出现，10-21 最后一次运行时又短暂黑过，时间短、次数少；用户怀疑 HDMI 线。
- 已排除的仍成立（单缓冲、首帧后不写任何 VDMA 寄存器也会黑）→ 不是显示程序。剩下的怀疑按排查成本排序：
  1. **线 / 显示器**：换一根短的 HDMI 2.0 线；关显示器 FreeSync / 自适应同步；换一台显示器或电视（或 HDMI 采集卡）看是否同样黑。
  2. **干扰**：记下黑屏时皮带 / 舵机 / 光源控制器是否正在动作（TB6600 斩波、舵机电流突变）；HDMI 线远离电机线、步进线。
  3. **PL 发送串行器时序**：HDMI 串行时钟（约 743MHz）那条厂家路径对布局敏感（v7 +0.033 / v8 −0.338 / v9 +0.120 / v11 −0.066 / **v12 +0.041ns**），余量很小，板子热了可能偶发误码；若 1、2 都排除且长时间运行后更频繁，再对比 v9 比特流（+0.120ns）。
- 视频录制：拍摄日前用实际要用的显示器 / 采集卡连续录 10 分钟确认；正式拍时黑屏就补拍那一段。
