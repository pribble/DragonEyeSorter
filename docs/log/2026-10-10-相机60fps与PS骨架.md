# 2026-10-10 · 相机 60fps 根因、PS 骨架上板、v5 拍摄锁存

> 当日实测快照。PS 代码见 `ps/`。

## 一、相机只有 53fps 的根因：INCK 频率不对

v3 实测传感器 / ISP 输出 53.04fps（`FRAME_PERIOD` 1,414,154 @75MHz）；按 VMAX 2283 × HMAX 542 推算应为 60fps，差 12%。

| 项 | 值 |
|---|---|
| 传感器寄存器 | 厂家 demo 写的是 IMX415 **INCK 27MHz / 891Mbps** 那一套（BCWAIT 0x5D、CPWAIT 0x42 等） |
| 实际 INCK | PL `al_ip/PLL/PLL.v` 的 CLKC3（`O_imx334_clk_24m`，管脚 W20）：50MHz ×3 ×7 = VCO 1050MHz，÷44 = **23.86MHz**（IP 配置请求 24MHz，名字沿用 IMX334） |
| 推算 | 60 × 23.86 / 27 = **53.03fps** = 实测 |

→ 厂家原设计的遗留问题（换了 IMX415 + 27MHz 寄存器表，没改 PLL）。**修正（v4）**：`CLKC3_DIV 44→39`（同步 `CPHASE 43→38`、`DUTY_INT 22→20`）→ 26.92MHz（−0.3%）→ 预期 59.84fps；MIPI 每 lane 约 786 → 约 888Mbps，`clk_mipi` 约束（6.4ns）仍有余量。剩余 0.3% 由软件把 VMAX 2283 → 2276 补齐（`des_app.json` 的 `camera.vmax`）。批处理编译直接读 `PLL.v`，不会从 IP 配置重新生成。

## 二、取帧：PS 能拿到每一帧

厂家帧写模块 `uidbuf_write` 的地址寄存器实时使用、不在帧起始锁存，PS 只能在两帧之间的消隐期重新提交；`des_app probe` 在 `WaitFinish` 返回后立刻提交下一块（4 块环形），用 PL 帧号差判断漏帧：

| 条件（v3，53.04fps） | 结果 |
|---|---|
| SCHED_FIFO 60 + mlockall，8s | 425 帧，**PL 帧号差全为 1（0 丢帧）**，重新提交平均 0.2µs、最大 1µs |
| 普通调度（`--no-rt`），5s | 266 帧，0 丢帧，重新提交最大 4µs |

→ 厂家 demo 的 28fps 是它自己的串行流水（取帧 → resize → NPU → 后处理 → 显示）造成的，不是硬件 / 驱动限制；原计划的 PL 双缓冲排队**不需要做**。

## 三、PS 定位耗时

`des_app locate`：降采样灰度 → Otsu（下限钳位 60）→ 3×3 开运算 → 外轮廓 → `minAreaRect` → 单应矩阵换台面 mm。

| 降采样 | 灰度 | 阈值 + 开运算 | 轮廓 | 缓存同步 | 合计 |
|---|---|---|---|---|---|
| 1/2（960×540） | 9.3ms | 7.2ms | 3.9ms | 0.8ms | **21.3ms**（超 16.7ms 帧预算，隔帧取） |
| 1/4（480×270） | 2.4ms | 2.1ms | 1.6ms | 0.8ms | **6.8ms** |

两种降采样下同一目标中心差约 0.2mm、角度差 0.4°，默认 1/4。读 DMA 缓冲很慢（缓存同步 0.8ms、读 4MB 要 9ms），大图像别在 PS 上全帧做；尺寸测量用全分辨率 ROI。

## 四、PS 骨架（`ps/`）

- `common/des_hw`：舵机事务 / 步进 / 帧计数 / 拍摄锁存 C 接口；`desreg` 改用它后板上回归通过（PING 超时、SYNC 3298.9µs、move 3200 精确、反向速度模式减速停）。
- `scheduler/`（纯逻辑）：跟踪表（s = x − B、类别投票、越过判定线定去向）、调度（停带 = 步进位置模式停在「抓取线 − s」，两指占位与邻件求交、圆件试 12 个角度）、IK/FK 与取放航点；`test_scheduler` 板上 **103 项全过**（IK/FK 往返误差 < 0.01mm）。
- `app/des_app`：`probe / locate / track / ik` 四模式；配置 `des_app.json`，类别规则从 `models/label_list.json` 读。

## 五、v4 上板（PLL 修正）✅

BOOT md5 `f7aaa06e…`；全局 SWNS −4.191ns（厂家基线 −4.120，违例仍在厂家路径上）。板上 `BOOT.bin.prev` = v3。

| 测试 | 结果 |
|---|---|
| `desreg` | VERSION = 4；`FRAME_PERIOD` 1,253,454 = 16.713ms = **59.83fps**（预测 59.84） |
| `des_app probe --vmax 0`（VMAX 2283），8s | 479 帧，59.83fps，**0 丢帧** |
| `des_app probe`（VMAX 2276，默认），20s | 1201 帧，**60.02fps**（`FRAME_PERIOD` 1,249,612），**0 丢帧**，重新提交平均 0.3µs |
| 厂家 demo 回归 | 10s 内 mipicam 中断 281 次（≈28fps，与改前一致），无超时；`locate --dump` 图像完整、无撕裂 |

`mipicam.ko` 开机不自动加载（厂家脚本里才 insmod），板上用 `/root/des/des_app.sh` 启动。

## 六、v5 上板：拍摄锁存 + 步进 BRAKE ✅

BOOT md5 `f5d46c71…`；全局 SWNS −4.222ns（厂家路径）；**75MHz 域 SWNS +0.106ns**（读数据多路选择变深，余量比 v3 的 +0.451 小）；150↔75MHz 跨域路径最差 +1.785ns。板上 `BOOT.bin.prev` = v4。

| 测试 | 结果 |
|---|---|
| VERSION | 5 |
| `des_app probe` 10s（步进同时 3000 步/s 空转） | 601 帧，60.02fps，**PL 锁存帧号差全为 1** |
| 拍摄锁存 | 最后一帧带位置 36260 → 36308（48 步）；`CAP_T1 − CAP_T0` = 15.814ms × 3000 步/s = 47.4 步 ✓ |
| BRAKE（3000 步/s，加速度 20000 步/s²） | 217 步（理论 (3000² − 500²) / 40000 = 219）；停下后 0 |
| 目标改到身后（约 8000 步/s 时把 TARGET 改到当前位置 −100） | 减速停在 4278（越过 ≈ BRAKE 1587 步），moving = 0、AT_TARGET = 0，**不再卡死**；随后 `move 0` 正常回原点 |

### v5 设计（原记录）

- **拍摄锁存**：`uidbuf_write` 开始写帧时翻转 `O_W_start_tgl`，完成中断上升沿再翻转；`des_regs` 开始时暂存 {帧号, 时间, 带位置}，完成时整组更新 `CAP_*`（0x020~0x034）；跟踪表按件所在图像行在 `CAP_POS0/1` 间插值（卷帘快门）。此前 PS 在完成后才读步进位置，带速 50mm/s 时约 0.85mm 常值偏差。
- **步进**：`BRAKE`（0x224）= 当前速度刹停所需步数；位置模式下目标被改到身后时减速停在目标之后（以前会骤停并卡在 moving）。
- 仿真 `tb_des_axi`（锁存值只在完成时变化、序号递增）与 `tb_stepper_ctrl`（巡航 BRAKE > 0、运动中改目标精确停、目标在身后减速停不卡死）全过。

## 七、显示通路（供 UI 用）

`vision/hdmi.cpp` 的 `hdmi_t::show()`（往 `0x8010_0800` 写地址）以为能零拷贝，但本比特流 `0x8010_0000` 那组寄存器全读 0；真正的扫描输出是 `vdma@0x8020_0000`（24bpp BGR、行跨度 5760、`START_1` = fb0 显存、60.6Hz），相机 32bpp 不能直接翻页。`des_app display` 每帧 CPU 转 BGRA→BGR 进两块 CMA 缓冲之一再切 VDMA：60.0 帧/s（8s 479），转换 6.2ms（最大 22ms 首帧缺页）、刷缓存 0.6ms、开头丢 1 帧 → 60fps 显示不需改 PL，每帧约占一个核 7ms。Qt 控件层合成见 [软件与UI](../软件与UI.md)。

## 八、`des_app live`：带检测叠加的 60fps 显示（10-10 晚）

双线程：核 0（SCHED_FIFO）取帧 → BGRA→BGR 进显示缓冲 → 画叠加（跟踪框按**当前帧**带位置重投影，工作线程晚一两帧也对得上）→ 翻页；核 1（普通调度）定位 / 跟踪 / 调度并发快照。工作线程忙时到来的帧只被工作线程跳过，显示不跳。最终 **11.7ms/帧、59.96fps（20s 1200 帧，启动丢 1 帧），工作线程处理 99.9% 帧、定位 6.6ms**；此前初版 20.2ms/40fps（叠加层 6~12ms），主因是 3 行线宽 2 的 `putText` 约 5ms → 状态文字 10Hz 重画 + 标签线宽 1。`--dump x.png` 存第 180 帧 PNG（读缓冲 + 编码约 650ms，只调试用）。
