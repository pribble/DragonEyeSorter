# 2026-10-10 · 相机 60fps 根因、PS 骨架上板、v5 拍摄锁存

> 当日实测快照。PL 补丁见 `pl/soc_patch/`，PS 代码见 `ps/`（README 有构建 / 部署方法）。

## 一、相机只有 53fps 的根因：INCK 频率不对

v3 实测传感器 / ISP 输出 53.04fps（`FRAME_PERIOD` 1,414,154 @75MHz）。按 VMAX 2283 × HMAX 542 推算应为 60fps，差 12%。

| 项 | 值 |
|---|---|
| 传感器寄存器 | 厂家 demo 写的是 IMX415 **INCK 27MHz / 891Mbps** 那一套（BCWAIT 0x5D、CPWAIT 0x42、INCKSEL3 0xC6、INCKSEL4 0xE7、TXCLKESC 0x06C0 = 27×64） |
| 实际 INCK | PL `al_ip/PLL/PLL.v` 的 CLKC3（`O_imx334_clk_24m`，管脚 W20）：50MHz ×3 ×7 = VCO 1050MHz，÷44 = **23.86MHz**（IP 配置里请求的是 24MHz，名字沿用 IMX334） |
| 推算 | 60 × 23.86 / 27 = **53.03fps** = 实测 |

→ 厂家原设计的遗留问题（换了 IMX415 + 27MHz 寄存器表，没改 PLL）。
**修正（v4）**：`CLKC3_DIV 44→39`（同步 `CPHASE 43→38`、`DUTY_INT 22→20`）→ 26.92MHz（−0.3%）→ 预期 59.84fps；MIPI 每 lane 从约 786 提到约 888Mbps，
`clk_mipi` 约束（6.4ns）仍有余量。剩下 0.3% 由软件把 VMAX 2283 → 2276 补齐（`des_app.json` 的 `camera.vmax`）。批处理编译直接读 `PLL.v`，不会从 IP 配置重新生成。

（v4 上板实测：59.83fps；VMAX 2276 后 60.02fps，见第五节）

## 二、取帧：PS 能拿到每一帧

厂家帧写模块 `uidbuf_write` 是「提交一块缓冲 → 等下一个帧起始 → 写满 → 中断」，地址寄存器实时使用、不在帧起始锁存，所以 PS 只能在两帧之间的消隐期里重新提交。
`des_app probe`（`ps/app`）在 `WaitFinish` 返回后立刻提交下一块（4 块环形），用 PL 帧号差判断有没有漏帧：

| 条件（v3，53.04fps） | 结果 |
|---|---|
| SCHED_FIFO 60 + mlockall，8s | 425 帧，**PL 帧号差全为 1（0 丢帧）**，重新提交平均 0.2µs、最大 1µs |
| 普通调度（`--no-rt`），5s | 266 帧，0 丢帧，重新提交最大 4µs |

→ 厂家 demo 的 28fps 是它自己的串行流水（取帧 → resize → NPU → 后处理 → 显示一条线）造成的，不是硬件 / 驱动限制。原计划的 PL 双缓冲排队**不需要做**。

## 三、PS 定位耗时

`des_app locate`：降采样灰度 → Otsu（下限钳位 60）→ 3×3 开运算 → 外轮廓 → `minAreaRect` → 单应矩阵换台面 mm。

| 降采样 | 灰度 | 阈值 + 开运算 | 轮廓 | 缓存同步 | 合计 |
|---|---|---|---|---|---|
| 1/2（960×540） | 9.3ms | 7.2ms | 3.9ms | 0.8ms | **21.3ms**（超 16.7ms 帧预算，隔帧取） |
| 1/4（480×270） | 2.4ms | 2.1ms | 1.6ms | 0.8ms | **6.8ms** |

两种降采样下同一目标中心差约 0.2mm、角度差 0.4°。默认用 1/4。读 DMA 缓冲很慢（缓存同步只要 0.8ms，读 4MB 却要 9ms），大图像处理别在 PS 上全帧做；尺寸测量以后在全分辨率 ROI 上做。

## 四、PS 骨架（`ps/`）

- `common/des_hw`：舵机事务、步进、帧计数、拍摄锁存的 C 接口；`desreg` 改用它，板上回归（PING 超时 / SYNC 3298.9µs / move 3200 精确 / 反向速度模式减速停）通过。
- `scheduler/`（纯逻辑）：跟踪表（带坐标 s = x − B，多帧融合，类别投票，越过判定线定去向）、调度（停带 = 步进位置模式「停在 B = 抓取线 − s」，
  夹爪两指占位与邻件求交、圆件试 12 个角度，翻板冲突转复检）、机械臂 IK/FK 与取放航点。`tests/test_scheduler` 板上 **103 项全过**（含 IK/FK 往返误差 < 0.01mm）。
- `app/des_app`：`probe / locate / track / ik` 四个模式；配置 `des_app.json`，类别规则从 `models/label_list.json` 读。

## 五、v4 上板（PLL 修正）✅

BOOT md5 `f7aaa06e…`；全局 SWNS −4.191ns（厂家基线 −4.120，违例仍在厂家路径上）。板上 `BOOT.bin.prev` = v3。

| 测试 | 结果 |
|---|---|
| `desreg` | VERSION = 4；`FRAME_PERIOD` 1,253,454 = 16.713ms = **59.83fps**（预测 59.84） |
| `des_app probe --vmax 0`（VMAX 2283），8s | 479 帧，59.83fps，**0 丢帧** |
| `des_app probe`（VMAX 2276，默认配置），20s | 1201 帧，**60.02fps**（`FRAME_PERIOD` 1,249,612），**0 丢帧**，重新提交平均 0.3µs |
| 画面 | `locate --dump` 图像完整、直线无撕裂（MIPI 约 888Mbps/lane 接收正常） |
| 厂家 demo 回归 | 10s 内 mipicam 中断 281 次（≈28fps，与改前一致），无超时 |

注：`mipicam.ko` 开机不自动加载（厂家脚本里才 insmod），板上用 `/root/des/des_app.sh` 启动（缺模块时先 insmod）。

## 六、v5（仿真通过，16:55 开始编译，待上板）

  PS 在 `WaitFinish` 后有一整帧时间读；跟踪表按件所在图像行在 `CAP_POS0/1` 之间插值（卷帘快门）。现在 PS 是完成后才读步进位置，带速 50mm/s 时有约 0.85mm 的常值偏差。

- 仿真：`tb_des_axi`（锁存值只在完成时变化、序号递增）、`tb_stepper_ctrl`（巡航 BRAKE > 0、运动中改目标精确停、目标在身后减速停不卡死）全部通过。
