# 2026-10-30 抓取可达下限改 -10

## 1. 现象

连续几件在抓取线 x=438 报 `out of reach`：

```
[run] pick failed: track #7: out of reach
[run] track #7 recheck: pick failed (x 438, y -22)
```

更早还有 y=-14 / -15 / -16 的 `pick failed`。

`y=-22` 是零件中心的横向实测位置（CSV `y_mm`，台面坐标，+y = 机械臂侧），不是配置值；底座在 y=+142.4，y=-22 离底座 164.4 mm。和前后 30 cm 内有没有别的齿轮无关。

## 2. 判断

- picker 先按 `reach_y0`（当时 -80）+ 刹车距离停带，停稳后才在臂线程跑 `plan_pick` / `arm_ik`；`arm_ik` 的 `|c3|>1` 返回 `out of reach`，臂一步没动，`job_done` 改判复检、皮带恢复 → “停一下又放走”。
- 当前腕线（#5≈89°）几何下限模型 ≈ -21.0（`c3=1`），y=-22 差 1 mm 吻合。
- 文档 10-24 的抓取线竖直可达是 y −10~+60（[2026-10-24](2026-10-24-缺齿样品初测.md) 实测「y ≤ −20 竖直够不着」）；日志里 -14 / -15 也失败过 → 真实下限大概 -13~-15，模型 -21 没算底座 / 手指 / 侧框，偏乐观。
- 结论：`reach_y0=-80` 太宽，会先停带再失败；按文档的 -10 收。

## 3. 改动

- `ps/src/des_app.json`：`picker.reach_y0` **-80 → -10**；`reach_y1` 仍 80（未按文档 +60 收）。
- 板端 `/root/des/des_app.json` 同步；旧配置备份 `/root/des/des_app.json.before_reach10_1030`。
- 服务重启，`des_app` 60 fps；启动日志正常（storage / beam / npu）。
- 效果：y<-10 的件在判定线 x=195 改复检，不再停带；仍不会被夹，走复检箱。

## 4. 验证

- 未做真件回归：下次跑线看 y<-10 的件是否直接 recheck、不再停带。
