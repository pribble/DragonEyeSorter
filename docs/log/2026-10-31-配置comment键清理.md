# 2026-10-31 配置 comment 键清理

## 背景

三个入库配置件的字段说明以「`comment` / `xxx_comment` 字符串键」内嵌在 JSON 里（JSON 标准没有注释，这是冒充注释的写法）：`des_app.json` 19 行、`recipes.json` / `label_list.json` 各 1 行，占了文件大头（des_app.json 18.1KB → 5.0KB）。**全仓无任何程序读这些键**（grep `_comment` 零命中，C++ / Python 都只取自己认识的键），删掉对板端与 PC 工具零影响。

## 决定（2026-10-31，用户提议）

删掉全部 comment 键。这些大段文字混着三类内容，逐一核对后都有归处、无需搬运：

| 内容 | 归处（已有） |
|---|---|
| 沿革 / 实测数字（10-21 标定过程、0.8→0.6 之类） | `docs/log/` 各篇（注释里自己就引着 log 链接） |
| 字段语义与单位 | 代码注释唯一源：`config.hpp`（各字段）、`rs485_io.hpp`（coils 怪癖）、`arm.hpp`（zero_count 等） |
| 操作警告 / TODO | ui_params 覆盖配方尺寸警告 = [软件与UI](../../docs/软件与UI.md)「界面参数」；换模型 label_list 同换 / 放行轻飞边改一行 = [视觉与检测](../../docs/视觉与检测.md) §类别表；RS485 coils=8 = [软件与UI](../../docs/软件与UI.md)「RS485」；挡板标定操作单 = [到货联调清单](../../docs/到货联调清单.md) §6（比注释更细） |

且注释已开始腐烂：`measure_comment` 写 rule「标定实测后再开 enabled」，实际 `rule.enabled` 早已是 `true`；`picker_comment` 里 flying 段与 [运动控制与分拣](../../docs/运动控制与分拣.md) 重复。

## 改了哪些

- `scripts/deploy/out/des_app.json`：删 19 行 comment 键（顶层 16 + 嵌套 `flying_comment` / `colors_comment` / `rs485_comment`），其余字节不动；
- `scripts/deploy/out/recipes.json`、`scripts/deploy/out/label_list.json`：各删 1 行顶层 `comment`。
