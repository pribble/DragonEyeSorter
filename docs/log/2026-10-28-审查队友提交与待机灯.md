## 2. 逐项核对

- **PosAccum（皮带位置）**：与原来三份实现逐行相同——首次读数锚在 PL 计数零点、`uint32` 差值防回绕、`int64` 累计；`peek()` 在首次 `feed()` 之前的结果也与原 `now_mm()` 相同。`BeltDriver` 的方向符号在初始化列表里由 `cfg.dir` 直接算，与 `sign_` 一致。
- **门表合一**：门表现在不管 `flaps.enabled` 都会读进来，但 picker 里所有用到门的地方都经过 `gate_for()`，它先看 `gates_on`；Runner / live 也都改用 `gates_active()`。现在挡板关着（`flaps.enabled false`），行为与原来相同。运行中没有任何地方改 `flaps.enabled`，`gates_on` 不会过期。
- **门几何缓存**：键 = (门号, y, r)，`gate_margin` 是常量，`closed` 按 r、`sweep` 按 r + margin，与所有调用点一致 → 纯函数缓存，结果逐位相同。
- **删齿条**：`gear_ratio` 0 时原来就全部按齿轮测；新代码只在 `wid == 0` 这种不会出现的情况下少测一件。PC 端没有按列号读 CSV 的工具（`part_stats.py` 按列名读）。
- **裁切逆单应缓存**：`track_measure` 的缓存 = `px_to_part` 的逆、裁切也用 `px_to_part`；collector 同样 → 逐字节相同。
- **去掉调用方的版本判断**：`des_io_read` / `des_estop_latched` / `des_estop_clear` 在 des_hw 入口自己判断版本、旧比特流返回 `DES_E_ARG`，调用方 `== 1` / `== DES_OK` 的判断结果不变。
- **CSV 清洗挪到写盘处**：`PartLog::write` 仍对 label / dest / why 做 `csv_sanitize`；界面那份只是显示用。
- **servo_bus**：LEN 在 idx == 1 时按整字节检查 2~30，越界直接结束接收，所以写下标最大 31，删掉的守卫确实不会起作用。
- **des_togsync**：三级同步、取第三级（ap）/ 第二三级比较（res），与原来的手写链完全相同。
- **scripts 拆分**：仓库里没有残留旧路径的引用（只有一条历史说明）。

## 4. 三色灯待机改为不亮（用户 10-28）

- 现象：服务开机后处于空闲，绿灯每秒闪一次 = 继电器每秒咔哒一次，用户嫌吵。
- 改：新配置 `rs485.idle`：`off`（默认，空闲不亮）/ `green`（绿灯常亮）/ `blink`（原来的闪烁）。没选「常亮」作默认：绿灯常亮与运行一样，现场看到会以为皮带在转。
- 其余状态不变：运行 = 绿灯常亮（PLC 连上过又断了再加黄灯）、暂停 = 黄灯、急停 = 红灯常亮、故障 = 红灯闪，报警开始时蜂鸣器响 `buzzer_s`（1 s）。故障时红灯仍然每秒闪，继电器同样会响——要是嫌吵可以同样做成可选。
- 测试：test_rs485 加「默认空闲 1.5 s 内继电器一直不吸合」与 green / blink 两种模式（56 过，板上同）。
- 部署：des_app `f02e6fbf` / des_tool `5ad2d686` / des_app.json `26c93fe6`（旧版 `.prev`、`data/des_app.json.before_idle_1028`），服务已重启；PC 经 Modbus-TCP 读：空闲、RS485 在线、**灯读回全灭**、386 次 0 失败。

## 5. 故障红灯改为常亮固定秒数（用户 10-28）

- 用户：故障时也不要闪，改成常亮特定秒数。→ 新配置 `rs485.fault_s`（默认 10）：进入故障后红灯常亮 fault_s 秒再熄灭（< 0 = 一直亮到复位，0 = 不亮）；计时从线体进入故障状态那一刻起（rs485 线程记状态切换时间）。急停仍是红灯常亮到复位，不受它影响。
- ⚠ 现在的代码里没有地方会让线体进入「故障」（CANP_ST_FAULT 只在协议里定义、复位报警时处理）→ 实际红灯只在急停时亮；以后接「机械臂失败 / 总线掉线 → 故障」时自动按这个规则。
- test_rs485 60 过（板上同）：故障红灯在 fault_s 内常亮、两个闪烁相位都亮，超时熄灭，fault_s < 0 / 0，急停不受影响。PC rs485_tool demo 同步。
- 部署 des_app `bffcfbff` / des_tool `a9f79ec8` / des_app.json `228b9796`（旧配置 data/des_app.json.before_fault_1028），服务已重启；Modbus 读回空闲灯全灭、RS485 66 次 0 失败。

## 6. 运行时黄灯常亮 = PLC 掉线误报（用户 10-28）

- 现象：运行时绿灯 + 黄灯一直亮。原因：黄灯「PLC 掉线」的条件是「收到过 CAN 心跳或 Modbus 请求」且「最近 1 秒没有」；我部署后用电脑 `mb_client status` 读了一次状态，程序就当作接过 PLC，1 秒后判掉线，而这个「接过」标记只有程序重启才清 → 之后每次运行都亮黄灯。现场没有接 PLC。
- 改（用户定）：`PlcWatch`（rs485_io.hpp）——通信（每次间隔 < 1 s）不间断持续 3 秒以上才算接了 PLC，偶尔一次读数不算；线体回到空闲（停线）就清掉标记，下次启动不会因为上次拔掉的 PLC 模拟器亮黄灯；停线期间 PLC 一直在通信的，启动后立刻认得。
- test_rs485 68 过（板上同；新加：单次读数不报、3 s 后掉线报、恢复灭、停线清除、带着在线 PLC 启动）。部署 des_app `32aa04e8` / des_tool `2b7aaa6e`（配置没变），服务已重启（旧标记随之清掉）；之后又用 `mb_client status` 读了一次（就是原来触发误报的动作），下次运行应只亮绿灯。
- 顺带弄清：`scripts/deploy/out/MD5SUMS.txt` 里文本文件的校验值是**去掉回车符后**算的（make 末尾 deploy.ps1 -Stage 自动写），别手改；本节之前我手填的 26c93fe6 / 228b9796 是带回车的值，已由生成的 e5ceffa8 取代。
