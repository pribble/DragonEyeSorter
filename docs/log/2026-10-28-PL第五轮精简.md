## 根因分析

- **不是 RTL 回归（证据链）**：源码只差 `4ff55cd` 11 行；工程文件 / 约束（`soc_prj.al`、两份 `soc_prj.prj`、`soc_prj.hpf`、`settings.cfg`、`timing.sdc`）自上版起零提交；place 后 25 个 setup 违例端点**全部落在厂家 PLL / VTC ↔ NPU 的跨域 recovery 路径**（与 v14 / v15 / v16 同组），自研 75M / 像素 / 150M / PS AXI 域 0 违例且余量为正；36 项逐拍等价 + 9 项功能仿真为 11 行改动背书。
- **设计余量小是主因（数据）**：place slice **84.90%**（较 v16 84.22% 只高 0.68pt ≈ 350 slice）、ERAM **93.21%**、232 个 >100% tile / max congestion level 4；route 每次清溢出都要 36 / 43 轮 R&R、Phase2 越跑越慢（热区 2704→2905、线长 +2%），是「接近满载 → 绕线变长 → 更堵」的正反馈。同机同族历史：slice 83.2% 时 route 33~47min 收敛；10-17 先例 slice 90.2% 时 route 5h 不通、降到 81.7% 后 23min 通过——84.9% 正处敏感段，微小布种差异即可把收敛时间放大 5~10 倍。
- **机器负载是次要因素**：route 的 R&R 段 CPU 约 100%（单核跑满，不是被抢核），负载只放大 wall time 波动；但 route 峰值内存约 5.5GB、本机 15.6GB，内存 <6GB 时不应进 route。
- **工程文件不是杠杆**：elaborate 实测 11.4s（read_design 到结束约 21s，占 syn 约 2~4%）；三份工程文件 52 条完全一致、登记 HDL 45/45 均被例化（删除清单为空）→ 维持现状，删文件收益近乎 0。
- **结论**：**设计余量小（84.9% slice / 93.2% ERAM）+ `4ff55cd` 布种变化**导致临界区非确定性失控，没有可定位的功能 / 时序回归；减源码量能减缓、不保证收敛，治理杠杆在构建流程（两段式 phy + 布局检查点、机器 / 内存纪律），见 [开发环境与构建](../开发环境与构建.md)「编译时间与拥堵排查」。
