# 2026-10-31 配置唯一源并入 out：`des_app.json` / `recipes.json` 唯一源 = `scripts/deploy/out/`

## 决定（2026-10-31，用户拍板）

仓库里 `ps/src/des_app.json`、`ps/src/recipes.json` 与 `scripts/deploy/out/` 里那两份逐字节相同（10-16 收敛时有意保留「别处是源、`out/` 刷进来」的结构，见 [部署件目录收敛](2026-10-16-部署件目录收敛.md)）。实际使用中「改配置改 `ps/src/`、再 stage 刷 `out/`」两步易漏，而 `out/` 里文本件本来就要求入库（红线 3），双份没有额外价值 → **删掉 `ps/src/` 两份，配置唯一源并入 `out/`**，与板端脚本、`des.env`、`label_list.json` 同一待遇。

| 类别 | 唯一源 | `out/` 里的身份 |
|---|---|---|
| `des.env` + 全部 `.sh` | **`scripts/deploy/out/`（就地改、就地提交）** | 源本体 |
| `des_app.json` / `recipes.json` / `label_list.json` | **`scripts/deploy/out/`（就地改、就地提交）** | 源本体（本次并入） |
| `des_app` | `ps/build/`（编译产物，不入库） | 刷进来的副本 |
| `part_cls.json` / `part_cls_uint8.onnx` | `models/`（导出产物，不入库） | 刷进来的副本 |
| `MD5SUMS.txt` | 生成 | 生成物 |

## 改了哪些

- 文件：`git rm ps/src/des_app.json ps/src/recipes.json`（与 `out/` 那两份逐字节相同，板端内容无变化）。
- `scripts/deploy/manifest.tsv`：② 配置两条的「源」列 `ps/src/…` → `scripts/deploy/out/…`；表头「规矩」段同步（全部配置的唯一源 = `out/`）。
- `scripts/check/source_check.json`：`outAllowlist` 删掉 `des_app.json` / `recipes.json` 两条——它们现在是 manifest 登记的源本体，不再走「暂存副本」例外（检查器对「manifest 源」直接放行）。
- 注释与文档口径（唯一源指针全部改指 `scripts/deploy/out/`）：`scripts/deploy/deploy.sh`（头注、`stage` 变量注、usage、刷清注释、MD5SUMS 头两行、完成语）、`scripts/deploy/README.md`（清单表「配置」行、唯一源段、场景表、`out/` 是什么一节）、`docs/板端布局.md`（§3 默认值改 `out/des_app.json`、§7 边界）、`docs/开发环境与构建.md`（手动 scp 行）、`docs/软件与UI.md`（0x102 RECIPE 配方表指针）、`docs/视觉与检测.md`（配方名义值指针）、`ps/README.md`（目录树删 `src/des_app.json` 行、上板件指针含配置、`run` 配置指针）、`ps/Makefile`（头注两处）、`pc/report/README.md` 与 `pc/report/part_stats.py`（`RECIPES` 缺省路径 → `scripts/deploy/out/recipes.json`）、`pc/plc_sim/backends.py`（注释）。`docs/log/` 旧文按「当时快照」不回改。
