## 生成链适配

- `md2docx.py`：支持 `####`（Heading 3，黑体 11pt）；新增 `setup_header()`（logo 6.5cm 居中 + 0.75pt 底框线，页眉距边 1.2cm）；自检改为「页眉恰 1 图无文字」。
- `verify_report.py`（64 → 65 项）：旧「H1≥10 / H2≥20」「附录 A 前分页」删除；新增官方模板骨架断言（标题 = 官网报名名、H1 = 摘要+五部分、H2 = 1.1~4.2、H3 = 2.2.x/2.3.x/3.2.x）、**模板字数检查**（摘要 800 / 1.1~1.3 400 / 1.4~1.6 200 / 4.1 300 / 4.2 1000，Word 口径只数正文段）、页眉 logo 检查、参考文献 1~20 篇。
- `pdf_images_hires.py`：页眉 logo 是每页共用的图像对象，按「同一 xref 出现 ≥ 一半页面」识别；给 `--header <png>` 时**原地改写图像对象**（`update_object` + `update_stream`，所有引用页同步生效、对象数不变）。不能走 `Page.replace_image`——它先 `insert_image` 再 `xref_copy`，会在页面资源里留下孤儿图像对象（实测替换 1 张后总对象数 15→16、后续对账错位）。`update_stream` 默认自带 Flate 压缩，自己再 zlib 压一遍会双重压缩、解码出噪声（首版踩过，复核渲染发现后改传原始像素）。
- `logo_header.png`：最终取自**官方 docx 模板** `word/media/image1.png`（564×103，白底化入库）——这是官方素材的原始分辨率；从模板 PDF 直接抽 xref 得到的是不透明黑底（PIL 读回角像素 (0,0,0,255)），透明 PNG 在 Word 导出 PDF 时会被压成黑底，必须白底。
- **页眉模糊修复（同日晚）**：Word 导出把页眉 logo 重采样到 96 dpi（245px 铺 6.5cm），正文插图有高清化步骤、页眉没有，所以糊。修复后 logo 换回源图原生 564×103 ≈ **221 dpi**——与官方模板 PDF 自身页眉的分辨率一致（官方素材上限即此）；4 倍放大渲染逐字清晰。`--header` 复核要求替换后像素与源图一致，不做 300 dpi 门禁（源图原生 221 dpi 即上限）。
- `build.ps1` 保持 UTF-8 BOM；`.gitignore` 维持生成物不入库，logo 是唯一入库图片。
