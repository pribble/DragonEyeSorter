算子落点（YOLOv8n）：Alnpu backend 115 层（ALHardNPU×63、MemImport×28、Concat×13、ElementwiseBinary×6、Pooling2d×3、Resize×2）；CpuAcc 16 层（Splitter×8 + 配套 MemImport×8）。

- SiLU 已被融合进 ALHardNPU（63 个 ALHardNPU 对应 63 个 Conv），不需要为避开 SiLU 改网络。
- 唯一 CPU fallback 是 C2f 里的 8 个 Split，优先级低。

## 三、当日结论（对设计的反作用）

1. **瓶颈是 A35 上的 resize，不是 NPU** → 验证了 `roi_scaler` 下沉 PL 的架构决策；只缩 ROI 小图后该级开销可归零。
2. **算子全部落 Alnpu，零（416 模型）/ 极少（640 模型）CPU fallback** → R1 中"算子 backend 落点"悬念部分解除。
3. **CMA 共 128 MiB**，416 模型够用；640 模型 + ROI 缓冲需重新评估 → 路线 B 编内核时把 CMA 加到 256M。
4. **推理耗时相对节拍有巨大余量**（机械臂取放数百 ms 量级）→ 推理按物料触发即可，"60fps"口径仅对采集/预处理/显示成立。
5. **模型选型暂定 YOLOv8n @ 416×416**（按像素数缩放外推约 34ms，精度优于极简网，量化流程已验证）。此为推断值，待自训模型上板实测确认。

## 四、官方 ONNX 模型逆向拆解

| | yolo_face_uint8_15.onnx | fire_detect_sim_quant_uint8.onnx |
|---|---|---|
| producer | pytorch 1.13.0 | onnx.quantize 0.1.0（= ORT 量化器签名） |
| opset / ir_version | 14 / 7 | 13 / 7 |
| 输入 | FLOAT [1,3,416,416] | FLOAT [1,3,640,640] |
| 输出 | 2 头（anchor 版） | 6 头 cv2/cv3（YOLOv8 anchor-free） |
| 量化格式 | QDQ，UINT8 权重 + UINT8 zero-point + FLOAT scale，bias INT32 | 同左 |
| 量化粒度 | per-tensor（scale 均为标量） | per-tensor |

→ R1 降级依据：量化格式已确认是 ORT `quantize_static` 标准输出，fire 模型就是标准 ultralytics YOLOv8n（Detect 前截断）。

## 五、舵机总线与供电实测（万用表）

| 测量 | 结果 | 结论 |
|---|---|---|
| 断电通断档，两个舵机座信号脚之间 | 导通 | 确认总线舵机（六路并联），总线协议路线成立 |
| 上电直流档，信号脚对 GND 空闲电平 | **3.7V** | 超过 3.3V IO 绝对最大值（3.6V），**不能直连**，须 BSS138 转换 |
| 原适配器铭牌 | FY-1250：DC 12V / 5A / 60W，中心正 | 非 7.4V |
| 适配器空载 | 12.35V（+2.9%） | 开关电源空载虚高，健康 |
| 舵机座 V+ | **6.87V** | 扩展板内部有降压，舵机未超压；但偏低端（约 93% 扭矩） |

供电核算：4 轴堵转约 75W(入)，6 轴约 112W(入)，60W 适配器必然塌压 → 解释了"带不动"症状；超压损伤假设排除。

## 六、纯电阻分压为何不行（单线半双工）

- 接收方向：3.7V 分压后 ≈2.54V，可过门限；
- 发送方向：PL 3.3V 经 1k 被总线上拉网络拉到 ≈2.27V，舵机 VIH min = 2.0V，余量仅 0.27V，不可靠。
- 结论：BSS138（Philips AN97055 结构），不用 TXS0108E（自动方向检测在强上拉总线上会锁死）。

## 七、遗留问题

- ⚠ `camera` 阶段 26.9ms（37fps）而非 60fps：sensor 模式为 2/2-line binning，待确认是传感器帧率上限还是 DMA 拷贝开销。
- ⚠ fire demo 数据原缺（厂商脚本少传 `-s` 参数的 bug），本记录中 640 数据为补测后回填。
- ⬜ 逐个舵机 V+~GND 电阻 + 旷量检查（接新 24V/10A 电源前必做）。
