# 2026-09-20 · NPU 推理与硬件实测

> 首次上板验证快照，仅代表当日配置。

## 一、NPU 推理性能（yolo_face 416×416，MIPI + HDMI 全链路）

| 阶段 | 耗时 | 等效帧率 |
|---|---|---|
| `camera` | 26.9 ms | 37.2 fps |
| **`resize`（瓶颈）** | **37.1 ms** | 27.0 fps |
| **`npu`（纯推理）** | **26.0 ms** | 38.5 fps |
| `yolo`（后处理） | 0.20 ms | ~5000 fps |
| `hdmi` | 7.2 ms | 139 fps |
| **`inv_fps`（实际吞吐）** | **37.1 ms** | **26.9 fps** |

端到端延迟 `frame` = 107.6 ms（9.3 fps）。连续运行 3.5 分钟，每 10s 帧数 268~279，无衰减 / 泄漏 / 卡死。

## 二、fire demo（YOLOv8n 640×640）对照

| 指标 | yolo_face 416 | fire 640 |
|---|---|---|
| `npu` 纯推理 | 26.0 ms | 80.9 ms |
| `resize` | 37.1 ms | 69.8 ms |
| 实际吞吐 | 26.9 fps | 12.4 fps |
| 端到端延迟 | 107.6 ms | 249.9 ms |
| CMA 权重占用 | 8.85 MB | 4.70 MB |

> 补测回填：fire demo 数据原缺（厂商脚本少传 `-s` 参数的 bug），上表 640 列数据为补测后回填，不是与 416 同轮采集。

算子落点（YOLOv8n）：Alnpu backend 115 层（ALHardNPU×63、MemImport×28、Concat×13、ElementwiseBinary×6、Pooling2d×3、Resize×2）、CpuAcc 16 层（Splitter×8 + MemImport×8）；SiLU 已融合进 ALHardNPU，唯一 CPU fallback 是 C2f 里的 8 个 Split（优先级低）。

## 三、结论

1. 瓶颈在 A35 上的 resize，不是 NPU → 验证 `roi_scaler` 下沉 PL 的决策，只缩 ROI 小图后该级开销可归零。
2. 416 模型算子全部落 Alnpu、零 CPU fallback；CMA 共 128 MiB 够用，640 模型 + ROI 缓冲需重估 → 编内核时加 CMA 到 256M。
3. 推理耗时相对节拍余量巨大（机械臂取放数百 ms）→ 推理按物料触发即可，「60fps」只对采集 / 预处理 / 显示成立。
4. 模型选型暂定 YOLOv8n @416（按像素数外推约 34ms，待自训模型上板确认）。

## 四、官方 ONNX 模型逆向

| | yolo_face_uint8_15.onnx | fire_detect_sim_quant_uint8.onnx |
|---|---|---|
| producer | pytorch 1.13.0 | onnx.quantize 0.1.0（= ORT 量化器签名） |
| opset / ir_version | 14 / 7 | 13 / 7 |
| 输入 | FLOAT [1,3,416,416] | FLOAT [1,3,640,640] |
| 输出 | 2 头（anchor 版） | 6 头 cv2/cv3（YOLOv8 anchor-free） |
| 量化格式 / 粒度 | QDQ，UINT8 权重 + UINT8 zero-point + FLOAT scale，bias INT32；per-tensor（scale 均为标量） | 同左 |

→ 量化格式已确认是 ORT `quantize_static` 标准输出，fire 模型是标准 ultralytics YOLOv8n（Detect 前截断）。

## 五、舵机总线与供电实测（万用表）

| 测量 | 结果 |
|---|---|
| 断电通断档，两个舵机座信号脚之间 | 导通 → 六路并联总线舵机，总线协议路线成立 |
| 上电直流档，信号脚对 GND 空闲电平 | **3.7V** → 超 3.3V IO 绝对最大值（3.6V），不能直连，须 BSS138 转换 |
| 原适配器铭牌 | FY-1250：DC 12V / 5A / 60W，中心正（非 7.4V） |
| 适配器空载 | 12.35V（+2.9%）→ 开关电源空载虚高，健康 |
| 舵机座 V+ | **6.87V** → 扩展板内部降压，未超压；但偏低端（约 93% 扭矩） |

供电核算：4 轴堵转约 75W(入)，6 轴约 112W(入)，60W 适配器必然塌压 → 解释了「带不动」症状；超压损伤假设排除。

## 六、纯电阻分压不可行（单线半双工）

接收方向 3.7V 分压后 ≈2.54V 可过门限；发送方向 PL 3.3V 经 1k 被总线上拉网络拉到 ≈2.27V，舵机 VIH min = 2.0V、余量仅 0.27V，不可靠 → 用 BSS138（Philips AN97055 结构），不用 TXS0108E（自动方向检测在强上拉总线上会锁死）。

## 七、遗留问题

- ⚠ `camera` 阶段 26.9ms（37fps）而非 60fps：sensor 模式为 2/2-line binning，待确认是传感器帧率上限还是 DMA 拷贝开销。
- ⚠ fire demo 数据原缺（厂商脚本少传 `-s` 参数的 bug），本记录中 640 数据为补测后回填。
- ⬜ 逐个舵机 V+~GND 电阻 + 旷量检查（接新 24V/10A 电源前必做）。
