# 2026-11-16 4G 上报上板

## 硬件与模组

- 移远 EM05-CN，装在底板 M.2 位；天线接主集（M）与分集（D），GNSS 不接；联通卡（先插卡再上电）。
- USB `2c7c:0125`，5 个接口，AT 口 = 接口 2；固件 `EM05CNFDR08A03M1G_ND`，带 `AT+QMT*`。
- 实验室信号 23~28 / 31（−59 ~ −67 dBm），联通 FDD LTE Band 3；`AT+CFUN?` = 1（11-16 凌晨排查闪屏时临时设过飞行模式，重新上电后恢复）。

## 主程序

板上主程序换成集成分支编的 `des_app`（`3d15c34a`：温湿度、两种夹取补偿、振动 PS 侧、单元号 250 监视），备份 `des_app.before_int`。启动日志正常、60 fps；`des_4g feed` 能从上传口读到状态。

## 配置

`/root/des/des_4g.json`（权限 600，不入库）：服务器 `broker.emqx.io:1883`，主题前缀与操作密钥现场随机生成，`mode always`，`board.modbus_port 502`，允许的命令 `ack / stop / pause`。

## 结果

| 项 | 结果 |
|---|---|
| 连接 | init → sim → register → data → mqtt → up 全部走通，客户端名 `des-` + IMEI 后 6 位 |
| 上报 | 电脑端另起 MQTT 订阅，每 10 s 收到一条 `<前缀>/state`，含线体状态、件数、工单、网线、信号、发送计数 |
| `ping` | 往返约 0.6 s（电脑 → 服务器 → 4G → 板子 → 服务器 → 电脑） |
| 签错名的 `stop` | `bad signature`，拒绝 |
| 签名正确的 `stop` | 经单元号 250 写进 `des_app`，`ok`，`result 0`（线体本就停着） |
| 同一条签名命令重发 | `replayed`，拒绝 |
| 拔网线 | 断开 2 s 内发出 `eth=0`，断线期间照常每 10 s 上报，发送计数连续；插回后 `eth=1`。板子日志 `wired link is down: reporting over 4G only` / `wired link is back` |
| 开机自启 | `scripts/deploy/out/des_4g_service.sh`，`/etc/init.d/S91des4g` 指向它。整机重启：先发 `offline`，开机后约 15 s 连上服务器，约 35 s 恢复上报 |

## 发现的问题

- **只重启 `des_4g` 时**（模组不断电），模组里上一条 MQTT 连接要过一会儿才释放：`AT+QMTOPEN` 回 result 2（标识已占用），按退避重试约 30 s 后连上。整机重启时只多等了约 8 s。功能不受影响。
- 同一块板上**只能跑一份 `des_4g`**：两份用同一个客户端名，会在服务器上互相挤下线、反复重连。服务脚本启动前会检查有没有别的实例。
- `-v` 模式下 AT 命令的逐行记录没有及时刷新（用 `printf` 写、只有状态行 `fflush`）。服务里不用 `-v`，日志只有状态行。

## 手机看板与远程控制（当晚）

- 看板放到 GitHub Pages（网址不入库）；安卓手机关 Wi-Fi 走流量扫码打开，收得到板子状态，往返约 0.6 s。
- `des_4g` 加 `recipe` 命令、`commands.speeds` / `commands.recipes` 白名单、保留消息 `<前缀>/meta`（可选档位与配方名）、状态里的设定带速 `line.set` 和上一条命令序号 `seq`；`test_uplink` 192 项（电脑与板上各跑一遍）全过。板上 `des_4g` 换成新版（旧版 `.before_ctl`），配置放开 `ack stop pause resume start reset speed recipe`，档位 30 / 50 / 70，配方 1~4，**换了新密钥**（旧密钥作废，配置旧版 `.before_ctl`）。
- 经 4G 从看板：调速 50→30→50、切配方 1→2→1 都 `ok`（停机时做，设备不动）；切配方后 `des_app` 把设定带速恢复成 50。
- 手机扫控制码（`#p=…&k=…`）自动填密钥；台前实测启动、暂停、确认工单、停止、运行中调速 5 次，`des_app` 日志 `Modbus 启动 / 联锁暂停 / 停止` 对应。「继续」「复位报警」还没在实机上点。
- 运行中 50 和 70 看不出差别：不是命令没生效，而是自适应带速在空闲时按 `fast_mm_s` 80 提速、只在处理零件时回到设定速度。决定不改主程序，看板把这排改叫「处理零件时的带速」并实时显示实际带速。
- 坑：看板读到 `k` 后会把它从地址栏去掉，所以用 Edge「为此页面创建二维码」做出的控制码不带密钥。改用 `pc/uplink/make_qr.py`（OpenCV 生成并解码回读）。
