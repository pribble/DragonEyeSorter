## 结论

- **`des_app` 首次在本机编出**：`ps/build/des_app` 19,660,240 B，ELF64 / AArch64；`make -C ps all` 退出码 0，8 个产物齐全。此前 `ps/build/` 只有 7 个产物，`des_app` 从未编出来过。
- 过程中撞到三个坑，性质是同一个：**文档与自检脚本说"没问题"，构建说"过不去"**。

  1. **声明有、定义无**：`vision/` 50 个文件只有 4 个 `.cpp` 进编译，而 `icamera::enumerate_device` 声明在 `icamera.hpp`、定义在未编入的 `icamera_enum.cpp` —— 照厂家 demo 调用必链接失败。更麻烦的是"自然修法"（把 `icamera_enum.cpp` 加进 Makefile）会顺着 `usb_camera.hpp → stream_input.hpp → jputypes.h / JW_Wrapper.h` 拖进仓库里根本不存在的厂家 JPU 解码 SDK 头；`main.cpp` / `solution.cpp` 要的 `udp_send.hpp`、`main_helper.cpp` 要的 `JW_Encoder.h` 同样不在仓库里，修到一半卡死。
  2. **`FREETYPE_INC` 是空头配置**：`.env` 里路径正确但目录不存在，FreeType 头从未取到本机；而 `scripts/test_env.ps1` 把该项标 `[可选]`，失败也打印"✅ 核心环境配置正确"、`exit 0` —— 闸门与构建口径相反（`ps/Makefile` 的 `check-board` 是硬错误）。
  3. **`board_libs` 只有一套名字**：三个库只有链接名（`libfreetype.so` / `libpng16.so` / `libz.so`），缺 SONAME 名。链接器解析 `libfreetype` 自己的 `DT_NEEDED`（`libpng16.so.16` / `libz.so.1`）时按 SONAME 在 `-rpath-link` 目录里找不到文件，报 27 条 `undefined reference to png_*@PNG16_0` / `inflate*`。文档 §3 只教 scp 成 SONAME 名（那样 `-lfreetype` 又找不到库），§6 排查表还把方向写反。

## 处置

| 问题 | 处置 |
|---|---|
| `icamera::enumerate_device` 声明有、定义无 | 定义并进已编入的 `ps/vision/mipi_camera.cpp`（去掉 USB 分支，只认 `/dev/mipicam`）；`ihdmi` 侧删掉悬挂声明（显示走 `app/hdmi_out.cpp`）；`vision/` 删 22 个「一行未编 + 依赖仓库里不存在的头」的文件，50 → 28 个 |
| FreeType 头缺失 | 装到 `.env` 已指定的 `$FREETYPE_INC`（`.env` / `.env.make` 无需改动，路径本来就对，也不需要重生）；`scripts/test_env.ps1` 该项 `[可选]` → `[重要]` 并标注「编 des_app 必需」 |
| `board_libs` 只有一套名字 | 补出 SONAME 名副本；`scripts/sdk_fix_sonames.sh` 泛化为支持任意库目录（原先只认 SDK 的两个子目录，且 glob `lib*.so.*` 匹配不到无版本号的 `libX.so`）；`docs/环境与上手.md` §1/§3/§6 与 `scripts/README.md` 同步写明「两套名字都要有」及两种报错的对应关系 |
