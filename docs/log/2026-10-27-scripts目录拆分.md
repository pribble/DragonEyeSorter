# 2026-10-27 scripts 目录按职责拆分（bootbin + sd_image 合并为 boot）

**范围**：`scripts/` 顶层重构。原来 `scripts/` 根上平铺着环境脚本与校验脚本，旁边是三个功能目录（`bootbin/`、`sd_image/`、`deploy/`），「哪个脚本归谁」只能从文件名猜；`bootbin/` 与 `sd_image/` 各只有一两个文件，做的却都是「让板子启动」的介质准备。按「什么时候跑 / 碰不碰板子」重分为 `env/`、`check/`、`boot/`、`deploy/` 四个目录，`bootbin/` 与 `sd_image/` 合并为 `boot/`。**行为零改动**：只动文件位置与 `$PSScriptRoot` 推导层级，没有改任何命令、参数、清单或板端文件。

## 拆分结果

| 目录 | 内容 | 原位置 |
|---|---|---|
| `env/` | `env_loader.ps1` / `.sh`、`generate_env_make.sh`、`test_env.ps1`、`sdk_fix_sonames.sh` | `scripts/` 根 |
| `check/` | `check_docs.ps1`、`check_sources.ps1`、`doc_check.json`、`source_check.json` | `scripts/` 根 |
| `boot/` | `make_bootbin.ps1`、`boot.bif`、`parts/`（`fsbl.elf` / `u-boot.elf` / `MD5SUMS.txt`）、`flash_to_disk.ps1`、`boot.cmd` | `bootbin/` + `sd_image/` |
| `deploy/` | 不动（`manifest.tsv` + `deploy.ps1` / `.sh` + `out/`） | — |

四个目录的分工与命令入口唯一源：[scripts/README](../../scripts/README.md)。共 16 个入库文件用 `git mv` 移动，历史可 `git log --follow` 追踪。

## 实现要点

- 脚本自身：`check_docs.ps1` / `check_sources.ps1`、`env_loader.*` / `generate_env_make.sh` 的仓库根推导从「上一级」改为「上两级」；`make_bootbin.ps1` 改从 `..\env\env_loader.ps1` 加载，`parts/` 与 `boot.bif` 仍按自身目录取；`test_env.ps1` 的零件路径改为 `..\boot\parts`。
- 仓库引用：`.gitignore`（`scripts/boot/parts/` 白名单、`scripts/boot/flash_log.txt`）、`.env` / `.env.example`、`ps/Makefile` 的 `ENV_HINT`、`scripts/deploy/manifest.tsv` 注释、`scripts/boot/parts/MD5SUMS.txt`、`scripts/README.md`、`README.md`、`AGENTS.md`、`docs/README.md`、`docs/log/README.md`、`docs/环境与上手.md`、`docs/开发环境与构建.md`、`docs/板端布局.md`、`pl/README.md`、`pl/soc_base/README.md`、`ps/README.md`。
- 改完跑文档检查时发现 1 条失效链接（[2026-10-08 log](2026-10-08-持久化SD与BOOT.bin打包.md) 指向旧 `scripts/bootbin/boot.bif`），一并改到新路径；其余 log 里的旧路径按「log 是当时快照」保留。
- `scripts/deploy/` 与板端文件零改动：`manifest.tsv` 条目、`out/`、板端脚本一个字节没动。
