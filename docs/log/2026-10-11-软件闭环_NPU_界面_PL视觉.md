## 6. 2h 软件浸泡（`soak.sh`，无零件，CAN 回环 + canplc 当 PLC）

70s 试跑：显示 60.00fps，worker 100%，RSS 88MB 不涨，CAN STATUS 0 丢失 / 0 重复，canplc START 应答 11.5ms。
正式 2h（14:53~16:53）：**60.02fps，432122 帧跳 13 帧**；显示平均 9.29ms / 最大 14.67ms；工作线程 99.9%；内存 88.5→99.9MB，阶梯上涨的时刻（1516 / 1819 / 2244 / 3760 / 4124s）与零件记录突发一致，最后 50 分钟持平 → 有界（界面 40 件裁切图 + 分配器），不是泄漏。画面里出现了噪声件（603 件全进复检，相机对着桌面），正好制造了 PART 帧突发。

**CAN 回环丢帧**：接口 TX 108691 / RX 107691；PLC 侧 STATUS 丢 82 帧，其中 79 帧在有 PART 突发的秒内（全程 179 秒有 PART）。与 `test_can` 的结论一致（间隔发送零丢失，背靠背连发回环会无声丢帧）→ `Runner` 除 ACK 外排队、每周期发 1 帧，且用不阻塞的 `can_try_send`（原 `can_send` 在发送队列满时会等最长 100ms，没接 PLC 时会卡工作线程）。真实总线（USB-CAN）再测。

## 7. 指令响应延迟（`desreg cmdlat / steplat`，v5）

## 9. PL v6 → v7 → v8（晚上）

| 版本 | 内容 | 结果 |
|---|---|---|
| v6 第二次 | 瘦身后的 des_vision | 第 2 阶段 5h 卡在 ~225 溢出，停掉（`phy_v6_try2.out`） |
| v7 | + ISP 白平衡两个 50 级流水线除法器换逐位除法器（`awb_seq_div`）+ des_pwm + 步进首脉冲修正 | slice 90.2% → **81.7%**，布线 **23 分钟**通过；上板：相机 60.02fps、步进首脉冲 **10.6µs**（原 1.94ms）。查出两个问题 ↓ |
| v8 | ① des_vision / des_pwm 读数据改组合逻辑；② **clk_mipi 约束挂到真实的字节时钟**（厂家约束挂在不存在的硬核 MIPI 引脚上，像素时钟域从未做时序分析） | 像素域首次被分析并满足 125MHz（fmax 127MHz）；`pl_check.sh` **19 项全过** |

**v7 的两个问题**：
1. 读 0x3xx 全部返回阈值寄存器的值、`desreg vis` 死循环 → 两个新模块的读数据打了一拍，而 fvdma_ctrl 桥接在同一时钟给地址和 RVALID、下一沿取数，读回的是上一个地址（desreg 启动时读的 0x004 → 索引 1 = 阈值）。测试平台以前等 2 拍再读，掩盖了问题；现在按桥接时序 1 拍读，旧 RTL 失败、新 RTL 通过。
2. PL 帧计数停在 1、des_vision 的帧序号也停在 1，但取帧正常 60fps → TD 日志 `No pins matched 'get_pins …u_DR1_PHY_MIPIIO.hsrx_byteclk_to_fabric'` / `defined a virtual clock: clk_mipi`：本工程是 MIPI over LVDS，字节时钟来自 `u_rx_clk_gen/U_io_clk_div_1.clkdivout`（LVDS 时钟 4 分频）。没有约束 = 像素时钟域（ISP、des_vision、帧写入）布局时不考虑时序，v5 碰巧能用；v7 换了布局后，直接对 tuser 做组合边沿检测的两处漏帧（帧写模块先 4 级同步，所以不受影响）。

**v8 实测**（`ps/tools/pl_check.sh`）：PL 帧率 60.02fps（FRAME_PERIOD 1249613）；des_vision 读回正确、统计每帧更新、模式 0~5 都生效；**像素时钟实测 111.1MHz**（CYCLES 1850388 × 60.02fps），与 IMX415 891Mbps/lane ÷ 8 = 111.4MHz 吻合；PWM 读回 1500 / 1200µs、50 次/秒；步进首脉冲约 10µs，舵机 1.1µs；取帧 60.02fps 0 跳帧。
6 种显示模式的 HDMI 截图（界面截图通道）：`img/2026-10-11-pl-modes-v8.jpg`。注意：PL 模式 ≠ 0 时 PS 拿到的也是处理后的图（同一帧缓冲），定位 / 测量 / NPU 都看到处理图，正式运行保持模式 0。

**遗留**：v8 布线后 HDMI 发送串行器（742.5MHz，`clk9`）一条寄存器间路径 −0.338ns（v7 是 +0.033ns，厂家路径、对布局敏感）→ 用 place / route effort high 重跑同一网表（`phy_v8b.out`）。⚠ 若重跑仍不满足：请用户看 HDMI 画面有没有噪点。

**HDMI 显示（v8，用户目视）**：`live` 运行时显示器一直是 fb0 控制台（两只企鹅），但 VDMA `START_1` 在两块缓冲间正常翻页 → 手写一次 `V_SIZE` 后画面切到相机 → `hdmi_out` 每次翻页都写 `V_SIZE` 提交，用户确认 **60fps 流畅、无噪点**。
v8 布线后 HDMI 串行器 742.5MHz 那条 −0.338ns 路径（place / route effort high 重跑结果完全相同）在实际板子上没有表现（无噪点），保留 v8。
