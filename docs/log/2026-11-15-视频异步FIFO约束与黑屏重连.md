# 2026-11-15 视频异步 FIFO 约束与黑屏重连

> 2026-11-16 复核：小屏「黑一下、弹 HDMI1」的主因后来查明是设备树把像素时钟设成 150 MHz（非标准 60.61 Hz），v16 上同样会闪，见 [2026-11-16 log](2026-11-16-HDMI像素时钟150MHz改标准148.5MHz.md)。本文的各版同屏对比每次只有约 10 分钟，不能说明闪屏与比特流版本有关；`set_max_delay` 约束本身是对异步 FIFO 的正确约束，保留。

## 现象

同一台 11.9 寸 HDMI 小屏、同一根线：

| 比特流 | 构建 | 现象 |
|---|---|---|
| v16（10-24） | 两段式 CLI，`timing.sdc` 的 clock group 在 phy 段丢失 | 10 分钟一次没闪 |
| 第六轮候选 `bf9826f0`（10-28 构建，10-31 上板） | 单进程，VTC ↔ NPU / 150M 声明异步 | 开机即黑多亮少，换回 v16 消失（当时根因未查） |
| v17b2（种子 3） | 同第六轮约束 | 偶尔整屏黑一下、弹「HDMI1」 |
| v17b2u（种子 3 + HDMI 串行时钟多留 0.15 ns） | 同上 | 更频繁（HDMI 实际余量 +0.155 ns，反而更糟） |
| **v17b2c**（种子 3 + 本文约束） | VTC ↔ 150M 改 `set_max_delay` | 开机后约 5 分钟目视 0 次；之后照常使用观察（结论待补） |

闪的时候板子没有重启、主程序只启动过一次（`service.log` 与开机时长核对过）。

## 排除

- **不是 HDMI 内部时序余量**：v17b2u 的串行时钟余量从 +0.023 ns 提到约 +0.155 ns，闪得反而更多。
- **不是 HDMI 时钟走线抖动**：串行时钟与它的参考时钟（视频时序模块的 148.5 MHz PLL 输出）在 v16 / v17b1 / v17b2 / v17b2u 里各段走线延时逐项相同，用的是时钟专线。
- **不是新加的振动 / 触发引脚**：W8～W11、V8 只接 J12 排针，排针上没有外接。

## 根因

画面数据由 150 MHz（`pll_150m`）读内存，经厂家 `AXI4_Stream_to_Video_Out` 的异步 FIFO 进入 148.5 MHz 像素时钟（VTC）。FIFO 读写指针用格雷码跨域，前提是指针各位到达同步器第一级（`sync_r1_reg`）的时间差小于一个周期（约 6.7 ns）。

10-28 第六轮把 VTC ↔ 150M 整组声明为 `-asynchronous`，这些路径从此完全不受约束，布局可以把指针各位拉得很长。时间差一旦超过一个周期，读侧偶尔会采到错误的指针，FIFO 读空或读乱，视频输出丢一下同步，显示器就重连。v16 编的时候这组约束没生效，跨域路径按同步检查（有违例，但布局把它们压得很紧），所以从来没出过这个问题。

这能解释两件事：换种子时好时坏（全看布局），HDMI 约束一加反而更糟（布局整体变了）。

## 修改

`timing.sdc`：VTC ↔ 150M 不再声明异步，改为双向 `set_max_delay 5.0 -datapath_only`。写法取自 TD 自带的 Soft FIFO IP（格雷码寄存器 → `sync_r1`，取两边周期较小者减去余量）。VTC ↔ NPU 仍保持异步：那一组只有 VTC 锁定信号去复位厂家 `pwm_0_1`，不进视频数据。

## 结果（`full_v17b2_s3c`，种子 3）

- 29 分钟布通，slice 85.19%，0 违例：NPU +0.101 / 75M +0.124 / 像素 +0.146 / 150M +0.102 / VTC +0.295 / HDMI 报告 +0.005（实际约 +0.155）ns，保持全正。
- `soc_prj_exception.timing` 的 MCP/SMD 汇总：150M→VTC 6 个端点、VTC→150M 5 个端点，0 违例。路径正是 `wr_to_rd_cross_inst/primary_addr_gray_reg → sync_r1_reg` 与复位，余量 3.3～4.3 ns，即走线不超过 1.7 ns。
- 上板：`pl_check.sh` 0 失败，各项与 v16 相同；`desreg` 读 VERSION 17、`des_bpi`、`des_vib`（ID 0x56494231）正常；主线回归 5 件良品全部夹住。

## 以后编比特流

- 只要设计里有跨时钟域的异步 FIFO，就不能把两个时钟整组声明为异步。要按 FIFO 的格雷码路径给 `set_max_delay -datapath_only`，否则时序报告全绿，比特流照样会偶发出错。
- 新比特流上板，除了 `pl_check.sh`，还要在同一台屏、同一根线上目视：至少 20 分钟，或照常使用 1 小时。
- 打包工具 BootGen 有时会把未初始化内存写进启动头，导致 FSBL 认为开了认证而停住。`make_bootbin.ps1` 已经加了启动头核对。
