# 2026-10-28 PL 第六轮构建收敛（单进程构建 + VTC 异步约束 + 零行为减资源，源码级）

> 2026-11-15 复核：本轮给 VTC ↔ 150M 加的 `-asynchronous` 让视频异步 FIFO 的格雷码指针失去约束，是第六轮起比特流偶发黑屏重连的根因；现已改为 `set_max_delay 5.0 -datapath_only`，见 [2026-11-15 log](2026-11-15-视频异步FIFO约束与黑屏重连.md)。本文正文保留当时结论。

目的：让默认 `opt_timing=high` 的 TD 6.2.1 全流程编译收敛。10-28 全量重编在 route 阶段 2h36m 未完成被中止（[第五轮 log](2026-10-28-PL第五轮精简.md)），本轮把失败根因从「设计余量小 / 布种波动」修正为**两段式 CLI 构建在 phy 段丢失全部 clock group + `timing.sdc` 缺 VTC 异步组**，对应修复为：构建改**单进程**（`read_design`→`bitgen`）、`timing.sdc` 追加 2 条 `set_clock_groups -asynchronous`、三路 RTL 零行为减资源。本轮**未上板**：寄存器偏移 / 位域 / 复位值、模块端口与参数、`VERSION` = 16 零变化，板端仍 v16；全流程编译结果见「验证」，数字汇总进 [测试与验证](../测试与验证.md)。

基线：HEAD `7d1453b`（第五轮源码，默认 `opt_timing=high`）。`git diff` 相对该基线：**20 个文件 +233/−151 行**（19 个 RTL + `timing.sdc`），无文件增删。

## 背景：10-28 全量重编 route 未收敛

- 两段式 CLI（`syn_1` 一段 + `phy_1` 一段，见 [soc_prj_Runs README](../../pl/soc_base/soc_prj_Runs/README.md)）：`syn_1` **9m03s**（opt_rtl 3m08s + opt_gate 5m52s）、`phy_1` 的 `opt_place` **18m29s** 正常完成；`place.qor`：slice **84.90%** / #slices 44,553 / **232 个 >100% util tile** / max congestion level 4 / 窗口 `[101 60]-[111 83]` / Setup WNS **−954ps** / TNS −17.385ns / **25 S-EP**、Hold −52ps / 12 H-EP。
- `opt_route` 从 01:05 跑到 03:41（03:43 中止）、**2h36m 未完成**：Stage 2.5.1 Phase1 1,520.2s（R&R 1,414.8s / 36 轮，overflow 42,218→0）、Stage 2.5.2 Phase2 4,796.3s（R&R 4,604.8s / 43 轮，1,667→0）、Stage 2.5.3 的 Setup 优化又制造 **1,296 个溢出**，15 轮只压到 70（单轮 80~308s）。产物只有 syn / place 数据库与报告：无 `.opt_route.end.f`、无 `soc_prj.bit`。
- 第五轮把原因判为「设计余量小（84.90% slice / 232 个 >100% tile）+ `4ff55cd` 布种变化」，属临界区非确定性；该结论**在本轮被推翻**（见「根因」），design 文档按本轮结论改写。
- 对照：同一份源码的 scratch medium 档（只把 `opt_timing` high→medium，不改仓库工程文件）**40m04s 收敛**（place 13m08s / route 25m28s），但 place slice **85.25%（44,741）比 high 还高 0.35pt**、线长 −3.95%、>100% tile **133**、窗口搬到中部横带 `[32 27]-[68 39]` → **「把 slice 压到 83.3% 以下」不是 route 收敛的必要条件**，place 拥堵形态与约束是否生效才是。

## 根因

### A. 两段式 CLI 在 phy 段丢失全部 clock group

- **机制**：`phy_1/settings.cfg` 的 `run_type phy` / `start_step opt_place` / `parent ../syn_1` 会让 TD 从 `syn_1/soc_prj_gate.db` 重新导入网表并**重放 SDC 文本**；重放时 `derive_clocks` 尚未为 PLL 引脚建立时钟对象，`timing.sdc` 里所有 `get_clocks {…u_DR1_PHY_PLL.clkc[N]}` 匹配为空 → `set_clock_groups` 的 group 是空集 → **整条命令 no-op**（TD 只报 warning、不报 error）。
- **证据**（只读复核现有日志）：
  - `phy_1/td_20261028_004604.log`（10-28 high 失败构建）：**12 条** `USR-6001 WARNING: No clocks matched`，行 **92-95 / 647-650 / 1789-1792**（`timing.sdc` 里 4 个 PLL 引脚 × 3 次重放：约束导入、布局时钟初始化、布线前重放）；`syn_1/td_20261028_003550.log` **0 条**。
  - `_fifth/after/medium/full/build.out.log`（10-28 medium 收敛构建）：同样 **12 条**。
  - `phy_1/td_20261026_074232.log`（10-26 另一次未收敛尝试：place 865.6s、route Phase1 1,773.4s、Phase2 到 Iter16 仍未清零后中止）：同样 **12 条**（行 92-95 / 647-650 / 1786-1789）。
  - → **10-26 / 10-28 两次 place/route 都是在「`timing.sdc` 的全部 clock group 均未生效」的状态下跑的**，现有 2 条 `-exclusive`（`clk_mipi` ↔ NPU / 75M / U_PLL、`clk_mipi` ↔ 150M）从未在 place/route 生效。
- **单进程验证（判据看最终 STA，不看告警数）**：候选 A 与最终构建 B 的**初始 `read_sdc` 段都是 0 条 `USR-6001`**（两段式 10-28 是初始段就 12 条——这才是根因 A 的判据）；place 的 `Stage 2.9.1 Packing` 与 route 的 `Stage 2.4.2 Update Timing` 会各重放一次 SDC，每次 8 条（候选 A 只有 place 那次 8 条＝行 7570-7577；B 共 16 条＝行 7596-7603 与 8736-8743）；重放时 `get_clocks` 求值为空只是那一次 Tcl 求值结果，**已提交的 clock group 不受影响**。同一份源码的「仅综合」run 与单进程全流程的综合段结果一致（429 S-EP / 46,643 LUT / 40,163 FF / 44,811 slice 估）。
- **历史构建方式**：v14 / v15 / v16 的构建日志不在仓库，无法确认其是否单进程（⚠）；因此它们的 route 33~47min 收敛记录**不能**用来证明「两段式流程安全」——在更低利用率 / 不同 `opt_timing` 下，约束缺失未必立刻表现为不收敛，但 10-26 / 10-28 的 84.9% 拥堵把它放大成 2h+ 的 R&R。

### B. `timing.sdc` 缺 VTC ↔ NPU / 150M 异步组

- place 后 25 个 setup 违例端点 **100% 落在 3 个跨时钟组**，且 25 条路径全是 CDC（异步复位 recovery + 异步 FIFO 格雷码同步器第一级 setup），没有一条同步数据通路；三组总计就 14 / 6 / 5 个端点，排除后不会藏起真实路径（逐条证据见 `phy_1/soc_prj_place.timing` 行 16846-16854 / 18126-18134 / 18908-18916）：

| 组 | S-EP | 检查 | WNS / TNS | 起点 → 终点性质 |
|---|---|---|---|---|
| VTC pclk 148.5M（clk4）→ NPU 150.015M（clk0） | 14 | recovery（全） | −0.679ns / −9.414ns | `AXI4S→Video Out` 的 `SYNC_INST/locked_reg` → 厂家 `pwm_0_1` 计数器异步复位脚（`.asr`） |
| 150M PLL（clk3）→ VTC（clk4） | 6 = 1 recovery + 5 setup | recovery + setup | −0.954ns / −4.455ns | 150M 域复位 / AXI4S 异步 FIFO 格雷码指针 → VTC 域异步复位脚 / 同步器第一级 `sync_r1_reg` |
| VTC（clk4）→ 150M PLL（clk3） | 5 | setup（全） | −0.733ns / −3.516ns | 读地址回送 → 同步器第一级 |
| 合计 | **25** | | | 与 `place.qor` 的 25 S-EP 一致 |

- **为什么是缺约束而不是 RTL 问题**：三组涉及的是彼此独立的 PLL（VTC 148.5MHz 自带 PLL；NPU 与 150M 各一颗 150.015MHz PLL），没有频率/相位关系；路径端点全在厂家加密 IP（`design_0_AXI4_Stream_to_Video_Out_0`、`proc_sys_reset`）与厂家 `pwm.v` 内，P&R 物理上修不了 → 被 `opt_timing=high` 的 Setup TimeOptimization 当目标反复追，是 route 阶段「越优化越溢出」的机制来源（high Phase3 制造 1,296 个溢出，medium 只有 144）。

### 为什么不再是「布种 / 机器负载波动」

- 两次 route 不收敛的日志都带同一环境性差异（12 条丢约束告警），与布局种子无关；`syn` 段 0 条告警。
- route 的 R&R 段 CPU 约 100%（单核跑满，不是被抢核），机器负载只放大 wall time；10-28 route 峰值内存约 5.5GB / 本机 15.6GB，不构成中止原因。
- 设计余量与拥堵仍是**放大因素**（232 个 >100% tile 让每轮 R&R 更贵：Phase1 单轮均值 39.3s vs medium 15.5s），但它是「放大器」不是「开关」——本轮按约束层修复，不再靠砍资源到 83.3% 以下。

## 本轮改动

### 1) 构建：改单进程（`read_design` → `bitgen`）

- **做法：以 `phy_1/settings.cfg` 为底**（它带 `run_type phy` / `parent ../syn_1` / `set arr_filter false` / `set drHoldFix on`），只把 `start_step` 由 `opt_place` 改为 `read_design`、`end_step` 保持 `bitgen`；`soc_prj.prj` 用 `phy_1` 那份（含 `<opt_timing>high</opt_timing>` 与 `<compress>on</compress>`）。这样一次进程依次跑 `read_design`→`opt_rtl`→`opt_gate`→`opt_place`→`opt_route`→`bitgen`，约束在 `read_design` 解析、后续阶段沿用。
- **两段式（`syn_1` + `phy_1`）只保留为历史件与只读实验**（如只看综合资源 / gate 估计、在现成布局库上做探针）；其 place / route 结果**不能作为时序签核与收敛证据**——约束会丢。
- 布局检查点方式随之修正：单进程跑到 `opt_place` 结束（`.opt_place.end.f` 出现、`place.qor` 刚写出）立刻读 QoR，不达标就杀进程重跑（损失约 28 分钟）；**不要**用两段式 phy 续跑检查点——那正是约束丢失的路径。

### 2) 约束：`timing.sdc` 追加 2 条异步组（+22 行，含注释）

- 追加 `set_clock_groups -asynchronous` 两条：VTC pclk ↔ NPU PLL、VTC pclk ↔ 150M PLL。用完整层次名（PLL 硬核 `u_DR1_PHY_PLL.clkc[N]`），现有 2 条 `-exclusive` 不动。
- **不加** VTC ↔ TMDS（`PLL_3` 742.9MHz）：该组 31 个端点当前 place/route 全过，且 TMDS 串行与 VTC 存在 5× 相位关系，按异步排除会屏蔽真实路径。VTC → TMDS 的 30 条 gate 估计违例仍保留在分析口径内（place 后转正）。
- 副作用 / 口径：PLL 实例名由厂家块设计决定，若将来重建 `design_0` 导致例化名变化，这两条会**静默匹配为空**（TD 只报 warning）→ 加完必须核对 build log 无 `clock not found` 类告警、且 place 后 3 个 path group 从报告里消失。
- **后备 recipe（约束层止损，未进正式流程）**：两段式 phy 阶段不能作为签核证据，但可在 phy 里 `update_timing` 之后用 Tcl 直接对完整时钟名 `set_clock_groups -asynchronous`，当场生效——build-runner 在 10-28 phy 数据库上实测 place SWNS **−0.954ns → +0.335ns、25 EP → 0**。若将来单进程方案受限，可在 phy 的 `opt_route` editable zone 重挂约束；但这会形成「place 无约束 / route 有约束」的混合口径，结果不能与单进程构建直接对比。

### 3) RTL：三路零行为减资源（19 个文件，+211/−151 行）

外部契约零变化：模块端口 / 参数 / 流水级数 / 延迟 / 复位值 / x-z 传播未动；寄存器偏移 / 位域 / 复位值、`VERSION` = 16 零变；`pl/sim`、三份工程文件、`.enc`、`design_0` 零改。

| 域 | 文件数 | diff 行 | 改法（零行为依据） | 结构估算省量 |
|---|---|---|---|---|
| 自研 `des/` | 5 | +44/−24 | `des_485` 的 RX_BUF 64×8 由触发器改 4 个 16×8 单写口 lane RAM（TD syn 日志 `syn_1/build.out.log:5870` 只提取了 `tx_buf`、没有 `rx_buf` → 原实现被综合成 512 FF）；`stepper_ctrl` 的 pos±1 / accel±1 / vmax 逼近合并为单增量器；`des_io` 编码器 ±1 合一；`des_pwm` 复用 `us+1`；`des_vision` 流水直接携带 `row−1` | **−512 FF**（确定）+ −127~−162 adder + −20~−60 LUT |

## 决策与否决项

- **不做 PWM 删实例**（删 `design_0_pwm_0_0/0_1` 两个实例——厂家 `src/pwm.v` 的 2Hz 方波当 lock 指示，改 lock 直连 LED）：只省约 40 LUT + 52 FF（≈0.12pt）、只消 14/25 EP，且要手工改块设计导出的 `design_0.v`，与 2 条 SDC 一次消 25 EP 相比不成比例；`pwm` 清零锁指示行为也不再与厂家镜像一致。
- **不加 VTC↔TMDS 异步组**（理由见「改动」2）。
- **本轮不做可见行为裁剪**（ISP 4 级色调节点旁路 ≈0.86pt、`des_vision` `LANES=2` ≈0.97pt、`wfifo` 深度减半等）：medium 在 85.25% slice 下已收敛、且约束修复把不可修路径摘出优化目标后，不需要再牺牲行为去换 1.6pt；这些只保留为后备。
- **CRC 不改**：`des_485` 的 288 adder 全部来自计数器（CRC 的 XOR 网络 0 adder），字节表改法反而每调用多 LUT（21 vs 18）；第五轮 CRC 常量特化的 +272 LUT / +512 FF 回归已作前车之鉴。
- **两段式构建只作实验**，不作为正式构建与签核流程（根因 A）。
- **`opt_timing=medium` 仍为后备候选档**（实测 40m04s 收敛），但默认 `high` 不动；本轮目标是默认 high 收敛。

## 风险

- **最终时序余量很薄**：Routed Setup WNS 仅 **+0.007ns**、Hold WNS **+0.022ns**，最差路径在 **TMDS 742.94MHz 域**（周期 1,346ps，余量约 0.5%）；STA coverage 99.60%。温度 / 批次 / 供电波动都可能吃掉这点余量。
- **未上板**：本轮未换板端 `BOOT.bin`（板端仍 v16 `71f41a20…`）、未跑 `pl_check.sh`；构建 B 的候选 `BOOT.bin`（5,179,264 B / `bf9826f0681b6892cdefe705bbb1be82`）未上板、非板端正式版本。
- **上板复核清单**：停自启服务 → 换 `BOOT.bin` → `/root/des/pl_check.sh` 回归 → NPU 参考集（`test_npu`）→ 相机 / 显示（TMDS 视觉）肉眼复核；通过后再记版号、转正，并关注 TMDS 742MHz 域余量对温度 / 批次的敏感性。
- **历史对比**：本轮 **0 setup / hold 违例**，与历史各版（NPU 域内 −0.093~−0.399ns、VTC 跨域 −4.5ns、`wfifo`→HP1 −0.132ns）形成对比——约束生效后 NPU 域内违例也消失、最终全设计 SWNS +0.007ns；但**余量很薄**，不能当作长期稳定余量。

## 结论

**目标达成：默认 `opt_timing=high` 全流程单进程 59m16s 收敛、Routed 0 个 setup / hold 违例**（Setup WNS +0.007ns、Hold +0.022ns，全部 clock 域余量为正；历史各版均有 NPU 域内 / VTC 跨域 / `wfifo`→HP1 违例）。根因 A（两段式 phy 丢 clock group）与根因 B（缺 VTC 异步组）修复后，place 的 Setup S-EP 25→0、route 各 Phase 的 R&R 全部清零；叠加 RTL 减资源后 place 拥堵 tile 首次低于基线（232→202）、slice 84.90%→83.80%、ERAM 93.21%→87.50%。**注意余量很薄**（Setup +0.007ns / Hold +0.022ns，见「风险」）；寄存器接口 / `VERSION` 16 / 板端 v16 不变，**本轮未上板**；采用前须上板复核（见「后续」「风险」）。
