# 2026-10-30 三色灯不亮：RS485 从站断线恢复

## 1. 现象

三色灯（警报灯）不亮。板上只读检查：

```
RS485 9599 baud parity N | status 0x00020006
sent 10608, ok 0, timeouts 10245, CRC errors 0, frame errors 0, listen 0
```

PL 一直在发，但模块**一个字节都没回**（`listen 0`、CRC / 帧错误 0），不是灯语或 `lamp_pattern` 的问题。

读 `TX_BUF`（0x680 / 0x684）确认请求 PDU = `01 01 00 00 00 08`（地址 1、FC 01、读 8 路线圈），与 10-27 调通时一致 → 软件侧没有变化。

## 2. 原因与恢复

用户检查为接线松动（继电器模块供电 / A-B 一线），重新插紧后恢复。

复测（服务运行中，只读）：

- 3 秒内 `sent 10608 → 10622`、`ok 363 → 377`，`timeouts` 停在 10245 不再增加；
- `status 0x00020612`：完成 + 应答正确 + 最近一帧 6 字节（读线圈应答）+ RX 空闲高；
- CRC / 帧错误仍为 0。

## 3. 注意

- 空闲 `rs485.idle = "off"`：IDLE 时灯本来就是灭的，RUN 才绿灯常亮（暂停黄、急停红、故障红 `fault_s` 秒）。要空闲也亮，把 `idle` 改成 `green` / `blink`。
- 排查顺序：先看 `desreg 485` 的 `ok` / `listen`；**0 应答 + 0 字节 = 物理层**（模块供电、A-B、J11 第 5/6 位），不是灯语代码。
- 旧的 10245 次 timeout 是断线期间的计数；需要干净统计时停服务后 `desreg 485 clr` 再跑。
