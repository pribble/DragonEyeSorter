## 排错过程（摘要）

1. 文档说的私钥不在 `~/.ssh`；全盘搜 `id_ed25519*` / `*anlu*` / 文件内容含 `BEGIN OPENSSH PRIVATE KEY`，只有 `des-deps` 那一份。
2. 该文件被 ssh 拒用（`UNPROTECTED PRIVATE KEY FILE!`）。真因不是「对本人太松」，而是它**从 `%USERPROFILE%\Anlogic` 继承了 DSH 沙箱的 `S-1-4-*` 授权条目**，被 Win32-OpenSSH 判成「他人可访问」；复制到 `%TEMP%` 会继承另一个 `S-1-4-*`，同样被拒。
3. `%USERPROFILE%\.ssh` 的 ACL 是干净的（SYSTEM / Administrators / 本人）→ 私钥复制进去（工作区外写入被沙箱挡，提权一次）即可用；`des-deps` 原文件未删，留给用户决定。
4. 同一把钥匙从 `des-deps` 读时指纹行末尾是 `no comment`、从 `~/.ssh` 读时是 `anlu-board`；指纹相同（`sSlm047y…`），是权限检查提前中止导致注释字段没读到（⚠ 推测），不是两把钥匙。

## 复现与验证

```powershell
# 1. 别名连通（BatchMode = 禁密码提示，能连上即证明是纯密钥认证）
ssh -o BatchMode=yes des "hostname; echo OK"

# 2. 生效配置（不打印私钥内容）
ssh -G des | Select-String '^(hostname|user|identityfile|identitiesonly) '

# 3. 私钥可用性与指纹（-P '' 能导出公钥 = 无 passphrase 且权限合格）
ssh-keygen -y -f "$env:USERPROFILE\.ssh\id_ed25519_anlu" -P "" | Select-Object -First 1
ssh-keygen -lf "$env:USERPROFILE\.ssh\id_ed25519_anlu"

# 4. 板端只剩一条公钥、指纹与本机一致
ssh des "ssh-keygen -lf /root/.ssh/authorized_keys"
```
