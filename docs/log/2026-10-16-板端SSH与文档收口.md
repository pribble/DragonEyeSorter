# 2026-10-16 板端 SSH 连接、authorized_keys 清理与文档单一来源收口

## 结论

- **板子连上了，靠别名不靠 `-i`**：`ssh des "..."`（`~/.ssh/config` 别名；私钥 `~/.ssh/id_ed25519_anlu`，指纹 `SHA256:sSlm047y1FbTrfLhqCozvJ8PPLo2NzTqvOm2v/GC8YM`，无 passphrase）。同一条 `Host` 行里保留旧名 `dragon-eye`，两个名字都能用。
- **"文档里那把私钥"其实一直不可用**：它在 `C:\Users\11691\Anlogic\des-deps\id_ed25519_anlu`，`ssh` 直接拒用（`UNPROTECTED PRIVATE KEY FILE! ... bad permissions`）。原因不是"对本人太松"，而是该文件**从 `C:\Users\11691\Anlogic` 继承了 DSH 沙箱的 `S-1-4-*` 授权条目**，被 Win32-OpenSSH 判成"他人可访问"。复制到 `%TEMP%` 会继承另一个 `S-1-4-*`，同样被拒；`C:\Users\11691\.ssh` 的 ACL 是干净的（SYSTEM / Administrators / 本人），所以**只有放进 `~/.ssh/` 才能用**。
- **板端 `authorized_keys` 原有两把公钥**，其中一把的私钥本机已不存在；按"只留本机私钥对应的公钥"清理，删前备份、删后用新连接验证通过（没有把自己锁在外面）。
- **`.env` 里的 `BOARD_IP` / `SSH_KEY` 此前是"假单一来源"**：含隐藏文件在内全仓库扫描，只有 `.env`、`.env.example`、生成的 `.env.make` 三处**声明**，没有任何脚本或文档**引用**；命令里全是写死的 `-i ~/.ssh/id_ed25519_anlu root@192.168.137.100`。
- **文档里有已不存在的系统描述**：`docs/环境与上手.md` §4 写的是 `/etc/init.d/S99des`（"默认注释掉自启"、启动时 `date -s` 硬编码对时），板上实际是 `S90des` 软链 → `des_service.sh` 监督进程 + `autostart.conf`。

### 一、文档说的私钥不存在


### 二、拿到路径后 ssh 拒绝加载（真因是继承来的沙箱授权条目）

```powershell
$k = "C:\Users\11691\Anlogic\des-deps\id_ed25519_anlu"
ssh-keygen -y -f $k -P '""'
# Bad permissions. Try removing permissions for user: UNKNOWN\UNKNOWN (S-1-4-830753572-318020337)
#   on file C:/Users/11691/Anlogic/des-deps/id_ed25519_anlu.
# @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
# @         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
# @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
# Permissions for 'C:\Users\11691\Anlogic\des-deps\id_ed25519_anlu' are too open.
# It is required that your private key files are NOT accessible by others.
# This private key will be ignored.    Load key "...": bad permissions
```

定位——不是"权限对本人太松"，而是**从父目录继承下来的沙箱条目**：

```powershell
(Get-Acl $k).Access | Select-Object IdentityReference,IsInherited
# S-1-4-830753572-318020337                    True   ← 罪魁（解析成 UNKNOWN\UNKNOWN）
# NT AUTHORITY\SYSTEM / BUILTIN\Administrators / SCHEMER\11691   True
(Get-Acl "C:\Users\11691\Anlogic").Access | Select-Object IdentityReference,IsInherited
# Everyone / S-1-4-830753572-318020337         False  ← 显式写在这一层，往下继承
(Get-Acl "C:\Users\11691\.ssh").Access | Select-Object IdentityReference
# SYSTEM / Administrators / SCHEMER\11691      ← 干净：没有沙箱条目
```

反证"随便换个目录复制就行"——复制到 `%TEMP%` 会继承**另一个**沙箱条目，同样被拒：

```powershell
Copy-Item $k "$env:TEMP\des_key_probe\id_ed25519_anlu"
ssh-keygen -y -f "$env:TEMP\des_key_probe\id_ed25519_anlu" -P ""
# Bad permissions ... UNKNOWN\UNKNOWN (S-1-4-919460967-657893147-1) ...
Remove-Item "$env:TEMP\des_key_probe" -Recurse -Force     # 探针副本立即删除
```
