# 2026-10-16 接板盘点：板子是什么、`/opt/bin` 用不用得上、NPU 到底跑没跑、PL 现在跑的是哪一版

> 接板后第一轮盘点，目的是给后面的部署与联调一个事实基线。全程**只读**（`ls` / `cat` / `md5sum` / `desreg r` / `desreg` 无参数 / `free` / `uptime` / `/proc`）：没停过自启服务、没写 `/root/des`、没 `insmod` / `rmmod`、没换 `BOOT.bin`。板子当时**有人同时在用**（`/root/des` 里有 `variants/`、`synth_val/`、`live.png`，`data/log` 正在写），本次不干预。
>
> 板上**没有 RTC**（时间停在 1970），板端 mtime 一律不可信，两次开机只能靠 `uptime` 区分——下文数字标「当时」（本会话早前那次开机）与「复核」（写这份 log 时这次开机），没有推算值。

## 结论

- **板子是什么**：MLK-F3P-DR1M90G（DR1M90GEG400：双核 Cortex-A35 + FPGA + 0.4T NPU），跑厂家 Buildroot 2022.02.6，内核 `6.1.111-rt42`。rootfs 是 **SD 卡第二分区**（`root=/dev/mmcblk0p2 … rw`）→ 板上的改动会留下来，eMMC 出厂系统没动。
- **厂家给的一堆 `.ko` 里只有 `mipicam.ko` 有用**：`jpu` / `soft_npu` / `hard_npu` / `cma_mem` **已经编进内核**，`/opt/bin` 里那四个是多余拷贝，唯一害处是让人以为「要先 `insmod` 才能用 NPU」；`yolo_demo_hdmi_camera`、`/opt/scripts`、`/opt/inputs`（12 MB 厂家 demo 输入）一概不用。
- **自启那份里 NPU 是关着的，但硬件是通的**：只是 `/root/des/part_cls.json` 不在（模型没导出上板），`des_app` 打一行 `npu: cannot open ./part_cls.json (parts get no NPU class)` 后照常跑，结果落成「未分类 / 复检」。手动把模型与参考集放上去跑 `test_npu`，32 个裁切与 PC 的 uint8 **32/32 一致**、NPU 中断计数从 0 涨到 5016/1320 —— **「NPU 没在用」≠「NPU 不能用」**。
- **板上跑的是 v9**：`desreg` 读到 `DES_VERSION = 9`；本次开机是从 `/mnt/mmcblk0p1`（启动分区）的 `BOOT.bin` 引导的（⚠ 推断该分区就是这套卡的引导分区），所以那份 BOOT.bin 里是 v9。`docs/PL设计.md` 等处的「v8 上板」是陈的（口径收口见「未验证」）。
- **PL 里「在动」和「从没动过」要分开说**：相机链路真在跑（60.02 fps、拍摄锁存与 `MIPICAM_IRQ` 同步、`des_vision` 统计逐帧更新）；**舵机总线、步进、PWM 从没被用过**（寄存器全 0，等实物）。
- **开机自启链是通的，而且走的是软链**：监督进程 argv 就是 `/bin/sh /etc/init.d/S90des _supervise` —— `des_service.sh` 里当时写死 `DIR=/root/des` 才没被软链带偏（该写死已在 [部署器上板验证](2026-10-16-部署器上板验证.md) 第三轮去掉）。
- **别拿仓库那份 `des_app.json` 直接覆盖板上**：板上那份的 `belt` 段是实测值（`mm_per_step 0.0207` / `dir -1`），仓库里还是估计值（`0.0098` / `dir 1`）。部署器会把它算成「需要更新」——先看 `--dry-run`，把实测值搬回仓库再传；想先试新版不碰它就用 `--dest /root/des/test`。
- ⚠ **没弄清的**：文档 v8 / 实测 v9 的口径；相机 i2c 曾连崩 5 次自杀（轮转日志里两回）；HDMI 黑屏的两个修复**无法从板上证实**；`6.1.111-rt42` 的「PREEMPT_RT 真开着」**本次没能证实**。

**PREEMPT_RT 只能证到「版本串是 RT 系列」**（⚠）：`uname` banner 是 `SMP PREEMPT`（不是 `PREEMPT RT`），`/sys/kernel/realtime` **不存在**，`/proc/config.gz` 也**不存在**（读不到 `CONFIG_PREEMPT_RT`）。`/sys/kernel/` 下有 `rcu_expedited` / `rcu_normal`（RT 补丁带出来的旋钮，⚠ 推测）。要坐实「内核真的按 PREEMPT_RT 配置编的」，得看厂家内核 `.config` 或把 `IKCONFIG_PROC` 编进去后 `zcat /proc/config.gz`。

### 四、PL v9 现读数

偏移见 `ps/src/hw/des_regs.h`。复核时的 `desreg` 状态原文（节选）：

```
VERSION 0x00000009 | FRAME_CNT 61094 | FRAME_PERIOD 1249613 ticks = 16.662 ms = 60.02 fps
SERVO frames 0, timeouts 0, rx errors 0 | CAPTURE seq 40544, start->done 15.814 ms
STEPPER pos 0, status 0x14 enabled, brake 0 steps
```

| 偏移 | 项 | 复核值（当时值） |
|---|---|---|
| `0x000` / `0x004` | `DES_ID` / `VERSION` | `0x44455301` / **9**（当时同） |
| `0x014` / `0x01C` | `FRAME_CNT` / `FRAME_PERIOD` | 61094 → 72644（相隔约 190 s）/ 1249613 ticks = 16.662 ms = 60.02 fps（当时 1249612 ticks = 16.6615 ms） |
| `0x020` / `0x02C` / `0x034` | `CAP_SEQ` / `CAP_T1` / `CAP_POS1` | 40544（同刻 `MIPICAM_IRQ` = 40543，差 1 = 读取间隔；当时 230324 且等于 IRQ）；`CAP_T1−T0` = 1,181,948 ticks = **15.759 ms**（状态行 15.814 ms）；`CAP_POS0/1` = 0 / 0 |
| `0x314` / `0x320` / `0x33C` | `des_vision` `ID` / `VIS_SEQ` / `VIS_CYCLES` | `0x56495331`；`VIS_SEQ` 61093（同刻 `FRAME_CNT` 61094）；**1850387 /帧**（当时 1852436） |
| `0x340` / `0x300` / `0x304` | `VIS_ACTIVE` / `CTRL` / `THR` | `0x04800000`（mode 0 / thr 128 / lanes 4）；`CTRL` 0、`THR` `0x00c80080`（thr 128、edge thr 200） |
| `0x308` / `0x30C` / `0x324` | `VIS_ROI_X/Y` / `VIS_AREA` | **x 519–674、y 427–628**（当时 x 1395–1910）；AREA 直读 `0x0e48` = **3656**，同一轮 `desreg vis` 打 `area 3679`（bbox x 576..688、y 431..583、质心 601.4,511.5、edges 920）——逐帧变，当时为 0 |
| `0x104` / `0x120` | `servo_bus` `STATUS` / `CNT_FRAMES` | 全 0（**从未发过**） |
| `0x204` / `0x218` / `0x220` / `0x224` | `stepper_ctrl` `STATUS` / `POS` / `STEPS` / `BRAKE` | STATUS `0x14`（enabled + at_target）、POS/STEPS 0、BRAKE 0 |
| `0x400` / `0x404` / `0x414` / `0x410` | `des_pwm` `CTRL` / `PERIOD` / `ID` / `CNT` | 周期 20000 µs、CTRL 0、ID `0x50574D31`、`CNT` `0xc918` = 51480 个周期（PWM 从未使能） |

- **像素时钟**：`CYCLES × 60.02 fps` ≈ **111.1 MHz**（当时 1852436 → 111.2 MHz），与 [测试与验证](../测试与验证.md) 记的「IMX415 891 Mbps/lane ÷ 8 = 111.4 MHz」相符。
- **ROI / AREA 两次不同**：当时 ROI 在画面右侧（x 1395–1910）、AREA 0；复核时 ROI 在左侧且 AREA 非 0 —— ROI 由正在运行的应用按跟踪动态设置（⚠ 推测，依据是 ROI 与 bbox 落在同一小块且 AREA 非 0），不是 PL 自己变的。
- ⚠ **`FRAME_CNT / uptime` 这个比值不能用来判断「PL 与 Linux 谁先起」**：当时记到 **60.09 fps**，复核两次是 `61094 / 1023.68 s = 59.68 fps`、`72644 / 1216.24 s = 59.73 fps` —— 复核的两次都**低于** 60.02（按 60.02 fps 折算，少 347 / 355 帧 ≈ 5.8 / 5.9 s 的帧数），方向与当时的记录相反，且两次复核彼此一致。**只能得出「帧计数与 `uptime` 的零点不重合（差 5~6 s 量级的帧）」**；「PL 计数器比 Linux 早约 5 s 起」这个推断本次没能成立，归因待查（⚠ 猜测与相机开始出帧的时刻有关：`dmesg` 里 `mipicam` 在 4.06 s 才加载）。

### 五、开机自启链

```
/etc/init.d/S90des  →(软链)  /root/des/des_service.sh
      └─ setsid $0 _supervise        → 监督进程：argv 实测 = /bin/sh /etc/init.d/S90des _supervise，PID 记在 /var/run/des_service.pid
            ├─ /root/des/can_up.sh can0 normal     （CAN 起接口；经典模式被拒时自动退 FD）
            └─ /root/des/des_app.sh run --can can0 → exec /root/des/des_app -c ./des_app.json run --can can0
```

| 项 | 值 |
|---|---|
| 软链 | `lrwx------ /etc/init.d/S90des -> /root/des/des_service.sh`（监督进程 argv 里就是软链名，所以 `S90des` 显示为进程名） |
| `autostart.conf`（五个变量） | `ENABLED=1`、`MODE=run`、`CAN=can0`、`CAN_MODE=normal`、`ARGS=""` |
| 监督进程 | PID 文件 `/var/run/des_service.pid`（复核时 = 255，`PPid` = 1、`State` = S）；子进程 `./des_app -c ./des_app.json run --can can0`（复核期间观察到换过 PID：271 → 854） |
| 崩溃退避 | 2 s 起、每次翻倍、上限 30 s；**5 分钟内退出 5 次就放弃**——源码如此，且轮转日志里真出现过（见下） |
| 日志 | `/root/des/data/service.log`（超 1 MB 轮转 `.1`）：复核时 `service.log` 807,572 B、`service.log.1` 1,065,277 B |
| 带 CAN 上电 | 空闲，等 PLC 或界面按 START 才动；`ARGS` 里带 `--go` 机械臂才真动（见 [环境与上手](../环境与上手.md) §4） |

### 六、部署侧现状（本日新加：`scripts/deploy/`）

- **板端脚本与仓库逐字节一致**（`.gitattributes` 给 `*.sh` 钉了 `text eol=lf`，两边原字节相同、不用去 CR；工作区里是 CRLF 的只有 `*.json`）：6 个 `.sh` 的 MD5 与仓库同；`recipes.json` / `label_list.json` 一致（后者板上带 13 个 CR，去 CR 后同，JSON 里 CR 是合法空白）；`des_app.json` **不一致**，见结论。

## 复现与验证

```bash
# 板子本体 / 内存 / 磁盘 / 时钟
ssh $BOARD_HOST 'uname -a; cat /etc/os-release; cat /proc/cmdline; free -m; df -h / /mnt/mmcblk0p1; date; cat /proc/uptime'

# /opt/bin 谁在用（四条证据一起看才成立）
ssh $BOARD_HOST 'ls -l /opt/bin; lsmod; ls -A /lib/modules; grep -c " drv_" /proc/kallsyms; grep -E "^ *2(3[0-9]) " /proc/devices; ls /sys/module | grep -Ei "npu|jpu|cma|mipicam"; dmesg | grep -i "cma_mem\|mipicam"'

# NPU 状态（只读部分：中断恒为 0 + 缺模型 + 决策列）
ssh $BOARD_HOST 'grep -iE "npu|jpu" /proc/interrupts; grep -c "cannot open ./part_cls.json" /root/des/data/service.log; ls -l /root/des/part_cls.json'

# PL 现读数（des_app 跑着时只用 r 与无参数状态，别的都是写操作）
ssh $BOARD_HOST 'for o in 0x314 0x320 0x324 0x33C 0x340 0x308 0x30C 0x104 0x120 0x204 0x400 0x414 0x500 0x800; do printf "%-7s " $o; /root/bin/desreg r $o; done; /root/bin/desreg vis; /root/bin/desreg; grep -i mipicam /proc/interrupts; cat /proc/uptime'

# 开机自启链（argv 里能看到软链名）
ssh $BOARD_HOST 'ls -l /etc/init.d/S90des; cat /root/des/autostart.conf; cat /var/run/des_service.pid; tr "\0" " " < /proc/$(cat /var/run/des_service.pid)/cmdline; echo; ps | grep des_app'
```

## 未验证 / 遗留
