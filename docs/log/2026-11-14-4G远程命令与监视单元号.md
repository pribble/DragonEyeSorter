## 2. 为什么这样验权

MQTT 服务器是公共的、没有 TLS，主题前缀也可能被人看到。所以命令必须自带凭证：`sig` = HMAC-SHA256(密钥, `"<nonce>|<seq>|<cmd>|<arg>"`)。
`seq` 递增挡住运行期间的重放，`nonce`（每次启动随机）挡住重启后的重放。默认白名单只有确认工单、停止、暂停——远程不能让线体动起来，启动必须在现场。

## 3. 验证

- 主机（WSL，g++ 11，`-Wall -Wextra` 无警告）：`test_uplink` **172 passed, 0 failed**（原 132 项 + SHA / HMAC 向量、Modbus 主站、命令各种拒绝与执行、旧版映射）；`test_modbus` **44 passed, 0 failed**（+ 监视单元号 6 项）。
  命令测试的对端是仓库里真实的 `ModbusTcp` 从站代码加一个模仿 `Runner::handle_modbus` 的线程。
- 三处签名实现互相对上：C++ 过 RFC 4231 用例 2 / 6；网页里的实现用 Node 对照系统库 22 项全过；Python 用标准库 `hmac`。
- `pc/uplink/test_fake_board.py` **40 passed**。
- 电脑浏览器 + 公共 MQTT 服务器 + `fake_board.py --key`：错密钥 →「被拒绝：密钥不对」；正确密钥下「暂停」「继续」「确认全部工单」都得到「已执行」，看板上线体状态和工单状态随之变化。
- 交叉编译：`des_app`、`des_4g`、`test_uplink`、`test_modbus` 通过。

全部不是板上实测。`des_app` 改动后的二进制没有上过板。

## 4. 上板时要看的

1. 换上本分支的 `des_app` 后，`des_4g` 跑着的时候 HDMI 右栏应显示「Modbus 未连」，且不出现「PLC 通信中断」工单；停掉 `des_4g` 后也不出现。
2. 用 PC 的 `mb_client.py`（单元号 1）读写：仍然显示「Modbus 在线」——PLC 的行为不变。
3. 手机看板发「确认全部工单」「暂停」，HDMI 上看到相应变化；发「启动」（不在白名单）被拒绝。
