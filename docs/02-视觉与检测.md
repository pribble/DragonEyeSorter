# 02 · 视觉与检测

> 检测对象、类别表、数据集与模型上板路线。相关实测见 `log/`。

## 检测对象（✅ 2026-10-04 定版）

**POM 齿轮 + 齿条**（纯塑胶注塑件）。场景：塑胶传动件注塑后在线质检分拣。两种零件同场景、同工艺、同一套缺陷体系。

选材准则：

1. 宽度在夹爪张口内、有夹持高度（≥8mm）、平放稳定；
2. 在赛题举例范围内（塑胶零部件）；
3. 缺陷**冷加工**即可人工可控制造、可复现、可批量（不焊接、不加热 POM）；
4. 有标准几何尺寸，尺寸测量有意义。

（原"电子模块板 + 塑胶件 + 铝片、吸盘吸取、拨叉剔除"方案已作废。）

## 缺陷制造（冷加工，可复现）

| 缺陷 | 做法 |
|---|---|
| 缺料 | 锉齿顶 / 剪整齿 |
| 飞边 | 同色 AB 补土卡进齿槽 |

缺陷要在相机分辨率下看得见：视野 300mm 宽 / 1920px ≈ 0.16mm/px；需要时降低相机高度把视野收到约 200mm（≈0.1mm/px）。

## 数据集

- 每类 ≥250 张、共 ≥2000 张；覆盖不同位置、朝向、进入方向、亮度扰动。train/val = 9:1。
- **独立测试集按实物样本划分**：每类 2~3 个从未参与训练的实物样本。
- 必须在**最终光学条件**下采（两侧条形光、最终相机高度），否则要重采。
- 草案（待确认）：采集时每次只放一类，PS 用轮廓自动生成框，标注退化为"按类别分文件夹"；物料贴死时自动框出错就丢弃该帧。

## 视觉定位与角度

- 夹爪随机姿态抓取需要角度 θ。YOLO 框无角度 → 由二值 blob 的二阶矩 `θ = ½·atan2(2μ11, μ20−μ02)` 或 PS 端 OpenCV `minAreaRect` 求；近方形物料按 minAreaRect 取窄边方向夹。
- 两件贴死时连通域会连成一个 blob → 用 YOLO 框切分，或判"粘连"不抓、流到带尾复检。
- 草案（待确认）：主线先在 PS 上做（降采样灰度图阈值 + 轮廓 → `minAreaRect` 得 x, y, θ, 宽, 高），PL 图像链降为 P1/P2。
  → ✅ 已实现：`ps/app/locate`（1/4 降采样，板上 6.8ms/帧），见 [ps/README](../ps/README.md)。

## 相机标定（像素 → 台面毫米）

`des_app calib-cam`（`ps/app/calib`）：一张平放在皮带上的棋盘格 → 皮带平面的单应矩阵，写进 `calib.json`，`load_config` 读完 `des_app.json` 后自动合并。

**台面坐标系**：x 沿皮带前进方向；y 是从上往下看 x 逆时针转 90°（右手系，z 朝上，机械臂 IK 依赖这一点，不能镜像）；
**原点**：x = 0 在视野上游边缘（画面中线处），y = 0 在画面中线。抓取线、带尾位置都用尺子从视野上游边缘量。

**操作**：
1. 标定板**平放在皮带上，一条边贴着侧挡边**（板的一条轴 = 皮带方向）；整块板都在画面里，最好占画面一半以上。
2. **卡尺量一格的边长**（打印件会缩放，不要信名义值）。
3. `/root/des/des_app.sh calib-cam --board <列>x<行> --square <mm> --travel right --dump /root/des/calib.png`
   - `--board` 是**内角点**数（黑白格交点），不是格子数：10×7 个格子 → `9x6`；
   - `--travel` 是皮带在画面里往哪边走（right / left / down / up）。
4. 看输出的残差（rms / max）和 `calib.png`：红色 x 箭头应指向皮带前进方向，网格每格 50mm。

**限制**：单应只描述**皮带平面**。零件顶面比带面高（齿轮约 10mm）→ 有视差，`齿轮齿条_测量功能与数据.md` 里的视差校正 / 镜头畸变校正属于测量功能（P1），不在这一步。

**合成图测试**（`ps/tests/test_calib.cpp`，已知真值的透视渲染 + 模糊 + 噪声，5 种姿态：倾斜、倒放、旋转 90°、皮带朝下 / 朝左）：42 项全过，残差 rms 0.003~0.04mm，任意两点测距误差 ≤0.043mm（0.2mm/px 那组最大，其余 ≤0.015mm）。

**检测速度与超时**：先用经典角点检测（约 0.12s），不行再用半分辨率 sector 检测，再不行才全分辨率穷举（约 12s，要加 `--exhaustive`）。
⚠ **`--board` 填错（不是内角点数）时，OpenCV 经典检测器会搜索好几分钟** → `calib-cam` 把检测放在子进程里，默认 20s（`--exhaustive` 时 120s）没结果就杀掉并提示检查内角点数。

### 传送带标定（mm / 步 + 方向，`des_app calib-belt`，10-11 写好，⬜ 待实物）

相机标定之后做。**一个零件**放在皮带上、画面上游边缘附近（整件在画面里）→ `/root/des/des_app.sh calib-belt`：
1. 短走约 8mm（按配置里的估计值 0.0098mm/步 = 主动辊 Ø10 × π / 3200）→ 粗比例 + 方向（配置的 `dir` 猜错也没关系）；
2. 长走到画面约 75% 处 → 用整段位移 / 总步数算 mm/步（位置取 7 帧静止中位数，噪声 ~0.05mm，相对 ~90mm 行程 < 0.1%）；
3. 退回起点 → **往返误差**（打滑 / 回差，测试报告「传送带定位误差」的一个数）；另报横向漂移（mm / 100mm，> 2 说明相机 x 轴没沿皮带或跑偏）和等效辊径（核对 Ø10）。

结果写进 `calib.json` 的 `belt` 段（`load_config` 合并，覆盖 `des_app.json`）；重新跑 `calib-cam` 时保留 `belt` 段。选项：`--belt <mm/s>`（默认 20）、`--steps <长走步数>`、`--out`。两段比例差 > 25% 或零件没动会报错不写。`test_calib` 里有对应的纯计算检查（正向 / 反接 / 打滑 / 不动、文件合并）。

## 几何测量（P1，`ps/app/measure`，2026-10-11 合成图验证）

管「尺寸超差 / 规格混料」这两类 NPU 不判的 NG，也给缺齿 / 缺料 / 飞边一个与 NPU 无关的第二意见。每件只在**一帧**里测（见下面视差），A35 单核 **4~5ms / 件**。

**流程**：ROI 二值化（Otsu 只用来找轮廓）→ 外轮廓 + 最大内孔 → 沿每个轮廓点的法线找灰度穿过 **50% 电平**（皮带、零件两类灰度中位数的中点）的亚像素位置 → 单应映射到台面 mm → 视差校正 → 拟合。

| | 输出 | 方法 |
|---|---|---|
| 齿轮 | 外径（齿顶圆）、根径、孔径、偏心（孔心 − 齿顶圆心）、**规格齿数**、缺料齿 / 缺齿 / 飞边齿槽数、r(θ) 曲线（720 点，UI 画图用） | r(θ) 过半高的段 = 齿；**规格齿数由齿距中位数算**（30 齿缺 2 个和 28 齿都只看到 28 个齿，但 28 齿的齿距是均匀的 12.86°）；齿顶圆只用法线接近径向的点拟合（模糊会把窄齿顶的两角磨圆，混进来外径偏小 0.05mm） |
| 齿条 | 长度、高度、平均齿距（齿中心对齿位号线性回归）、齿位数、缺料 / 缺齿 / 飞边 | 最小外接矩形定方向；长度 / 高度取端面 / 齿背 / 齿顶平台各自点的**中位数**（取极值会被噪声往外推 0.015mm）；两端被锯断的半个齿不算 |

**飞边三种样子都要判**：① 齿槽底被填高（槽底比中位槽底高 > `flash_mm`）；② 填到半高以上、两齿连成一段（宽度 = (n−1) 个齿距 + 1 个齿宽 → 多出的齿数 = 飞边）；③ 齿槽中间立着一小块（看着像多一个齿）→ 按**齿相位**判：齿只在齿距网格上，偏离网格 ¼ 齿距以上的段是槽里的料。

**视差**（`camera_h_mm` 填实测相机高度后启用；8mm 镜头 H≈360mm，齿轮厚 10mm → 顶面放大 k = 360/350 = 1.029）：
- 侧壁亮（默认，`walls_visible = true`）：亮区 = 从底面（×1）到顶面（×k）所有截面的并集。远离光轴一侧的边是顶面边（缩回 1/k），朝向光轴一侧的是底面边（不动）；沿光轴射线方向的边是竖棱的投影，两边都不算，直接丢掉。
- **拖影限制**：每条边沿「离开光轴」方向被拖长 smear = (k−1)·|中心 − 光轴|。拖影顺着齿排方向时会把齿槽填平：中心离光轴 112mm 时拖 3.2mm ≈ 1 个齿距，两侧齿槽全看不见。→ smear > `max_smear_mm`（0.8mm，m=1 齿根槽宽约 1mm）时**外径 / 孔径照常给（已校正），齿的判定不做**（`teeth_judged = false`）。H=360、厚 10 时，对应零件中心离光轴 ≤ 28mm。
  - 跟踪里每件**选离光轴最近的那一帧测**（60fps、100mm/s 时每帧走 1.7mm，沿带方向总能到光轴附近）；横向偏移只能靠摆放，或带上加导向条把件往中线赶。还超的 → 复检。
- 侧壁暗（只有顶面亮，`walls_visible = false`）：整件按 1/k 缩回，没有拖影限制。⚠ 打光定了以后看实拍图决定用哪种。

**合成图测试**（`ps/tests/test_measure.cpp`：8 倍超采样多边形 → 抗锯齿 → 模糊 σ0.7 → 噪声 σ2，0.15mm/px；视差场景按 64 层截面渲染）：**39 项全过**。
- 尺寸误差（扣掉渲染器自身已知的 +0.019mm 后）：外径 ≤0.003mm、根径 0.004、孔径 0.008、齿条长度 / 高度 ≤0.006、齿距 ≤0.001mm、偏心 0.001mm，拟合残差 0.005mm；
- 30 齿 / 28 齿区分正确；缺料 1、缺齿 1、三种飞边各 1 都判对，良品零误报；
- 视差：不校正外径偏大 0.94mm（离光轴 22mm），校正后 0.003mm；离光轴 112mm 时外径仍准（0.007mm），齿判定按设计自动关闭；侧壁暗模式 112mm 处也全对。
- ⚠ 合成图上的精度 ≠ 实测精度：实拍还有镜头畸变（P1）、标定误差、零件边缘倒角 / 毛刺、光照不均。**实测精度用卡尺量过的良品件标**（`齿轮齿条采购清单.xlsx` 样本登记表的真值），报告里分开写。

**卷帘快门**：传感器逐行曝光，整帧读出约 16ms，皮带在此期间走了 b1−b0（PL 锁存的帧首 / 帧尾带位置）。每个边缘点按所在行退回到帧中间那一刻（`belt_mm_per_row`，与定位的行时间补偿同一口径）。夸大到每行 0.005mm（齿轮上下错开 1mm）时：不补偿拟合残差 0.19mm，补偿后 0.005mm、外径 / 圆心都回到真值。

**接入 `des_app`（✅ 10-11）**：`app/track_measure`（`TrackMeasurer`）在核 1 工作线程里、跟踪表更新之后运行：
- 每帧最多测 `per_frame`（默认 1）件，**没测过的优先**，之后只有「离光轴距离 < 0.75 × 上次 − 1mm」才重测 → 每件最后留下的是离光轴最近那一帧的结果（视差拖影最小、畸变最小）；
- 只测整个外框（+3mm）都在画面里的件；齿轮 / 齿条按跟踪表融合的宽长比分（> 0.6 = 齿轮）；ROI 直接从相机缓冲转灰度，测完若该缓冲已被 DMA 复用就丢弃结果；
- 结果存进跟踪表 `Track::meas`（`PartMeasure`），画面标签显示 `OD32.02 z30` / `L50.01 p3.142`（带 `?` = 视差过大、齿未判），CAN 每件结果的 `size_mm` 改为测量值（0 = 没测到）；
- **判定**（`tracker` 的 `SizeRule`，`des_app.json` 的 `measure.rule`，默认关）：只改判「按类别要抓取」的件（不把 NPU 的 NG 改成 OK）——规格齿数不符（28 齿）/ 外径超差（32±0.15）/ 孔径超差 / 偏心 > 0.3 / 齿条长度超差（50±0.5）→ 翻板 `scrap`；NPU 判 OK 但测到缺齿 / 缺料 / 飞边（且齿已判）→ 复检。公差取自 `齿轮齿条_测量功能与数据.md` 的配方示例。
- 实测（板上，无零件）：live 60.02fps、工作线程处理 99.8% 的帧，与接入前相同；单测 `test_scheduler` 128 项（新增 10 种判定情形）、`test_measure` 52 项（新增卷帘快门、TrackMeasurer 端到端：整帧 → 跟踪表 → ROI → 齿轮 / 齿条 → 结果写回、靠近光轴后重测）全过。

**待实测（⚠）**：相机高度 H、齿轮 / 齿条实际厚度（卡尺）、侧壁亮不亮、实拍边缘的灰度过渡宽度、实拍精度（卡尺真值对比）；之后再开 `measure.rule.enabled`。

## 模型与量化路线

官方两个 ONNX 已逆向：量化格式为 **QDQ / UINT8 / per-tensor**，`fire_detect` 的 producer 是 ORT `quantize_static` 的签名，结构是标准 ultralytics YOLOv8n（Detect 前截断）。详见 [log/2026-09-20](log/2026-09-20-NPU与硬件实测.md)。

**✅ 2026-10-11 改定：PS 定位 + 每件 ROI 裁切 → NPU 分类（YOLOv8n-cls @ 224，激活换 ReLU）**（模型训练由 Claude 负责，用户同意）。
- 原因：用户给出镜头 = 相机自带 **4.2mm**（H72° V56°）。IMX415 读出是全幅 2×2 合并（`WINMODE=0`、`HADD/VADD=1`），1080p 保留全视场，每像素 ≈ H × 0.00069mm（H = 镜头到带面）。H≈300mm 时 0.21mm/像素、视场约 400×224mm。整帧缩到 416 后约 0.95mm/像素，1mm 的黑点 / 缺料只剩约 1 像素；按零件裁 56mm→224px 后约 4 像素。
- 做法：`roi_crop`（零件中心、转正到零件轴向）→ NPU 分 8 类 → 每件在视野里分类 3~6 次（每次测量尝试一张，越靠近光轴越频繁），概率软投票（`Tracker::vote`），置信度 = 胜出类的平均概率。定位、多件跟踪仍是 OpenCV（已在 60fps 主循环里）。
- 标注：采集时一次只放一类（`des_app collect --cls`），裁切图直接按类别存文件夹，不用画框（总计划 §3-②）。
- 工具链：`train/`（合成数据冒烟 → 训练 → 导出去 Softmax → ORT QDQ/UINT8/per-tensor 量化 → 板上 `test_npu` 核对 + 测耗时）。整帧检测（YOLOv8n@416）留作备选：采集时 `--full N` 同时存整帧 + 自动框。

- 板上实测（合成数据冒烟，`cec5e2f` 之后）：NPU 7.8ms / 件，加载 0.1~0.15s；**ReLU 版 NPU 准确率 96.25% ≈ PC uint8 96.46%**，SiLU 版 NPU 只有 94.0%（NPU 近似 SiLU）→ 定 ReLU。量化后必须 `infer_shapes`，否则板上 ArmNN 解析器段错误。

原选型（保留作对照）：YOLOv8n @ 416×416（实测 NPU 纯推理约 26ms 量级）。

```
ultralytics 训 YOLOv8n(nc=8)
  → export ONNX，opset=13
  → onnx.utils.extract_model 截断到 6 个 cv2/cv3 conv 输出（Detect 后处理不导出）
  → onnxruntime.quantization.quantize_static(
        quant_format=QDQ, activation_type=QUInt8, weight_type=QUInt8,
        per_channel=False, 校准集 100~300 张)
  → JSON 的 className 换成 8 类
  → yolo_demo_hdmi_camera -m ours.onnx -u ours.json --yolov8 true
```

备选（帧率不够时）：走 `yolo_face` 的极简路线（416、13 层 Conv、纯 Relu、双头 anchor 版）；最保守兜底：照 `fire_detect` 原结构训，只改输出通道数。

- ⚠ C2f 中 Split 落 CpuAcc 的开销对 416 模型的实际影响。
