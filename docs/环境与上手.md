## 2. 配置 `.env`

脚本与 Makefile 里的本机路径各人不同、换台电脑要手改，故统一由 `.env` 管理：

- [.env.example](../.env.example)（✅）：模板，列全部配置项；`.env`（❌）：本机实际路径；`.env.make`（❌）：由 `.env` 生成，供 `ps/Makefile` include。
- [scripts/env_loader.ps1](../scripts/env_loader.ps1) / [.sh](../scripts/env_loader.sh)：手动加载进当前会话并报告路径是否存在；[scripts/generate_env_make.sh](../scripts/generate_env_make.sh)：生成 `.env.make`；[scripts/test_env.ps1](../scripts/test_env.ps1)：逐项检查关键路径。

**自动加载 `.env` 的入口**（不必手动 source）：[scripts/bootbin/make_bootbin.ps1](../scripts/bootbin/make_bootbin.ps1)、`ps/Makefile`（`-include ../.env.make`）。

### 怎么配

```powershell
cd <仓库根目录>
copy .env.example .env                  # 从模板复制；变量清单见 .env.example
bash scripts/generate_env_make.sh       # 生成 ps/Makefile 用的 .env.make
.\scripts\test_env.ps1                  # 自检：逐项检查关键路径是否成立
```

| 变量 | 指向什么 |
|---|---|
| `FD_ROOT` | FD 安装目录（含 `toolchain/gcc/aarch64_linux/`） |
| `TD_ROOT` | TD 安装目录（含 `license/`、`bin/`） |
| `ARMNN_LIB` / `OPENCV_LIB` | ArmNN / OpenCV 库目录（各含 `include/`、`lib/`；与板端 `/opt` 同构，`libfmt.a` 在 ArmNN 里） |
| `FREETYPE_INC` / `BOARD_LIBS` | FreeType 头文件目录 / 板上库的本地拷贝（链接期用，不上板） |
| `NPU_DEMO`（可选） | 厂家 NPU demo 解压目录；只在取两个库 / 重建 `parts/` 零件 / 复刻 SD 启动分区时要 |
| `BOARD_HOST` | `ssh` / `scp` 目标：`~/.ssh/config` 别名（推荐）或 `root@<板子IP>` |
| `BOARD_IP` | 板子原始 IP：`ping`、`ssh-keygen -R`、写 `~/.ssh/config`、板端 dhcpcd 用 |
| `SSH_KEY` | PC 端私钥路径；未配别名时配合 `-i` 使用 |

第三方库**一个库一个变量、各自一个根**，与板上 `/opt` 下的布局同构（见 §3）。**§4 起的板端命令都按「变量已加载」来写**：先 `. .\scripts\env_loader.ps1`（PowerShell）或 `source scripts/env_loader.sh`，`$BOARD_HOST` / `$BOARD_IP` / `$SSH_KEY` 才有值。

### 手动加载与覆盖

```powershell
. .\scripts\env_loader.ps1              # PowerShell：加载后 $env:FD_ROOT 等可用
```
```bash
source scripts/env_loader.sh            # Bash / WSL
make -C ps CROSS=<工具链前缀> ARMNN_LIB=<armnn_lib 目录> OPENCV_LIB=<ffmpeg_opencv4.7.0_aarch64 目录>   # 命令行覆盖（Makefile 自动 include .env.make）
```

**优先级**：命令行参数 > Shell 环境变量 > `.env` > 无默认值；都没给时 `ps/Makefile` 与 `scripts/` 下的脚本直接报错并提示怎么配。路径格式：`FD_ROOT=<盘符>:/目录/FD`（正 / 反斜杠都行）、`DES_WORK_DIR=$HOME/des-work`（用 `$HOME` 跨用户兼容）。Shell 加载器（env_loader.sh）只展开 shell 里已有的 `$NAME` / `${NAME}`（`$HOME` 靠它生效），`$()`、反引号与未知名一律原样保留、不执行任何替换；PowerShell 加载器（env_loader.ps1）按 PowerShell 字符串语义展开——`.env` 值里不要写 PowerShell 语法（`$()` 会被当子表达式执行）。

### 常见问题

| 现象 | 处理 |
|---|---|
| 提示"找不到 .env 文件" | `cp .env.example .env` 后填路径 |
| 路径存在却提示"路径不存在" | 查路径格式：多余空格、Windows 路径用 `/` |
| `make -C ps` 报 `FD_ROOT 未设置` / `ARMNN_LIB 未设置或目录不存在` | Makefile 不留默认值：填好 `.env` 后必须重新 `bash scripts/generate_env_make.sh` 生成 `.env.make` |
| 换一台电脑 | 克隆 → `cp .env.example .env` → 填路径 → `.\scripts\test_env.ps1` → `bash scripts/generate_env_make.sh`；`.env.make` 是生成物，换机后必须重生 |

路径只写在**不入库**的 `.env` 里，不直接改脚本 / Makefile（diff 大、易与队友冲突、换机要重改；规则见 [文档索引](README.md) 写作约定「不写主机路径」）。新增配置项时同步更新 `.env.example`。

## 3. 获取依赖文件

ArmNN / OpenCV 两个库、FreeType 头文件、板上库文件**自行获取、不入库**，对应 `.env` 的 `ARMNN_LIB` / `OPENCV_LIB` / `FREETYPE_INC` / `BOARD_LIBS`。

厂家 NPU demo 包（https://uisrc.com/t-5868.html）提供前两个库：取 `demo/sdk/face_detection/libs/` 下的 `armnn_lib/` 与 `ffmpeg_opencv4.7.0_aarch64/`（各自一个目录，`.env` 指到目录本身）。Windows 解压会丢失 `.so` 软链接，先跑修复脚本：

```bash
sh scripts/sdk_fix_sonames.sh "$ARMNN_LIB"  "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"
sh scripts/sdk_fix_sonames.sh "$OPENCV_LIB" "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"
```

FreeType 头文件：从板上拷（推荐，需先做完 §4）`scp -r $BOARD_HOST:/usr/include/freetype2 "$FREETYPE_INC"`；或用官网源码包 freetype-2.10.1，`FREETYPE_INC` 指向 `include/`。

板上库文件 → `$BOARD_LIBS`，两套名字都要有（SONAME 名供链接器解析 `libfreetype` 的依赖，链接名供 `-l`）：

```bash
mkdir -p "$BOARD_LIBS"
scp $BOARD_HOST:/usr/lib/{libfreetype.so.6,libpng16.so.16,libz.so.1} "$BOARD_LIBS/"
sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" \
    "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf.exe"   # 按 SONAME 补出链接名
```

`-lfmt` 命中 `$ARMNN_LIB/lib/libfmt.a`（静态），不用从板上拷。缺哪套名字报什么错见 §6；改内核 / U-Boot / 内核驱动 / 加系统软件包时才要米联客 Linux 开发包。

## 4. 板子一次性配置

### 启动与拨码

- **拨码开关**（SW1，3 位）：**ON-OFF-OFF** = 从 SD 卡启动（日常）；OFF-OFF-OFF = 从 eMMC 启动（出厂系统，救生艇，保持原样）。
- **SD 卡**：厂家预装系统的卡，或自制的持久化镜像（见 [开发环境与构建](开发环境与构建.md)「SD 卡布局与烧卡」）。
- **PS 网口**（RJ45，靠 USB 那个）：另一端接电脑有线网口或同一路由器；PL 网口需比特流里有网卡逻辑，当前工程不支持。
- **串口**（可选，调试与首次配置用）：USB-TTL 3.3V 接 J10 —— 1 = GND、2 = 板子 RX、3 = 板子 TX；115200 8N1，无流控。
- **首次登录**：串口登录 Buildroot 的 `root`（密码默认为空，或见板卡手册）；板子默认由 DHCP 取 IP。

### 板端网络

板子 `eth0` 由 dhcpcd 管理，固定 IP（= `.env` 的 `BOARD_IP`）追加在 `/etc/dhcpcd.conf` 末尾（原文件先备份为 `.orig`）：

```bash
cp /etc/dhcpcd.conf /etc/dhcpcd.conf.orig
cat >> /etc/dhcpcd.conf << 'EOF'

# DragonEyeSorter 固定 IP 配置
interface eth0
static ip_address=192.168.137.100/24
static routers=192.168.137.1
EOF
reboot      # 重启后板子固定为 192.168.137.100
```

PC 侧有线网卡设 `192.168.137.1`、掩码 `255.255.255.0`（`.env` 的 `BOARD_IP` 与 `static ip_address` 是同一个值）；用 Windows「Internet 连接共享」时该网卡也会被自动改成这个地址。

### 免密 SSH

**先要有密钥**（每台电脑自己的环境，仓库里没有）：没有就 `ssh-keygen -t ed25519 -f "$SSH_KEY" -C "<标签>"`，已有别的密钥就把 `.env` 的 `SSH_KEY` 指向它。公钥追加到板端 `/root/.ssh/authorized_keys`：

```bash
ssh-copy-id -i "$SSH_KEY.pub" root@$BOARD_IP     # PowerShell 没有它：用 Git Bash / WSL，或串口登录后手动
# 板端手动追加：mkdir -p /root/.ssh && cat "$SSH_KEY.pub" >> /root/.ssh/authorized_keys
#             chmod 700 /root/.ssh && chmod 600 /root/.ssh/authorized_keys
```

**配别名（推荐）**：在 PC 的 `~/.ssh/config` 写一段，把 IP、用户、私钥都收进去，之后 `ssh` / `scp` 只写别名。`Host` 名必须与 `.env` 的 `BOARD_HOST` 一致；`HostName` / `IdentityFile` 同 `.env` 的 `BOARD_IP` / `SSH_KEY`（以别名 `des` 为例）：

```
Host des
    HostName 192.168.137.100
    User root
    IdentityFile ~/.ssh/<密钥文件名>
    IdentitiesOnly yes
```

`IdentitiesOnly yes` 只用这一把密钥；**不配别名**时把 `BOARD_HOST` 填成 `root@<板子IP>` 并补 `-i "$SSH_KEY"`；非交互会话加 `StrictHostKeyChecking accept-new`。

### 板上目录与时间

板端目录 `/root/des`（主程序 / 模型 / 运行数据）与 `/root/bin`（工具脚本）由部署器与 `scp` 建好，布局见 [板端布局](板端布局.md)。

**无 RTC**：每次开机时间从 1970-01-01 起算，需手动设置或对时（板端 `ls -l` 时间戳也因此不可信）：`date -s "2026-10-15 14:30:00"` 或 `ntpdate pool.ntp.org`；PC 端可 `$ts = Get-Date -Format "yyyy-MM-dd HH:mm:ss"; ssh $BOARD_HOST "date -s '$ts'"`。

### 启动脚本

开机自启**已装好**：`/etc/init.d/S90des` 是指向 `/root/des/des_service.sh` 的软链接（BusyBox init 按 `S??` 顺序执行 `start`），脚本源在 `scripts/deploy/out/des_service.sh`。

```bash
ls -l /etc/init.d/S90des            # -> /root/des/des_service.sh
/root/des/des_service.sh status     # 在不在跑 + 最近几条服务事件
```

它是监督进程：拉起 `des_app`，崩了 2 秒后重启、退避到 30 秒；5 分钟内退出 5 次就放弃。事件写 `/root/des/data/service.log`（超 1 MB 轮转 `.1`），PID 记在 `des_service.pid`。板端路径全部取自同目录的 `des.env`（唯一有路径的文件，见 [scripts/deploy/out/des.env](../scripts/deploy/out/des.env)），整目录拷到别处部署也照常工作；改 / 换它要 `deploy.ps1 -WithService`。

行为由 `/root/des/autostart.conf` 决定（首次运行自动生成，改完 `restart` 生效）：

| 变量 | 作用 | 板上当前 |
|---|---|---|
| `ENABLED` | `0` = 开机不启动（只改这个文件，不动 `/etc`） | `1` |
| `MODE` | `run`（生产）/ `live`（不带传送带、机械臂、CAN） | `run` |
| `CAN` | 有值时先跑 `can_up.sh <CAN> <CAN_MODE>` 再给 `des_app` 传 `--can <CAN>`；留空直接进 RUN | `can0` |
| `CAN_MODE` | `normal` = 总线上要有伙伴（PC 的 USB-CAN 当 PLC）应答；`loopback` = 无总线自测 | `normal` |
| `ARGS` | 追加给 `des_app` 的参数，如 `--go`（机械臂真动）、`--belt 60` | 空 |

带 CAN 启动时 `des_app` 先停在**空闲**，等 PLC（或界面按钮）发 START 才动作；机械臂只在 `ARGS` 带 `--go` 时才真动——自启默认不碰硬件。右列为当前板上值，以 `autostart.conf` 为准。

人工跑 `des_app.sh`、`des_tool.sh` 或 `desreg` 写命令前先停服务（相机 DMA、舵机总线、步进都只有一个主人），用完恢复；命令见 [开发环境与构建](开发环境与构建.md)「部署与运行」。`pl_check.sh` / `soak.sh` 自动暂停与恢复。

**板端限制**：BusyBox 没有 `timeout`、`pkill`，限时运行用后台 + `sleep` 自己实现。

## 5. 从零跑起来

1. **PL**：TD 打开 `pl/soc_base/soc_prj.al`，综合 → 布局布线 → 生成比特流，再 `scripts/bootbin/make_bootbin.ps1 -Bit <比特流>` 打包 `BOOT.bin`。
2. **PS**：先加载 `.env`（`. .\scripts\env_loader.ps1` 或 `source scripts/env_loader.sh`），`make -C ps all`。
3. **上板**：`.\scripts\deploy\deploy.ps1 -WithService`（让它自己停 / 起自启服务）。
4. **确认**：`ssh $BOARD_HOST /root/des/des_service.sh status`；上电即由自启服务拉起 `des_app run`。

构建 / 打包 / 部署、换 `BOOT.bin` 与运行命令、SD 卡与烧卡见 [开发环境与构建](开发环境与构建.md)「PL：构建与打包」「部署与运行」「SD 卡布局与烧卡」；训练模型（可选）见 [train/README](../train/README.md)。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 编 `des_app` 报 `cannot find -lfreetype` | `$BOARD_LIBS` 缺**链接名** `libfreetype.so`（`-l` 只认无版本号的名字）：`sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" <readelf>` 补 |
| 编 `des_app` 报 `undefined reference to png_*@PNG16_0` / `inflate*`，或 warning `libpng16.so.16, needed by .../libfreetype.so, not found` | `$BOARD_LIBS` 缺 **SONAME 名** `libpng16.so.16` / `libz.so.1`（链接器按 SONAME 解析 `libfreetype` 自己的依赖）：同上补 |
| 链接报 `undefined reference to cv::...` | 检查 `OPENCV_LIB` 是否指向 `ffmpeg_opencv4.7.0_aarch64/` 目录本身（不是父目录），并确认运行过 `scripts/sdk_fix_sonames.sh` |
| 板上跑 `des_app` 报 `error while loading shared libraries: libfmt.so` | 板上 `/opt/armnn_lib/lib/libfmt.so` 缺失或库路径没设；从厂家镜像的 `/opt/armnn_lib/lib/` 补齐（`des_app` 的 rpath 已指向 `/opt/armnn_lib/lib`） |
| 换 `BOOT.bin` 后起不来、串口无输出 | 拨码应为 ON-OFF-OFF（见 §4「启动与拨码」）。板子起不来就没法 SSH：断电取 SD 卡插 PC，在 FAT 分区里把 `BOOT.bin` 删掉、`BOOT.bin.prev` 复制一份改名为 `BOOT.bin`；或拨到 eMMC 启动（OFF-OFF-OFF）后挂载 SD 卡的 p1 分区（FAT32）同样操作 |
| 厂家生成的 `proc_sys_reset_*.v` 显示「已修改」 | CRLF 差异，会让 `rebase --autostash` 失败：`git update-index --assume-unchanged <文件>`，rebase 完再 `--no-assume-unchanged` |
| Git Bash 的 heredoc / `printf` 吞反斜杠（Windows 路径与转义丢失） | 含反斜杠的脚本先写成文件再执行，不用内联 heredoc |

命令行编译的成败判定见 [开发环境与构建](开发环境与构建.md)「PL：构建与打包」。
