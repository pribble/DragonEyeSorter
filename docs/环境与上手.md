# 环境与上手

> 第一次把项目跑起来：需要哪些环境、`.env` 怎么配、依赖文件从哪拿、板子要做哪些一次性设置。工具链版本与编译 / 打包 / 部署见 [开发环境与构建](开发环境与构建.md)；板上文件布局见 [板端布局](板端布局.md)。

## 1. 需要哪些环境

各工具与库的版本号在 [开发环境与构建](开发环境与构建.md)「工具与版本」维护，本节只写"要什么 / 从哪拿 / 怎么验证"。本机路径一律写进 `.env`（见 §2），文档与脚本只用变量名引用。

| 要什么 | 从哪拿 | 怎么验证 |
|---|---|---|
| TD（PL 综合、布局布线、生成比特流） | 安路官网 FPGA 开发套件；许可证放 `$TD_ROOT/license/` | 打开 TD，Help → About 看版本；`$TD_ROOT/bin/` 与 `$TD_ROOT/license/` 存在 |
| FD（aarch64 交叉编译、BootGen 打包 `BOOT.bin`） | 安路官网嵌入式开发套件 | `$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-gcc` 与 `$FD_ROOT/tools/bootgen/albg1.exe` 存在 |
| WSL Ubuntu 22.04（`mkimage` / `dtc`，改启动脚本与设备树用） | `wsl --install -d Ubuntu-22.04`，再 `sudo apt-get install -y lz4 u-boot-tools mtools dosfstools parted device-tree-compiler` | `mkimage` / `dtc` / `lz4` / `parted` / `mcopy` 五条命令都能执行 |
| 厂家 NPU demo 包（可选，`NPU_DEMO`） | 米联客 `uisrc-lab-anlogic`：https://uisrc.com/t-5868.html | 解压目录里有 `boot/`、`soc_sdk/`、`soc_prj/` |

| OpenCV 库（`$OPENCV_LIB`） | 同一个 `libs/` 下的 `ffmpeg_opencv4.7.0_aarch64`（`include/` + `lib/`） | `ls "$OPENCV_LIB/lib/libopencv_core.so"` |
| FreeType 头文件（`$FREETYPE_INC`） | 从板上 `scp`（需先做完 §4），或官网源码包 2.10.1 | `ls "$FREETYPE_INC/freetype/freetype.h"` |

| PC 端 SSH 私钥（`$SSH_KEY`，免密登录用） | 每台电脑自己的环境，仓库里没有：`ssh-keygen -t ed25519 -f "$SSH_KEY"`（见 §4） | `ssh $BOARD_HOST "hostname"` 返回 `buildroot` |
| `BOOT.bin` 的两个固定零件（`fsbl.elf` / `u-boot.elf`） | 已入库：`scripts/bootbin/parts/`，台账 [parts/MD5SUMS.txt](../scripts/bootbin/parts/MD5SUMS.txt) | `make_bootbin.ps1 -Bit <比特流>` 直接能用 |
| 米联客 Linux 开发包（可选，`uisrc-lab-anlogic`） | 同 NPU demo 页面 | 只在改内核 / U-Boot / 内核驱动 / 加系统软件包时要；主线不依赖 |
| Python 训练环境（可选） | WSL 里的 venv `~/des-train`；GPU 版需 NVIDIA 驱动支持 CUDA | `python -c "import torch; print(torch.cuda.is_available())"`；流程见 [train/README](../train/README.md) |
| USB-CAN（可选，`pc/plc_sim` 用） | ZQWL-UCAN-101E 免驱动（Windows 自带 usbser），`pip install pyserial`；其他适配器用 ControlCAN.dll 或 `python-can` 后端 | `python plc_gui.py --backend virtual` 能起界面（无硬件也能跑）；`python zqwl.py selftest` |
| 提交材料生成环境（可选：作品报告 / 答辩 PPT） | Microsoft Office 桌面版（Word、PowerPoint，仅 Windows 可走 COM 导出）；Python 3 + `python-pptx` / `Pillow` / `PyMuPDF`（`python -m pip install`）；PowerShell 7（`pwsh`）；字体：报告用宋体 / 黑体 / Times New Roman，PPT 用微软雅黑，行内代码与等宽处用 Consolas | `python -c "import pptx, PIL, pymupdf"`；`New-Object -ComObject PowerPoint.Application` 不报错；细节（每步要什么、怎么导出）见 [submission/PPT制作指南](../submission/PPT制作指南.md)「需要什么环境」与 [submission/build/README](../submission/build/README.md)「依赖」 |

NPU demo 包只有三处要用：① 取上面两个库目录；② 重建丢失的 `parts/u-boot.elf`、或取厂家原始 `fsbl.elf`（两者都用 `make_bootbin.ps1 -VendorDemo <目录>`）；③ 手工复刻 SD 卡启动分区时取 `boot/`。**常规打包 `BOOT.bin` 不需要它**（零件已随仓库提供）。

不编需要 SDK 的程序（`des_app` / `des_tool` / 用到这些库的 `test_*`）时，`$ARMNN_LIB` / `$OPENCV_LIB` / `$FREETYPE_INC` / `$BOARD_LIBS` 可留空：`ps/Makefile` 的 `check-sdk` / `check-board` 只在编到那些目标时才检查。

**硬件**：必需 = 安路飞龙 F3P 开发板（米联客 F3P-NPU 版）、相机（VID005 子卡 + IMX415，MIPI CSI）、SD 卡（≥8GB，推荐 32GB）+ 读卡器、网线（直连电脑）或 USB-TTL 串口（调试）、PC（Windows 10/11，建议 16GB+ RAM、4 核以上）。可选 = HDMI 显示器、6 轴总线舵机机械臂（传动比 6:1，TTL 总线）、步进电机 + 驱动器（传送带）、CAN 收发器（与 PLC 通信）。

PL 工程与工具安装路径不能有中文和空格；TD / FD 的版本要求与共存限制见 [开发环境与构建](开发环境与构建.md)「工具与版本」。

## 2. 配置 `.env`

脚本与 Makefile 里的本机路径各人不同、换台电脑要手改，故统一由 `.env` 管理。

| 文件 | 作用 | 入库 |
|---|---|---|
| [.env.example](../.env.example) | 配置模板，列出全部配置项 | ✅ |
| `.env` | 你本机的实际路径 | ❌ |
| `.env.make` | 由 `.env` 生成，供 `ps/Makefile` include | ❌ |
| [scripts/env_loader.ps1](../scripts/env_loader.ps1) / [.sh](../scripts/env_loader.sh) | 手动加载进当前会话，并报告各路径是否存在 | ✅ |
| [scripts/generate_env_make.sh](../scripts/generate_env_make.sh) | 从 `.env` 生成 `.env.make` | ✅ |
| [scripts/test_env.ps1](../scripts/test_env.ps1) | 逐项检查关键路径并给结论 | ✅ |

**自动加载 `.env` 的入口**（不必手动 source）：[scripts/bootbin/make_bootbin.ps1](../scripts/bootbin/make_bootbin.ps1)、`ps/Makefile`（`-include ../.env.make`）。

### 怎么配

```powershell
cd <仓库根目录>
copy .env.example .env                  # 从模板复制；变量清单见 .env.example
bash scripts/generate_env_make.sh       # 生成 ps/Makefile 用的 .env.make
.\scripts\test_env.ps1                  # 自检：逐项检查关键路径是否成立
```

| 变量 | 指向什么 |
|---|---|
| `FD_ROOT` | FD 安装目录（含 `toolchain/gcc/aarch64_linux/`） |
| `TD_ROOT` | TD 安装目录（含 `license/`、`bin/`） |
| `ARMNN_LIB` | ArmNN 库目录（`include/`、`lib/`，含 `libfmt.a`）；名字与板端 `/opt/armnn_lib` 一致 |
| `OPENCV_LIB` | OpenCV 4.7 + FFmpeg 库目录；名字与板端 `/opt/ffmpeg_opencv4.7.0_aarch64` 一致 |
| `FREETYPE_INC` | FreeType 头文件目录 |
| `BOARD_LIBS` | 板上库的本地拷贝目录（`libfreetype.so.6` 等，链接期用，不上板） |
| `NPU_DEMO`（可选） | 厂家 NPU demo 解压目录；只有取编 PS 的两个库、重建 `parts/u-boot.elf` / 取厂家原始 `fsbl.elf`、手工复刻 SD 启动分区时才要（见 §1 表下说明） |
| `BOARD_HOST` | `ssh` / `scp` 的目标：`~/.ssh/config` 里的别名（推荐），或 `root@<板子IP>`；板端命令一律用它 |
| `BOARD_IP` | 板子原始 IP：`ping`、`ssh-keygen -R`、写 `~/.ssh/config`、板端 dhcpcd 配置用 |
| `SSH_KEY` | PC 端私钥路径；首次配置时生成，未配别名时配合 `-i` 使用 |

第三方库**一个库一个变量、各自一个根**（不是一个 SDK 根加两个子目录名）；两个库目录与板上 `/opt` 下的布局同构，见 §3。

**§4 起的板端命令都按「变量已加载」来写**：先 `. .\scripts\env_loader.ps1`（PowerShell）或 `source scripts/env_loader.sh`（Bash / WSL），`$BOARD_HOST` / `$BOARD_IP` / `$SSH_KEY` 才会有值。

### 手动加载与覆盖

```powershell
. .\scripts\env_loader.ps1              # PowerShell：加载后 $env:FD_ROOT 等可用
```
```bash
source scripts/env_loader.sh            # Bash / WSL
make -C ps all                          # Makefile 自动 include .env.make
make -C ps CROSS=<工具链前缀> ARMNN_LIB=<armnn_lib 目录> OPENCV_LIB=<ffmpeg_opencv4.7.0_aarch64 目录>   # 命令行覆盖
```

**优先级**：命令行参数 > Shell 环境变量 > `.env` > 无默认值。`.env` 与命令行都没给时 `ps/Makefile` 直接报错并提示怎么配，`scripts/` 下的脚本同理——它们不留任何主机路径默认值。

### 路径格式

```bash
FD_ROOT=<盘符>:/目录/FD                 # Windows：正斜杠或反斜杠都行，脚本自动处理
DES_WORK_DIR=$HOME/des-work             # 用 $HOME 跨用户兼容（推荐）
```

### 常见问题

| 现象 | 处理 |
|---|---|
| 提示"找不到 .env 文件" | `cp .env.example .env` 后填路径 |
| 路径存在却提示"路径不存在" | 查路径格式：多余空格、Windows 路径用 `/` |
| `make -C ps` 报 `FD_ROOT 未设置` / `ARMNN_LIB 未设置或目录不存在` | Makefile 不留默认值：填好 `.env` 后必须重新 `bash scripts/generate_env_make.sh` 生成 `.env.make` |
| 换一台电脑 | 克隆 → `cp .env.example .env` → 填路径 → `.\scripts\test_env.ps1` → `bash scripts/generate_env_make.sh`；`.env.make` 是生成物，换机后必须重生 |
| CI / 无人值守 | 不放 `.env`，直接设环境变量：`export FD_ROOT=<…> ARMNN_LIB=<…> OPENCV_LIB=<…>` 后 `make -C ps all` |

路径只写在**不入库**的 `.env` 里，不直接改脚本 / Makefile：那样 diff 大、易与队友冲突，换台电脑还要再改一遍（[AGENTS.md](../AGENTS.md) 硬性约定第 9 条）。新增配置项时同步更新 `.env.example`。

## 3. 获取依赖文件

ArmNN / OpenCV 两个库、FreeType 头文件、板上库文件**自行获取、不入库**，分别对应 `.env` 的 `ARMNN_LIB` / `OPENCV_LIB` / `FREETYPE_INC` / `BOARD_LIBS`。

厂家 NPU demo 包（米联客 https://uisrc.com/t-5868.html）提供前两个库：解压后取 `demo/sdk/face_detection/libs/` 下的 `armnn_lib/` 与 `ffmpeg_opencv4.7.0_aarch64/`。Windows 解压会丢失 `.so` 软链接，必须先跑修复脚本：

```bash
# 两个库各自一个目录，建议平铺成与板端 /opt 同构的布局：
#   <某个仓库外目录>/armnn_lib、<同一个目录>/ffmpeg_opencv4.7.0_aarch64
# 然后把 .env 的 ARMNN_LIB / OPENCV_LIB 分别指到这两个目录（不是它们的父目录）
sh scripts/sdk_fix_sonames.sh "$ARMNN_LIB"  "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"
sh scripts/sdk_fix_sonames.sh "$OPENCV_LIB" "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"

# FreeType 头文件 → FREETYPE_INC。选项 A（推荐，需先做完 §4）：从板上拷；选项 B：官网源码包
scp -r $BOARD_HOST:/usr/include/freetype2 "$FREETYPE_INC"
wget https://download.savannah.gnu.org/releases/freetype/freetype-2.10.1.tar.gz
tar -xzf freetype-2.10.1.tar.gz        # FREETYPE_INC 指向 freetype-2.10.1/include

# 板上库文件 → BOARD_LIBS：两套名字都要有（缺哪套报什么错见 §6）
#   SONAME 名 libX.so.N —— 链接器解析 libfreetype 自己的依赖（libpng16.so.16 / libz.so.1）时按它找文件
#   链接名   libX.so   —— Makefile 的 -lfreetype 只认这个名字
mkdir -p "$BOARD_LIBS"
scp $BOARD_HOST:/usr/lib/libfreetype.so.6 "$BOARD_LIBS/"
scp $BOARD_HOST:/usr/lib/libpng16.so.16 "$BOARD_LIBS/"
scp $BOARD_HOST:/usr/lib/libz.so.1 "$BOARD_LIBS/"
sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" \
    "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf.exe"   # 按 SONAME 补出链接名
# libfmt 不用从板上拷：Makefile 的 -lfmt 命中的是 $ARMNN_LIB/lib/libfmt.a（静态）
```

改内核 / U-Boot / 内核驱动 / 加系统软件包时另需米联客 Linux 开发包（`uisrc-lab-anlogic`），主线不依赖它。

## 4. 板子一次性配置

### 启动与拨码

- **拨码开关**（板上 SW1，3 位）：**ON-OFF-OFF** = 从 SD 卡启动（日常使用）；OFF-OFF-OFF = 从 eMMC 启动（出厂系统，救生艇，保持原样）。
- **SD 卡**：厂家预装系统的卡，或自制的持久化镜像（见 [开发环境与构建](开发环境与构建.md)「SD 卡布局与烧卡」）。
- **PS 网口**（RJ45，靠近 USB 接口那个）：网线接这里，另一端接电脑有线网口或同一路由器；PL 网口需比特流里有对应网卡逻辑，当前工程不支持。
- **串口**（可选，调试与首次配置用）：USB-TTL 转换器 3.3V 电平接 J10 —— 1 = GND、2 = 板子 RX、3 = 板子 TX；115200 8N1，无流控。
- **首次登录**：串口登录 Buildroot 的 `root`（密码默认为空，或见板卡手册）；板子默认由 DHCP 取 IP，接了路由器也可从路由器管理界面查。

### 板端网络

板子 `eth0` 由 dhcpcd 管理，固定 IP（= `.env` 的 `BOARD_IP`）追加在 `/etc/dhcpcd.conf` 末尾，原文件备份为 `/etc/dhcpcd.conf.orig`：

```bash
cp /etc/dhcpcd.conf /etc/dhcpcd.conf.orig
cat >> /etc/dhcpcd.conf << 'EOF'

# DragonEyeSorter 固定 IP 配置
interface eth0
static ip_address=192.168.137.100/24
static routers=192.168.137.1
EOF
reboot      # 重启后板子固定为 192.168.137.100
```

PC 侧有线网卡设 `192.168.137.1`、子网掩码 `255.255.255.0`（与 `static routers` 对应；`.env` 的 `BOARD_IP` 与上面 `static ip_address` 是同一个值）。用 Windows 的「Internet 连接共享」给板子联网时，该网卡也会被自动改成 `192.168.137.1/24`，与上面的固定 IP 方案一致。

### 免密 SSH

**先要有密钥**——它和 TD / FD 一样是每台电脑自己的环境，仓库里没有：没有就生成，已有别的密钥就把 `.env` 的 `SSH_KEY` 指向它。公钥追加到板端 `/root/.ssh/authorized_keys`：

```bash
ssh-keygen -t ed25519 -f "$SSH_KEY" -C "<标签，仅注释用>"
ssh-copy-id -i "$SSH_KEY.pub" root@$BOARD_IP
```

PowerShell 默认没有 `ssh-copy-id`（用 Git Bash / WSL，或串口登录板子后手动追加）：

```bash
mkdir -p /root/.ssh
cat >> /root/.ssh/authorized_keys << 'EOF'
<粘贴 $SSH_KEY.pub 的内容>
EOF
chmod 700 /root/.ssh
chmod 600 /root/.ssh/authorized_keys
```

**配别名（推荐）**：在 PC 的 `~/.ssh/config` 写一段，把 IP、用户、私钥都收进去，之后 `ssh` / `scp` 一律只写别名，命令里不再出现 IP 与 `-i`。`Host` 名自定，但必须与 `.env` 的 `BOARD_HOST` 一致；`HostName` / `IdentityFile` 的值同 `.env` 的 `BOARD_IP` / `SSH_KEY`（下面以别名 `des` 为例）：

```
Host des
    HostName 192.168.137.100
    User root
    IdentityFile ~/.ssh/id_ed25519_anlu
    IdentitiesOnly yes
    ServerAliveInterval 60
    ServerAliveCountMax 3
    StrictHostKeyChecking accept-new
```

`IdentitiesOnly yes` 让它只用这一把密钥（否则连板子前会先挨个试 `id_rsa`、`id_ecdsa`…）；`StrictHostKeyChecking accept-new` 免掉非交互会话卡在指纹确认，板子重刷系统换了 host key 也不会把命令挂住。**不配别名**时把 `BOARD_HOST` 填成 `root@<板子IP>`，并在每条命令里补上 `-i "$SSH_KEY"`。

### 板上目录与时间

```bash
mkdir -p /root/des /root/des/data   # 主程序 / 模型 / 运行数据（日志、采集图像）
mkdir -p /root/bin                  # 工具脚本
```

完整布局（两个分区、四类文件各由谁更新、每件缺了会怎样、路径与相对引用规矩）见 [板端布局](板端布局.md)。

板上环境自检：

```bash
uname -a                                    # Linux buildroot 6.1.111-rt42 ... aarch64（-rt42 = PREEMPT_RT 补丁）
ls -l /opt/armnn_lib/lib/libarmnn.so        # -> libarmnn.so.32 -> libarmnn.so.32.1（ArmNN 32.1 + Alnpu backend）
ls -l /opt/ffmpeg_opencv4.7.0_aarch64/lib/libopencv_core.so*   # .so -> .so.407 -> .so.4.7.0
free -h                                     # Total 约 989M（DRAM 1 GiB，其中 128 MiB 归 linux,cma）
df -h                                       # 根分区显示为 /dev/root：3.6G 容量、可用约 2.9G
```

**无 RTC**：每次开机时间从 1970-01-01 起算，需手动设置或对时（因此板端 `ls -l` 的时间戳也不可信：开机后写入的文件都带 1970 的日期）：

```bash
date -s "2026-10-15 14:30:00"     # 手动设置
ntpdate pool.ntp.org              # 联网对时（板子能访问外网时）
```
```powershell
# 从 PC 同步时间（PC 端 PowerShell）
$timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
ssh $BOARD_HOST "date -s '$timestamp'"
```

### 启动脚本

开机自启**已装好**：`/etc/init.d/S90des` 是指向 `/root/des/des_service.sh` 的软链接（BusyBox init 按 `S??` 顺序执行 `start`），脚本源在 `scripts/deploy/out/des_service.sh`。

```bash
ls -l /etc/init.d/S90des            # -> /root/des/des_service.sh
/root/des/des_service.sh status     # 在不在跑 + 最近几条服务事件
```

它是监督进程：拉起 `des_app`，崩了 2 秒后重启、逐次退避到 30 秒；5 分钟内退出 5 次就放弃（坏版本不会反复起停）。服务事件写 `/root/des/data/service.log`（超 1 MB 轮转成 `.1`），PID 记在 `/root/des/data/des_service.pid`。**板端所有路径都取自同目录的 `des.env`**（唯一有路径的文件，见 [scripts/deploy/out/des.env](../scripts/deploy/out/des.env)），所以整套目录拷到别处部署也照常工作；改 / 换它要 `deploy.ps1 -WithService`（先停服务再传，新旧 PID 文件位置不同）。

行为由 `/root/des/autostart.conf` 决定（首次运行自动生成，改完 `restart` 生效）：

| 变量 | 作用 | 板上当前 |
|---|---|---|
| `ENABLED` | `0` = 开机不启动（只改这个文件，不动 `/etc`） | `1` |
| `MODE` | `des_app` 模式：`run`（生产）/ `live`（不带传送带、机械臂、CAN） | `run` |
| `CAN` | 有值时先跑 `can_up.sh <CAN> <CAN_MODE>`，再给 `des_app` 传 `--can <CAN>`；留空则直接进 RUN | `can0` |
| `CAN_MODE` | `normal` = 总线上要有伙伴（PC 的 USB-CAN 当 PLC）应答；`loopback` = 无总线自测 | `normal` |
| `ARGS` | 追加给 `des_app` 的参数，如 `--go`（机械臂真动）、`--belt 60` | 空 |

带 CAN 启动时 `des_app` 先停在**空闲**，等 PLC（或界面按钮）发 START 才动作；机械臂只在 `ARGS` 里带 `--go` 时才真动——所以自启默认不碰硬件。右列是当前板上值，以 `autostart.conf` 为准。

人工跑 `des_app.sh`、`des_tool.sh` 或 `desreg` 写命令前先停服务（相机 DMA、舵机总线、步进都只有一个主人），用完恢复；命令与运行方式见 [开发环境与构建](开发环境与构建.md)「部署与运行」。`pl_check.sh` / `soak.sh` 自己会在开跑前暂停服务、跑完恢复。

### 板端限制

- **BusyBox 没有 `timeout`、`pkill`**：限时运行用后台 + `sleep` 自己实现。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 编 `des_app` 报 `cannot find -lfreetype` | `$BOARD_LIBS` 缺**链接名** `libfreetype.so`（`-l` 只认无版本号的名字）：`sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" <readelf>` 补 |
| 编 `des_app` 报 `undefined reference to png_*@PNG16_0` / `inflate*`，或 warning `libpng16.so.16, needed by .../libfreetype.so, not found` | `$BOARD_LIBS` 缺 **SONAME 名** `libpng16.so.16` / `libz.so.1`（链接器按 SONAME 解析 `libfreetype` 自己的依赖）：同上补 |
| 链接报 `undefined reference to cv::...` | 检查 `OPENCV_LIB` 是否指向 `ffmpeg_opencv4.7.0_aarch64/` 目录本身（不是它的父目录），并确认运行过 `scripts/sdk_fix_sonames.sh` |
| 板上跑 `des_app` 报 `error while loading shared libraries: libfmt.so` | 板上 `/opt/armnn_lib/lib/libfmt.so` 缺失或库路径没设；从厂家镜像的 `/opt/armnn_lib/lib/` 补齐该文件（`des_app` 的 rpath 已指向 `/opt/armnn_lib/lib`） |
| 换 `BOOT.bin` 后起不来、串口无输出 | 拨码应为 ON-OFF-OFF（见 §4「启动与拨码」）。板子起不来就没法 SSH：断电取 SD 卡插 PC，在 FAT 分区里把 `BOOT.bin` 删掉、`BOOT.bin.prev` 复制一份改名为 `BOOT.bin`；或拨到 eMMC 启动（OFF-OFF-OFF）后挂载 SD 卡的 p1 分区（FAT32）同样操作 |

命令行编译的成败判定见 [开发环境与构建](开发环境与构建.md)「PL：构建与打包」；板上 NPU 推理的已知问题见 [train/README](../train/README.md)。
