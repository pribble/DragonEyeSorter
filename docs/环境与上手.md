# 环境与上手

> 用本仓库需要什么环境、怎么从零把它跑起来、板子有哪些一次性设置。工具链与构建细节见 [开发环境与构建](开发环境与构建.md)；各目录说明见[根 README](../README.md)「仓库结构」。

## 1. 需要哪些环境

版本以 [开发环境与构建](开发环境与构建.md)「工具与版本」为准；本机路径一律写进 `.env`（见 §2），文档与脚本只用变量名引用。

| 要什么 | 版本 / 内容 | 从哪拿 | 怎么验证 |
|---|---|---|---|
| TD（PL 综合布线） | 6.2.1 Release（Build 175876），含许可证 | 安路官网 FPGA 开发套件；许可证 `Anlogic.lic` 放 `<TD安装目录>\license\` | 打开 TD，Help → About 看版本；`$TD_ROOT/bin/` 与 `$TD_ROOT/license/` 存在 |
| FD（交叉编译、BOOT.bin 打包） | 2026.1 SP1 | 安路官网嵌入式开发套件 | `$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-gcc` 与 `$FD_ROOT/tools/bootgen/albg1.exe` 存在 |
| WSL（生成 SD 镜像、`mkimage`、`dtc`） | Ubuntu 22.04 + `lz4 u-boot-tools mtools dosfstools parted device-tree-compiler` | `wsl --install -d Ubuntu-22.04`，再 `sudo apt-get install -y …` | `mkimage` / `dtc` / `lz4` / `parted` / `mcopy` 五条命令都能执行 |
| 厂家 NPU demo（可选，`NPU_DEMO`） | 米联客 `uisrc-lab-anlogic` | https://uisrc.com/t-5868.html | 解压目录里有 `boot/`、`soc_sdk/`、`soc_prj/`。**只在做 SD 镜像、重建 boot 零件、取厂家原始 FSBL 时才要**；常规打包 BOOT.bin 不需要 |
| ArmNN 库（`$ARMNN_LIB`） | 厂家 `face_detection/libs/armnn_lib`：`include/` + `lib/`（含 `libfmt.a`） | 从 NPU demo 解压（Windows 解压后先跑 `scripts/sdk_fix_sonames.sh`） | `ls "$ARMNN_LIB/lib/libarmnn.so"` |
| OpenCV 库（`$OPENCV_LIB`） | 厂家 `face_detection/libs/ffmpeg_opencv4.7.0_aarch64`：`include/` + `lib/` | 同上 | `ls "$OPENCV_LIB/lib/libopencv_core.so"` |
| FreeType 头文件（`$FREETYPE_INC`） | 板上 `/usr/include/freetype2`，或官网源码包 2.10.1 | 从板上 `scp`，或 https://download.savannah.gnu.org/releases/freetype/ | `ls "$FREETYPE_INC/freetype/freetype.h"` |
| 板上库文件（`$BOARD_LIBS`） | `libfreetype` / `libpng16` / `libz` 各**两套名字都要**：SONAME 名（`libfreetype.so.6`、`libpng16.so.16`、`libz.so.1`）+ 链接名（`libfreetype.so` 等） | 从板上 `scp`（见 §3），再跑 `scripts/sdk_fix_sonames.sh` 补出缺的那套 | `ls "$BOARD_LIBS/libfreetype.so.6" "$BOARD_LIBS/libfreetype.so"` |
| BOOT.bin 的固定零件 | `scripts/bootbin/parts/` 的 `fsbl.elf`、`u-boot.elf` | **已入库，不用另找**（台账 `parts/MD5SUMS.txt`，脚本每次校验 `u-boot.elf` 的 MD5） | `make_bootbin.ps1` 直接能用 |
| Python 训练环境（可选） | WSL 里的 venv `~/des-train`；GPU 版需 NVIDIA GPU + CUDA 12.1 | [train/README](../train/README.md) | `python -c "import torch; print(f'CUDA available: {torch.cuda.is_available()}')"` |
| USB-CAN 驱动（可选，`pc/plc_sim` 用） | 卖家 `ControlCAN.dll`（ZLG 兼容），或 `python-can` 后端 | [pc/plc_sim/README](../pc/plc_sim/README.md) | `python plc_gui.py --backend virtual` 能起界面（无硬件也能跑） |

不编 PS 应用时 `$ARMNN_LIB` / `$OPENCV_LIB` / `$FREETYPE_INC` / `$BOARD_LIBS` 可留空——`ps/Makefile` 只在编 `des_app` / `test_calib` / `test_measure` / `test_npu` 时才检查它们。要改内核 / U-Boot / 写内核驱动 / 加系统软件包时，另需米联客 Linux 开发包（`uisrc-lab-anlogic`）。

**硬件**：必需 = 安路飞龙 F3P 开发板（米联客 F3P-NPU 版）、相机（VID005 子卡 + IMX415，MIPI CSI）、SD 卡（≥8GB，推荐 32GB）+ 读卡器、网线（直连电脑）或 USB-TTL 串口（调试）、PC（Windows 10/11，建议 16GB+ RAM、4 核以上）。可选 = HDMI 显示器、6 轴总线舵机机械臂（传动比 6:1，TTL 总线）、步进电机 + 驱动器（传送带）、CAN 收发器（与 PLC 通信）。

⚠ TD 6.2.1 与 2026.1 使用相同 UpgradeCode，**不能共存**：装过 2026.1 的需先卸载；PL 工程与工具安装路径**不能有中文和空格**。

## 2. 配置 `.env`

脚本与 Makefile 里的本机路径各人不同、换台电脑要手改，故统一由 `.env` 管理。

| 文件 | 作用 | 入库 |
|---|---|---|
| [.env.example](../.env.example) | 配置模板，列出全部配置项 | ✅ |
| `.env` | 你本机的实际路径 | ❌ |
| `.env.make` | 由 `.env` 生成，供 `ps/Makefile` include | ❌ |
| [scripts/env_loader.ps1](../scripts/env_loader.ps1) / [.sh](../scripts/env_loader.sh) | 手动加载进当前会话，并报告各路径是否存在 | ✅ |
| [scripts/generate_env_make.sh](../scripts/generate_env_make.sh) | 从 `.env` 生成 `.env.make` | ✅ |
| [scripts/test_env.ps1](../scripts/test_env.ps1) | 逐项检查关键路径并给结论 | ✅ |

**自动加载 `.env` 的入口**（不必手动 source）：[scripts/bootbin/make_bootbin.ps1](../scripts/bootbin/make_bootbin.ps1)、`ps/Makefile`（`-include ../.env.make`）。

### 怎么配

```powershell
cd <仓库根目录>
copy .env.example .env                  # 从模板复制；变量清单见 .env.example
bash scripts/generate_env_make.sh       # 生成 ps/Makefile 用的 .env.make
.\scripts\test_env.ps1                  # 自检：逐项检查关键路径是否成立
```

| 变量 | 指向什么 |
|---|---|
| `FD_ROOT` | FD 安装目录（含 `toolchain/gcc/aarch64_linux/`） |
| `TD_ROOT` | TD 6.2.1 安装目录（含 `license/`、`bin/`） |
| `ARMNN_LIB` | ArmNN 库目录（`include/`、`lib/`，含 `libfmt.a`）；名字与板端 `/opt/armnn_lib` 一致 |
| `OPENCV_LIB` | OpenCV 4.7 + FFmpeg 库目录；名字与板端 `/opt/ffmpeg_opencv4.7.0_aarch64` 一致 |
| `FREETYPE_INC` | FreeType 头文件目录 |
| `BOARD_LIBS` | 板上库的本地拷贝目录（`libfreetype.so.6` 等，链接期用，不上板） |

第三方库**一个库一个变量、各自一个根**（不再是一个 `SDK_LIBS` 根加两个子目录名）。两个库目录平铺在仓库外，与板上 `/opt` 下的布局同构，见 §3。

`NPU_DEMO`（厂家 NPU demo 解压目录）**已从 `.env` 移除**：打 BOOT.bin 的零件已随仓库提供（`scripts/bootbin/parts/`，见 §1 表），常规打包不需要它。只剩 `u-boot.elf` 损坏要重建、或取厂家原始 FSBL 时要它，命令行传 `-VendorDemo <目录>` 即可。

### 手动加载与覆盖

```powershell
. .\scripts\env_loader.ps1              # PowerShell：加载后 $env:FD_ROOT 等可用
```
```bash
source scripts/env_loader.sh            # Bash / WSL
make -C ps all                          # Makefile 自动 include .env.make
make -C ps CROSS=<工具链前缀> ARMNN_LIB=<armnn_lib 目录> OPENCV_LIB=<ffmpeg_opencv4.7.0_aarch64 目录>   # 命令行覆盖
```

**优先级**：命令行参数 > Shell 环境变量 > `.env` > 无默认值。`.env` 与命令行都没给时 `ps/Makefile` 直接报错并提示怎么配，`scripts/` 下的脚本同理——它们不留任何主机路径默认值。

### 路径格式

```bash
FD_ROOT=<盘符>:/目录/FD                 # Windows：正斜杠或反斜杠都行，脚本自动处理
DES_WORK_DIR=$HOME/des-work             # 用 $HOME 跨用户兼容（推荐）
```

### 常见问题

| 现象 | 处理 |
|---|---|
| 提示"找不到 .env 文件" | `cp .env.example .env` 后填路径 |
| 路径存在却提示"路径不存在" | 查路径格式：多余空格、Windows 路径用 `/` |
| `make -C ps` 报 `FD_ROOT 未设置` / `ARMNN_LIB 未设置或目录不存在` | Makefile 故意不留默认值：填好 `.env` 后**必须重新** `bash scripts/generate_env_make.sh` 生成 `.env.make` |
| 为什么不直接改脚本 / Makefile 里的路径 | 那样 diff 大、易与队友冲突，换台电脑还得再改。路径只写在**不入库**的 `.env` 里，脚本与文档只用变量名（[AGENTS.md](../AGENTS.md) 硬性约定第 9 条） |
| 换一台电脑 | 克隆 → `cp .env.example .env` → 填路径 → `.\scripts\test_env.ps1` → `bash scripts/generate_env_make.sh`。`.env.make` 是生成物，换机后必须重生 |
| CI / 无人值守 | 不放 `.env`，直接设环境变量：`export FD_ROOT=<…> ARMNN_LIB=<…> OPENCV_LIB=<…>` 后 `make -C ps all` |

新增配置项时同步更新 `.env.example`；`.env` 由 `.gitignore` 排除，只留本机。

## 3. 获取依赖文件

ArmNN / OpenCV 两个库、FreeType 头文件、板上库文件**自行获取、不入库**，分别对应 `.env` 的 `ARMNN_LIB` / `OPENCV_LIB` / `FREETYPE_INC` / `BOARD_LIBS`。

**NPU Demo 完整包（编 PS 时必需，打 BOOT.bin 不需要）**：米联客论坛 https://uisrc.com/t-5868.html 下载解压，用到两处 —— `demo/sdk/face_detection/libs/`（`armnn_lib/`、`ffmpeg_opencv4.7.0_aarch64/`，编 PS 用）；`demo/soc_prj/soc_prj_Runs/best_result/soc_prj.bit`（厂家基线比特流，仅在需要时核对）。⚠ Windows 上解压会丢失 `.so` 软链接，需先跑修复脚本：

```bash
# 两个库各自一个目录，建议平铺成与板端 /opt 同构的布局：
#   <某个仓库外目录>/armnn_lib、<同一个目录>/ffmpeg_opencv4.7.0_aarch64
# 然后把 .env 的 ARMNN_LIB / OPENCV_LIB 分别指到这两个目录（不是它们的父目录）
sh scripts/sdk_fix_sonames.sh "$ARMNN_LIB"  "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"
sh scripts/sdk_fix_sonames.sh "$OPENCV_LIB" "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf"

# FreeType 头文件 → FREETYPE_INC。选项 A（推荐，需先做完 §4）：从板上拷；选项 B：官网源码包
scp -r root@192.168.137.100:/usr/include/freetype2 "$FREETYPE_INC"
wget https://download.savannah.gnu.org/releases/freetype/freetype-2.10.1.tar.gz
tar -xzf freetype-2.10.1.tar.gz        # FREETYPE_INC 指向 freetype-2.10.1/include

# 板上库文件 → BOARD_LIBS：两套名字都要有（缺哪套报什么错见 §6）
#   SONAME 名 libX.so.N —— 链接器解析 libfreetype 自己的依赖（libpng16.so.16 / libz.so.1）时按它找文件
#   链接名   libX.so   —— Makefile 的 -lfreetype 只认这个名字
mkdir -p "$BOARD_LIBS"
scp root@192.168.137.100:/usr/lib/libfreetype.so.6 "$BOARD_LIBS/"
scp root@192.168.137.100:/usr/lib/libpng16.so.16 "$BOARD_LIBS/"
scp root@192.168.137.100:/usr/lib/libz.so.1 "$BOARD_LIBS/"
sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" \
    "$FD_ROOT/toolchain/gcc/aarch64_linux/bin/aarch64-linux-gnu-readelf.exe"   # 按 SONAME 补出链接名
# libfmt 不用从板上拷：Makefile 的 -lfmt 命中的是 $ARMNN_LIB/lib/libfmt.a（静态）
```

## 4. 板子一次性配置

### 启动与拨码

- **拨码开关**（板上 SW1，3 位）：**ON-OFF-OFF** = 从 SD 卡启动（日常使用）；OFF-OFF-OFF = 从 eMMC 启动（出厂系统，救生艇，保持原样）。
- **SD 卡**：厂家预装系统的卡，或自制的持久化镜像（见 §5）。
- **PS 网口**（RJ45，靠近 USB 接口那个）：网线接这里，另一端接电脑有线网口或同一路由器；PL 网口需比特流里有对应网卡逻辑，当前工程不支持。
- **串口**（可选，调试与首次配置用）：USB-TTL 转换器 3.3V 电平接 J10 —— 1 = GND、2 = 板子 RX、3 = 板子 TX；115200 8N1，无流控。
- **首次登录**：串口登录 Buildroot 的 `root`（密码默认为空，或见板卡手册）；板子默认由 DHCP 取 IP，接了路由器也可从路由器管理界面查。

### 板端网络

板子 `eth0` 由 dhcpcd 管理，固定 IP 追加在 `/etc/dhcpcd.conf` 末尾，原文件备份为 `/etc/dhcpcd.conf.orig`：

```bash
cp /etc/dhcpcd.conf /etc/dhcpcd.conf.orig
cat >> /etc/dhcpcd.conf << 'EOF'

# DragonEyeSorter 固定 IP 配置
interface eth0
static ip_address=192.168.137.100/24
static routers=192.168.137.1
EOF
reboot      # 重启后板子固定为 192.168.137.100
```

PC 侧有线网卡设 `192.168.137.1`、子网掩码 `255.255.255.0`（与 `static routers` 对应）。⚠ 用 Windows 的「Internet 连接共享」给板子联网时，该网卡也会被自动改成 `192.168.137.1/24`，与上面的固定 IP 方案一致。

### 免密 SSH

PC 端私钥 `~/.ssh/id_ed25519_anlu`，公钥追加到板端 `/root/.ssh/authorized_keys`：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_anlu -C "dragon-eye-sorter"
ssh-copy-id -i ~/.ssh/id_ed25519_anlu.pub root@192.168.137.100
```

PowerShell 默认没有 `ssh-copy-id`（用 Git Bash / WSL，或串口登录板子后手动追加）：

```bash
mkdir -p /root/.ssh
cat >> /root/.ssh/authorized_keys << 'EOF'
<粘贴 ~/.ssh/id_ed25519_anlu.pub 的内容>
EOF
chmod 700 /root/.ssh
chmod 600 /root/.ssh/authorized_keys
```

之后一律指定私钥：`ssh -i ~/.ssh/id_ed25519_anlu root@192.168.137.100`，`scp` 同理。可选在 PC 的 `~/.ssh/config` 写别名（之后 `ssh dragon-eye`）：`Host dragon-eye` / `HostName 192.168.137.100` / `User root` / `IdentityFile ~/.ssh/id_ed25519_anlu` / `ServerAliveInterval 60` / `ServerAliveCountMax 3`。

### 板上目录与时间

```bash
mkdir -p /root/des /root/des/data   # 主程序 / 模型 / 运行数据（日志、采集图像）
mkdir -p /root/bin                  # 工具脚本
```

板上环境自检：

```bash
uname -a                                    # Linux buildroot 6.1.111-rt42 ... PREEMPT_RT
```

```bash

ntpdate pool.ntp.org              # 联网对时（板子能访问外网时）
```
```powershell
# 从 PC 同步时间（PC 端 PowerShell）
$timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
ssh -i ~/.ssh/id_ed25519_anlu root@192.168.137.100 "date -s '$timestamp'"
```

### 启动脚本

开机自启动写在 `/etc/init.d/S99des`（⚠ 默认注释掉自启动，调试完成后再启用）：

```bash
cat > /etc/init.d/S99des << 'EOF'
#!/bin/sh
case "$1" in
  start)
    echo "Starting DragonEyeSorter..."
    cd /root/des
    # 设置时间（从 PC NTP 或固定值）
    date -s "2026-10-15 09:00:00"
    # 启动主程序（后台运行）
    # ./des_app run --log /root/des/data/app.log &
    ;;
  stop)
    echo "Stopping DragonEyeSorter..."
    killall des_app
    ;;
  *)
    echo "Usage: $0 {start|stop}"
    exit 1
esac
exit 0
EOF
chmod +x /etc/init.d/S99des
```

### 已知坑

- **首次连接报 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`**：旧 initramfs 系统每次开机重新生成主机密钥。先经串口登录板子核对指纹 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`（输出形如 `256 SHA256:xxxxx... root@buildroot (ED25519)`），无误后在 PC 端 `ssh-keygen -R 192.168.137.100` 移除旧记录，再连时输入 `yes` 信任新指纹。⚠ 持久化根分区后主机密钥不再变化，只需处理一次。
- **BusyBox 没有 `timeout`、`pkill`**：限时运行用后台 + `sleep` 自己实现。

### SD 卡

**现有持久化卡已经做好并上板通过**（[log/2026-10-08](log/2026-10-08-持久化SD与BOOT.bin打包.md)），日常只需要换 `BOOT.bin`，不需要重做卡。镜像生成脚本 `scripts/sd_image/make_sd_image.sh` 已于 2026-10-15 删除（一次性工具，且要厂家 demo 的 `uInitrd.lz4`）。

```powershell
# 有镜像要烧卡时（Windows PowerShell 管理员）；也可用 balenaEtcher / Rufus
Get-Disk                                   # 确认 SD 卡磁盘号
```

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 编 `des_app` 报 `cannot find -lfreetype` | `$BOARD_LIBS` 缺**链接名** `libfreetype.so`（`-l` 只认无版本号的名字）：`sh scripts/sdk_fix_sonames.sh "$BOARD_LIBS" <readelf>` 补 |
| 编 `des_app` 报 `undefined reference to png_*@PNG16_0` / `inflate*`，或 warning `libpng16.so.16, needed by .../libfreetype.so, not found` | `$BOARD_LIBS` 缺 **SONAME 名** `libpng16.so.16` / `libz.so.1`（链接器按 SONAME 解析 `libfreetype` 自己的依赖）：同上补 |
| 链接报 `undefined reference to cv::...` | 检查 `OPENCV_LIB` 是否指向 `ffmpeg_opencv4.7.0_aarch64/` 目录本身（不是它的父目录），并确认运行过 `scripts/sdk_fix_sonames.sh` |
| 板上跑 `des_app` 报 `error while loading shared libraries: libfmt.so` | 板上 `/opt/armnn_lib/lib/libfmt.so` 缺失或库路径没设；必要时重做 SD 镜像 |
| 换 `BOOT.bin` 后起不来、串口无输出 | 拨码应为 ON-OFF-OFF（见 §4「启动与拨码」）；恢复备份：`mv /mnt/mmcblk0p1/BOOT.bin.backup /mnt/mmcblk0p1/BOOT.bin` → `sync` → `reboot` |

其它已知坑（命令行编译的成败判定、板上 NPU 推理段错误、板上没有 `timeout` / `pkill`）分别在 [开发环境与构建](开发环境与构建.md) 与 [train/README](../train/README.md) 里，不重复。
