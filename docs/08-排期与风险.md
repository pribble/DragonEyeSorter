# 08 · 排期与风险

> 进度安排、主线范围与风险跟踪（2026-10-04 重排，草案）。2 人：A = 硬件 / FPGA，B = 软件 / AI。初赛约 **2026-11-10** 提交（PPT + 技术文档 + 演示视频，线下审核）。

## 工作策略

1. 架构和接口一次想清楚；功能分层做，不一次铺开。
2. 先用手上已有的设备做能做的事。
3. 主线闭环完整跑通、还有时间时，才加复杂度；加分项按 [01-系统概述](01-系统概述.md) 的 P1 顺序做，做到哪算哪。
4. **会影响架构或硬件选型的拓展现在就定**（光源可频闪、编码器接口、PL 寄存器预留地址）；**能独立插入的往后放**（4G、语音、Web UI、翻板第 2 级）。

## 主线闭环（MVP）—— 10-24 必须跑通

| 硬性项 | MVP 怎么满足 | 视频里看什么 |
|---|---|---|
| ① PL 硬实时 | 步进脉冲发生器 + **舵机总线主机**（SYNC WRITE、遥测回读）+ IO 同步采样（急停锁存、对射、统一时间戳） | 逻辑分析仪抓 SYNC WRITE 帧与步进脉冲；急停后全部停下 |
| ② Linux + 界面 + 存储 | 一个 HDMI 界面：视频 + 框 + 计数 + 参数 + 曲线；SQLite + NG 图片 | 改参数、看曲线、查记录 |
| ③ AXI 双向 | 命令寄存器下行；带位置、舵机遥测、状态、时间戳上行 | 界面上实时的舵机电流 / 温度、带位置曲线 |
| ④ NPU | YOLOv8n@416 跑 ROI，先 4 类再 8 类 | 实时框 + 类别 + 置信度 + 推理耗时 |
| ⑤ 工业总线 | CAN：PC 上 USB-CAN 当"产线 PLC"下发启停 / 调速 | PC 软件收发帧，板子跟着响应 |
| ⑥ 测试报告 | 从第一天埋点 | 文档 |

MVP 分拣范围：单件或放宽件距、随机 Y、随机 θ（S1~S3）。多件同时上带（S4）为 P1。

## 主线精简建议（⚠ 草案，待确认）

| # | 建议 | 原决策 |
|---|---|---|
| ① | 视觉定位先放 PS（OpenCV 阈值 + 轮廓 → `minAreaRect`），PL 图像链降 P1/P2 | PL 8 个图像模块为 P0 |
| ② | 标注用自动框，按类别分文件夹 | 每类人工标注 |
| ③ | 带位置先用 PL 步进脉冲计数，编码器为 P1 接进同一接口 | 编码器必需 |
| ④ | 取消 STM32 过渡，直接 PL 直驱舵机总线 | W2 先走 PL → I2C → STM32 |
| ⑤ | CAN 走 PS SocketCAN；RS485 降 P1 | CAN 用 PL IP；CAN + RS485 都是 P0 |
| ⑥ | 只做一个 HDMI 界面；Web UI 降 P2 | Qt + Web 双 UI |
| ⑦ | 沿用厂家内核 / 根文件系统 / 设备树，只换 `BOOT.bin` 里的比特流；`/dev/mem` 访问寄存器（✅ 已验证可用） | 完整 Buildroot 重编 |
| ⑧ | PS 算 IK 和路径点，PL 管 SYNC WRITE 时序和遥测；`traj_interp` 降 P2 | `traj_interp` 为 P1 |
