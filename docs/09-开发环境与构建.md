⚠ WSL 自带的 `gcc-aarch64-linux-gnu` 链接 glibc 2.35，编出的程序在板上跑不了（除非静态链接），用 FD 自带的那套。

## 板上系统

- 底座：米联客 NPU demo 预编译镜像。内核 6.1.111-rt42（Linaro GCC 7.5 编译），用户态 **Buildroot 2022.02.6**，BusyBox，OpenSSH。
- 自带：ArmNN 32.1 + Alnpu backend、OpenCV 4.7 / FFmpeg（`/opt`）、**Qt 5.15.8**、gdbserver、`fdisk` / `mke2fs` / `mkdosfs`。没有：`apt`、编译器、SQLite、Python、`resize2fs`。
- 无 RTC：每次开机时间从 1970 起算，需联网对时或开机设置。
- PL 外设地址（设备树）：`vdmafb` 0x80100000、`axi_dynclk` 0x80101000、VDMA 0x80200000、`mipicam` 0x80300000、`hard_npu` 0x63f00000、`soft_npu` 0x1f0000000。

## 启动链与"什么东西存在哪"

```
上电 → BootROM 读拨码（SD = ON-OFF-OFF，eMMC = OFF-OFF-OFF）
     → 从 SD 第 1 分区读 BOOT.bin
          ├─ FSBL     初始化 DDR / 时钟 / PS 配置，把比特流烧进 PL（日志 "PL init done"）
          ├─ 比特流    整个 PL 设计
          └─ U-Boot   执行 boot.scr：读入 uImage.lz4（内核）+ system.dtb（设备树）→ bootm
     → 内核挂载根分区 /dev/mmcblk0p2（ext4）→ /init → BusyBox init
```

| 想改什么 | 改哪个文件 | 位置（板上） |
|---|---|---|
| PL 逻辑 | `BOOT.bin` | `/mnt/mmcblk0p1/BOOT.bin` |
| 外设地址 / 中断（需内核驱动时） | `system.dtb` | `/mnt/mmcblk0p1/system.dtb` |
| 启动参数 | `boot.cmd` → `mkimage` → `boot.scr` | `/mnt/mmcblk0p1/boot.scr` |
| 内核 / 驱动 | `uImage.lz4` / `.ko` | 需开发包 |
| 应用、配置、数据 | 直接放文件 | 根分区任意位置（持久化） |

### SD 卡布局（持久化，2026-10-08 起）

厂家原版把整个根文件系统打成 `uInitrd.lz4` 在内存里运行（initramfs），重启即还原。现改为：

| 分区 | 文件系统 | 板上挂载点 | 内容 |
|---|---|---|---|
| p1（256MB） | FAT32 | `/mnt/mmcblk0p1` | `BOOT.bin` `boot.scr` `system.dtb` `uImage.lz4` + `initramfs_backup/`（回退用） |
| p2（3.8GB） | ext4 | `/`（另被 automount 再挂一次到 `/mnt/mmcblk0p2`，同一分区） | Buildroot 根文件系统（从 `uInitrd.lz4` 解出） |

与厂家版的差别只在 `boot.scr`：不再加载 initrd，`bootargs` 追加 `root=/dev/mmcblk0p2 rootwait rootfstype=ext4 rw init=/init`，`bootm 0x10000000 - 0x14000000`。写法照抄官方 Ubuntu demo。生成脚本：[scripts/sd_image/](../scripts/sd_image/)。

卡上剩余约 25GB 未分区；需要时用 `fdisk` 建 p3 + `mke2fs` 作数据分区（板上无 `resize2fs`，不能直接扩 p2）。

## PL：改逻辑 → 编译 → 打包

1. **改源码**（TD 6.2.1 打开 `pl/soc_base/soc_prj.al`，工程已入库——仓库里就是 6.2.1 原格式，不产生格式升级。⚠ 不要用 2026.1/6.2.2 打开：会触发格式升级并产生大量本地 diff，这种 diff 一律不提交。我们的源码改动只进 `pl/soc_patch/`）：新模块放 `src/`，在 `system_top.v` 里例化；需要 PS 读写的寄存器做成 AXI-Lite 从机挂到 `design_0`；管脚加进 `src/constraint/`（CEP = BANK11，3.3V）。
2. **编译**：综合 → 布局布线 → 生成比特流（耗时主要在这里）。
3. **打包**：`scripts/bootbin/make_bootbin.ps1 -Bit <xxx.bit>`，几秒钟。
4. **部署**：替换 `/mnt/mmcblk0p1/BOOT.bin` → `sync` → 重启。注意串口 `[BOOT INFO] Bitstream Generation` 的日期来自 FSBL（hpf 导出信息），**只换比特流时不会变**；确认新逻辑生效要看功能现象或读 PL 寄存器。

**命令行编译官方工程**（2026-10-10 实测，不开图形界面）：在 `soc_prj_Runs/syn_1`、`phy_1` 下依次运行
`td_commands_prompt.exe D:/ANLU/TD/scripts/DefaultFlow.tcl < NUL`（路径用正斜杠，反斜杠会被 Tcl 当转义吃掉）。
综合约 6 分钟、布局约 10 分钟、布线约 19.5 分钟，峰值内存约 5GB。原样重编的比特流与厂家逐位一致；
时序报告 SWNS −4.120ns / HWNS −2.594ns 与厂家相同 —— **原设计本身就有时序违例**，加模块时以此为基线，不要变差。
长时间编译建议作为独立进程运行（如 `Start-Process`），避免被会话里的后台任务管理误停。

**什么时候要重编 FSBL**：只改 PL 逻辑不用；改了 `design_0` 的 PS 配置（增删 AXI 口、PL 时钟 FCLK、MIO、DDR）要用 FD 按新 `.hpf` 重编（Platform 工程 `soc_base` + Application 工程 `soc_fsbl`，模板 FSBL，名字不能改），通过 `-Fsbl` 传入。U-Boot 永远不用动。

**AXI 地址窗口一次划够并固定**：之后只改模块内部，设备树不用动。

`BOOT.bin` 结构（BootGen `-read` 实测）：P0 FSBL（载入 OCM 0x61000000）/ P1 比特流（`destination_device=pl`）/ P2 U-Boot（载入并执行于 0x200000）。

## PS：应用开发

```bash
# Windows 下用 FD 自带编译器（或在 WSL 里调用同一套）
aarch64-linux-gnu-gcc -O2 main.c -o app
```

- **访问 PL 寄存器**：`/dev/mem` 可用（2026-10-09 实测 `devmem 0x80300000` → `0x1BB00000`），应用以 root 运行直接 `mmap`，不需要写驱动：
  ```c
  int fd = open("/dev/mem", O_RDWR | O_SYNC);
  volatile uint32_t *reg = mmap(NULL, 0x1000, PROT_READ | PROT_WRITE, MAP_SHARED, fd, PL_BASE);
  ```
  调试可直接用 `devmem <地址> [32 <值>]`。
- PL 中断要通知应用时需要 UIO（改设备树，可能要改内核配置）→ 届时再用开发包。
- Qt 应用：板上已有 Qt 5.15.8 运行库；编译需要对应的头文件与库（从 Buildroot 输出或官方 Qt demo 环境取）。
- SQLite：板上没有，把 amalgamation（单个 `sqlite3.c`）直接编进应用。
- 摄像头 / NPU 参考：厂家 `demo/sdk/face_detection.tar.gz`（`yolo_demo_hdmi_camera` 源码），运行脚本在 `/opt/scripts/`。

## 部署

| 方式 | 适合 | 说明 |
|---|---|---|
| 网线 + `scp` | 所有文件 | 见下 |
| SD 卡插电脑 | 只能放 p1 | Windows 看不到 ext4 分区 |
| U 盘 | 所有文件 | 插板子 USB 自动挂载到 `/mnt/sdX` |

**网络与 SSH（2026-10-09 配好）**
- 网线插板子的 **PS 网口**（Linux 只有一个 `eth0`；PL 网口需要比特流里有对应网卡逻辑，当前不工作），另一端直连电脑有线网口，电脑侧设固定 IP `192.168.137.1/24`。
- 板子 `eth0` 由 dhcpcd 管理，固定 IP 写在 `/etc/dhcpcd.conf` 末尾（`interface eth0` / `static ip_address=192.168.137.100/24` / `static routers=192.168.137.1`），原文件备份为 `/etc/dhcpcd.conf.orig`。
- 免密登录：电脑生成 ed25519 密钥，公钥追加到板子 `/root/.ssh/authorized_keys`。之后 `ssh -i <密钥> root@192.168.137.100`，`scp` 同理。
- 首次连接若报 "REMOTE HOST IDENTIFICATION HAS CHANGED"：旧 initramfs 系统每次开机重新生成主机密钥所致。先经串口 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 核对指纹，一致后 `ssh-keygen -R 192.168.137.100`。持久化根分区后主机密钥不再变化。
- 板上 BusyBox 没有 `timeout`、`pkill`；限时运行用后台 + `sleep`。

## 操作禁忌

- **Linux 运行时禁止用 BitWriter 往 SRAM 下载比特流**：会覆盖 Linux 依赖的 MIPI / VDMA / HDMI / NPU 软核。独立测试 bit（如 [pl/test/step_test](../pl/test/step_test/)）只能在不跑 Linux 时下载；SRAM 下载易失，断电重启即恢复。
- **关机用 `poweroff`，或先 `sync`**：根分区是真实 ext4，直接断电可能丢最近写入。
- **eMMC（`/mnt/mmcblk1p*`）是出厂系统，留作救生艇，不要写**。
- 厂家脚本 `run_mipicam_fb_fire_recognition.sh` 缺 `--server` 参数，手动补 `-s <ip:port>`；脚本外直接运行 `yolo_demo_hdmi_camera` 会缺库（`LD_LIBRARY_PATH` 在脚本里设）。
- 换 `BOOT.bin` 前把原文件改名备份（如 `BOOT.bin.vendor`），起不来就改回。
