# 视觉与检测

> 检测对象、类别表、数据集与模型上板路线；实测数字见 [测试与验证](测试与验证.md)，明细见 `log/`。

## 检测对象（✅ 定版）

**多规格、多颜色的 POM 齿轮**（纯塑胶注塑件）：宽度在夹爪张口内、有 ≥8mm 夹持高度、平放稳定，有标准几何尺寸便于测量。场景：塑胶传动件注塑后在线质检分拣。齿条已取消；齿条测量代码保留。

- **规格**（20 / 28 / 30 / 36 齿、孔 6 / 8）由几何测量判、**颜色**由裁切图色调判，不进 NPU 类别。

- **类别表五处同源**：训练 / NPU JSON / 分拣映射 / UI / 数据库共用 `models/label_list.json` 一份。

## 缺陷制造（冷加工，可复现）

| 缺陷 | 做法 |
|---|---|
| 缺料 | 锉齿顶 / 剪整齿 |
| 飞边 | 同色 AB 补土卡进齿槽 |
| 黑点 | 油漆笔点后刷透明指甲油封 |

缺陷要在相机分辨率下看得见：视野约 350mm 宽 / 1920px ≈ 0.18mm/px；需要时降低相机高度把视野收到约 200mm（≈0.1mm/px）。

## 数据集

- 每类 ≥300 张、≥30 个零件（共 ≥2400 张）；覆盖不同位置、朝向、进入方向、亮度扰动。train/val = 9:1。
- **独立测试集按实物样本划分**：每类 2~3 个从未参与训练的实物样本。
- 必须在**最终光学条件**下采（两侧条形光、最终相机高度），否则要重采；光源为人工手动（不接 PL）→ 全程档位固定并记录。
- 采集：`des_tool collect`（`ps/src/app/collector`）每次只放一类，PS 用轮廓自动生成框，标注退化为"按类别分文件夹"；物料贴死时自动框出错就丢弃该帧。

## 视觉定位与角度

- 夹爪随机姿态抓取需要角度 θ：PS 端对降采样灰度图阈值 + 轮廓 → `minAreaRect` 得 x, y, θ, 宽, 高；近方形物料取窄边方向夹。另一路径是二值 blob 二阶矩 `θ = ½·atan2(2μ11, μ20−μ02)`。
- 两件贴死时连通域会连成一个 blob → 判"粘连"不抓、流到带尾复检。
- 主线在 PS（`ps/src/app/locate`，1/4 降采样）；PL `des_vision` 只做显示与粗测。定位耗时见 [测试与验证](测试与验证.md)。

## 相机标定（像素 → 台面毫米）

`des_tool calib-cam`（`ps/src/measure/calib`）：一张平放在皮带上的棋盘格 → **皮带平面单应矩阵**，写进 `calib.json`，`load_config` 读完 `des_app.json` 后自动合并。

**台面坐标系**：x 沿皮带前进方向；y 是从上往下看 x 逆时针转 90°（右手系，z 朝上，机械臂 IK 依赖这一点，不能镜像）。**原点**：x = 0 在视野上游边缘（画面中线处），y = 0 在画面中线。抓取线、带尾位置都用尺子从视野上游边缘量。

**操作**：
0. **标定板用 A4 打印即可**：[pc/calib_board/标定板_A4_9x6_25mm.pdf](../pc/calib_board/标定板_A4_9x6_25mm.pdf)（10×7 格、格边 25mm、内角点 9×6，约占视野 63%×78%；`make_board.py` 可改格数 / 格边）。打印选「实际大小 / 100%」，贴在硬平板上（KT 板 / 亚克力，不起翘、不反光）。
1. 标定板**平放在皮带上，一条边贴着侧挡边**（板的一条轴 = 皮带方向）；整块板都在画面里，最好占画面一半以上。
2. **卡尺量一格的边长**（打印件会缩放，以实测为准）。
3. `/root/des/des_tool.sh calib-cam --board <列>x<行> --square <mm> --travel right --dump /root/des/calib.png`
   - `--board` 是**内角点**数（黑白格交点）：10×7 个格子 → `9x6`；
   - `--travel` 是皮带在画面里往哪边走（right / left / down / up）。
4. 看输出的残差（rms / max）和 `calib.png`：红色 x 箭头应指向皮带前进方向，网格每格 50mm。

**限制**：单应只描述**皮带平面**。零件顶面比带面高（齿轮约 10mm）→ 有视差，见「视差」。视差校正 / 镜头畸变校正属测量功能（P1）。

**检测速度与超时**：先用经典角点检测（约 0.12s），不行再用半分辨率 sector 检测，再不行才全分辨率穷举（约 12s，要加 `--exhaustive`）。⚠ `--board` 填错（不是内角点数）时 OpenCV 经典检测器会搜索好几分钟 → `calib-cam` 把检测放在子进程里，默认 20s（`--exhaustive` 时 120s）没结果就杀掉并提示检查内角点数。

### 传送带标定（mm / 步 + 方向，`des_tool calib-belt`）

相机标定之后做。**一个零件**放在皮带上、画面上游边缘附近（整件在画面里）→ `/root/des/des_tool.sh calib-belt`：
1. 短走约 8mm（按配置里的 mm/步）→ 粗比例 + 方向；
2. 长走到画面约 75% 处 → 用整段位移 / 总步数算 mm/步（位置取 7 帧静止中位数）；
3. 退回起点 → **往返误差**（打滑 / 回差）、横向漂移（mm / 100mm，> 2 说明相机 x 轴没沿皮带或跑偏）、等效辊径。

结果写进 `calib.json` 的 `belt` 段（`load_config` 合并，覆盖 `des_app.json`）；重跑 `calib-cam` 时保留 `belt` 段。选项：`--belt <mm/s>`（默认 20）、`--steps <长走步数>`、`--out`。两段比例差 > 25% 或零件没动会报错不写。当前 mm/步与往返误差见 [测试与验证](测试与验证.md)。

### 计米轮编码器标定（mm / 计数 + 方向，`des_tool calib-enc`）

计米轮（E6B2-CWZ6C 1000 线，PL `des_io` 4 倍频 → 名义 200mm 周长 / 4000 = 0.05mm / 计数）压在带面上，量的是**皮带本身**，不经过主动辊。`calib-belt` 之后做，**空皮带**：`/root/des/des_tool.sh calib-enc -n 3` —— 每轮下游走 300mm（`--steps` 可改）再退回，全程每 10ms 采一次（时间、步进位置、编码器计数），不用相机。输出：mm / 计数与方向（多轮均值 ± 标准差）、轮周长、往返误差、加减速滞后、匀速段实测带速均值 ± 标准差、Z 脉冲数、非法 A/B 跳变数（> 0 = 干扰或太快 → 加 4.7k 上拉）→ `calib.json` 的 `encoder` 段（`load_config` 合并到 `belt.enc_mm_per_count / enc_dir`，重跑 `calib-cam` 时保留）。编码器不计数时（没接 / 没压到带面）报错不写。

界面：编码器计过数之后，总览右上角「带速 xx 实测 xx」、参数页状态条「带速 / 实测」、曲线页绿线 = 编码器实测带速（0.5s 窗）。跟踪抓取仍用步进位置（帧起始锁存 `CAP_POS`）；编码器先用来验证打滑。

### 平场（零件裁切图亮度归一，`des_tool calib-flat`）

4.2mm 广角镜头的渐晕加上两侧条形光的不均，视野边缘只有中心的 40~70%（四角最低 37%）：同一个零件在画面不同位置裁出来亮度不同，NPU 会把它当成差异。`calib-flat`：一张空白 A4 横放在上料端、盖住视野上游边，皮带每次带它走 40mm（`--steps` 可改），每站 4 帧平均，直到纸的前沿到达视野下游边再多一站，然后退回。每个像素在「自己的最暗 ~ 最亮」之间超过 60% 且离纸边 25px 以上才算纸面（渐晕不影响判断），求平均 → 平滑 → 48×27 白电平网格 → 与 `des_app.json` 同目录的 `flat.json`（`flat_file`，相机重标不覆盖）。`crop_part` 把每张裁切图乘 ref / white（白电平按裁切图 8×8 节点取值再插值，增益限 1/3~3）——NPU 输入、NG 存图、训练集都走它，训练与推理一致；几何测量和定位用原始帧，不受影响。**换相机位置、灯光、曝光后重做**，并重采训练图。实测数据见 [测试与验证](测试与验证.md)。

## 几何测量（P1，`ps/src/measure/measure`）

管「尺寸超差 / 规格混料」两类 NPU 不判的 NG，也给缺齿 / 缺料 / 飞边一个与 NPU 无关的第二意见。每件只在**一帧**里测（见「视差」）。

**流程**：ROI 二值化（Otsu 只用来找轮廓）→ 外轮廓 + 最大内孔 → 沿每个轮廓点的法线找灰度穿过 **50% 电平**（皮带、零件两类灰度中位数的中点）的亚像素位置 → 单应映射到台面 mm → 视差校正 → 拟合。

| 输出 | 方法 |
|---|---|
| 外径（齿顶圆）、根径、孔径、偏心（孔心 − 齿顶圆心）、**规格齿数**、缺料齿 / 缺齿 / 飞边齿槽数、r(θ) 曲线（720 点，UI 画图用） | r(θ) 过半高的段 = 齿；**规格齿数由齿距算**（30 齿缺 2 个和 28 齿都只看到 28 个齿，但 28 齿的齿距是均匀的 12.86°）：先取相邻齿间隔的中位数，再取中位数 ±25% 以内间隔的**平均**（10-24 改：齿中心只精确到半格 0.25°，缺齿处的双倍间隔会把中位数推高半格 → 720 ÷ 24.5 读成 29 齿、齿相位网格错位、缺齿 / 飞边报十几个，实物缺齿件约 1/20 帧；齿相位网格同样用平均齿距）；齿顶圆只用法线接近径向的点拟合（模糊会把窄齿顶两角磨圆，混进来外径偏小 0.05mm） |

**飞边三种样子都要判**：① 齿槽底被填高（槽底比中位槽底高 > `flash_mm`）；② 填到半高以上、两齿连成一段（宽度 = (n−1) 个齿距 + 1 个齿宽 → 多出的齿数 = 飞边）；③ 齿槽中间立着一小块（看着像多一个齿）→ 按**齿相位**判：齿只在齿距网格上，偏离网格 ¼ 齿距以上的段是槽里的料。

**标准件偏置**（`measure.od_offset_mm` / `bore_offset_mm`，只加在报告值上，齿判定用原始拟合）：窄齿尖模糊后灰度到不了零件亮度，50% 边缘落在真实齿尖里面 → 外径读小；齿根与孔是宽轮廓，不受影响。偏置值与实测重复性见 [测试与验证](测试与验证.md)（孔径同样读小：亮顶面往孔里扩）。**位置**：尺寸只在画面中心附近可靠——外径横向偏离中线 42mm 就偏小 0.2~0.55，零件须由导向条约束在中线 ±10mm 内；孔径远离中心会偏大（远侧内壁被对面灯照亮，边界深度不定）→ `bore_near_arc`：中心沿用原逻辑，离开中心只用靠光轴一侧的孔口圆弧（横向 ±42mm 实测 ±0.1），⚠ 沿带小偏离时偏小，默认关。**换曝光 / 灯光 / 相机后重做**（`des_tool.sh measure -n 20`，标准件放画面正中）。

**视差**（`camera_h_mm` 填实测相机高度后启用；当前配置 4.2mm 镜头、H 295mm、侧壁亮模型，三齿轮扫描实测位置放大 k≈1.020；下面用 8mm 镜头 / H≈360mm 作推导示例）：
- 侧壁亮（默认，`walls_visible = true`）：亮区 = 从底面（×1）到顶面（×k）所有截面的并集。远离光轴一侧的边是顶面边（缩回 1/k），朝向光轴一侧的是底面边（不动）；沿光轴射线方向的边是竖棱的投影，直接丢掉。
- **拖影限制**：每条边沿「离开光轴」方向被拖长 smear = (k−1)·|中心 − 光轴|。拖影顺着齿排方向时会把齿槽填平：中心离光轴 112mm 时拖 3.2mm ≈ 1 个齿距。→ smear > `max_smear_mm`（0.6mm，10-24 由 0.8 收紧）时**外径 / 孔径照常给（已校正），齿的判定不做**（`teeth_judged = false`）。现 H=295、厚 10.05 → 系数 0.035/mm，对应零件中心离光轴 ≤ 17mm。10-24 实测：拖影 0.23~0.57 齿形判定全对，0.78 时 40 帧有 4 帧齿距数错一个、报缺齿 / 飞边 11~12（其实正中也会出现，根因是上面的齿距中位数，已改为平均；[log/2026-10-24-缺齿样品初测](log/2026-10-24-缺齿样品初测.md)）；导向条把零件收在中线 ±10mm 时拖影 ≤ 0.36。
  - 跟踪里每件**选离光轴最近的那一帧测**；横向偏移只能靠摆放，或带上加导向条把件往中线赶。还超的 → 复检。
- 侧壁暗（只有顶面亮，`walls_visible = false`）：整件按 1/k 缩回，没有拖影限制。⚠ 打光定了以后看实拍图决定用哪种。
- ⚠「光轴」默认取画面中心映射到台面（`axis_from_image`），只在相机垂直向下时成立；视差真正的中心是**相机正下方那一点**。相机倾斜时两者分开 → 先把相机调平（≤2°），否则用 `axis_table` 填正下方点。
- 视差同样影响**位置**：`load_config` 把「绕正下方点按 1/k 缩放」并进单应得 `px_to_part`（`measure_config.hpp` `part_homography`；侧壁暗 k = H/(H−h)，侧壁亮时斑点中心在顶面与底面中间，k = (2H−h)/(2(H−h))）——定位、跟踪、PL ROI、画面叠加、零件裁切全部用它，几何测量照旧用带面单应（它逐个边缘点自己校正）。只有 `measure.camera_h_mm` 填了实测值才生效。

**合成图测试**：`ps/tests/test_measure.cpp` / `test_calib.cpp` 全过，像素↔台面残差、几何测量误差、视差校正前后对比等数字见 [测试与验证](测试与验证.md)。⚠ 合成图精度 ≠ 实测精度：实拍还有镜头畸变（P1）、标定误差、零件边缘倒角 / 毛刺、光照不均；实测精度用卡尺量过的良品件标（样本登记表在仓库外），报告里分开写。

**卷帘快门**：传感器逐行曝光，整帧读出约 16ms，皮带在此期间走了 b1−b0（PL 锁存的帧首 / 帧尾带位置）。每个边缘点按所在行退回到帧中间那一刻（`belt_mm_per_row`，与定位的行时间补偿同一口径）。

**接入 `des_app run`（✅）**：`app/track_measure`（`TrackMeasurer`）在核 1 工作线程、跟踪表更新之后运行：
- 每帧最多测 `per_frame`（默认 1）件，**没测过的优先**，之后只有「离光轴距离 < 0.75 × 上次 − 1mm」才重测 → 每件留下离光轴最近那一帧的结果；
- 只测整个外框（+3mm）都在画面里的件；ROI 直接从相机缓冲转灰度，测完若该缓冲已被 DMA 复用就丢弃结果；
- 结果存进跟踪表 `Track::meas`（`PartMeasure`），画面标签显示 `OD32.02 z30`（带 `?` = 视差过大、齿未判），CAN 每件结果的 `size_mm` 改为测量值（0 = 没测到）；
- **判定**（`tracker` 的 `SizeRule`，`des_app.json` 的 `measure.rule`，默认关）：只改判「按类别要抓取」的件（不把 NPU 的 NG 改成 OK）——规格齿数不符（28 齿）/ 外径超差（32±0.15）/ 孔径超差 / 偏心 > 0.3 → 导流挡板 `scrap`；NPU 判 OK 但测到缺齿 / 缺料 / 飞边（且齿已判）→ 复检。公差取自测量功能文档（仓库外）的配方示例。
- 耗时见 [测试与验证](测试与验证.md)（自动测试在 `ps/tests/`，构建时运行）。

**待实测（⚠）**：实拍边缘的灰度过渡宽度、换件 / 换位置的卡尺交叉验证、实物验证集分类准确率、自训模型走通「训练 → 截断 → 量化 → JSON → 上板」。以上完成后再开 `measure.rule.enabled`。相机高度、齿轮厚度与标定值已实测，见 [测试与验证](测试与验证.md)。

## 模型与量化路线

官方两个 ONNX 已逆向：量化格式为 **QDQ / UINT8 / per-tensor**，`fire_detect` 的 producer 是 ORT `quantize_static` 的签名，结构是标准 ultralytics YOLOv8n（Detect 前截断）。详见 [log/2026-09-20](log/2026-09-20-NPU与硬件实测.md)。

**✅ 已定：PS 定位 + 每件 ROI 裁切 → NPU 分类（YOLOv8n-cls @ 224，激活换 ReLU）。**
- 原因：镜头 = 相机自带 **4.2mm**（H72° V56°）；IMX415 全幅 2×2 合并读出（`WINMODE=0`、`HADD/VADD=1`），1080p 保留全视场，实测标定 0.1945mm/像素。H≈295mm → 视场约 373×214mm；整帧缩到 416 约 0.9mm/像素，1mm 的黑点 / 缺料只剩约 1 像素，按零件裁 56mm→224px 约 4 像素。
- 做法：`roi_crop`（零件中心、转正到零件轴向）→ NPU 分 4 类 → 每件分类 3~6 次，概率软投票（`Tracker::vote`），置信度 = 胜出类的平均概率。定位、多件跟踪仍是 OpenCV（已在 60fps 主循环里）。
- 标注：采集时一次只放一类（`des_tool collect --cls`），裁切图按类别存文件夹，不用画框。
- 工具链：`train/`（合成数据冒烟 → 训练 → 导出去 Softmax → ORT QDQ/UINT8/per-tensor 量化 → 板上 `test_npu` 核对 + 测耗时）。
- 板上实测：单次推理耗时、加载时间与准确率见 [测试与验证](测试与验证.md)。量化后必须 `infer_shapes`，否则板上 ArmNN 解析器段错误。

**备选路线（未采用）**：整帧检测 YOLOv8n @ 416×416，实测 NPU 纯推理约 26ms 量级；1mm 缺陷在整帧上只剩约 1 像素，精度不够，故改分类路线。导出 / 量化流程与分类路线同为 QDQ/UINT8/per-tensor（`quantize_static`，校准集 100~300 张），采集时 `des_tool collect --full N` 可同时存整帧 + 自动框。原始流程记录见 [log/2026-09-20](log/2026-09-20-NPU与硬件实测.md)。

帧率不够时的退路：走 `yolo_face` 的极简路线（416、13 层 Conv、纯 ReLU、双头 anchor 版）；最保守兜底：照 `fire_detect` 原结构训，只改输出通道数。
