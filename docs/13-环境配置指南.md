# 13 · 环境配置指南

> 解决硬编码路径问题，让项目可以在不同电脑上无缝运行

## 问题背景

项目早期直接在脚本和 Makefile 中硬编码了本机路径（各人机器不同，换台电脑后所有命令都要手改），现在引入 `.env` 配置文件来统一管理。

## 配置系统组成

| 文件 | 作用 | 入库 |
|---|---|---|
| [.env.example](../.env.example) | 配置模板，列出全部配置项 | ✅ |
| `.env` | 你本机的实际路径 | ❌（`.gitignore` 已排除） |
| `.env.make` | 由 `.env` 生成，供 `ps/Makefile` include | ❌ |
| [scripts/env_loader.ps1](../scripts/env_loader.ps1) / [.sh](../scripts/env_loader.sh) | 手动加载进当前会话（`. .\scripts\env_loader.ps1` / `source scripts/env_loader.sh`），顺手报告各路径是否存在 | ✅ |
| [scripts/generate_env_make.sh](../scripts/generate_env_make.sh) | 从 `.env` 生成 `.env.make` | ✅ |
| [scripts/test_env.ps1](../scripts/test_env.ps1) | 逐项检查关键路径并给结论 | ✅ |

**自动加载 `.env` 的入口**（不需要手动 source）：[scripts/bootbin/make_bootbin.ps1](../scripts/bootbin/make_bootbin.ps1)、[scripts/sd_image/make_sd_image.sh](../scripts/sd_image/make_sd_image.sh)、`ps/Makefile`（`-include ../.env.make`）。命令行显式传参优先级最高。

## 快速开始

### 1. 创建配置文件

```bash
# 从模板复制
cp .env.example .env

# 编辑 .env 文件，填入你的本机路径
# Windows: 用记事本或 VS Code 打开
# Linux/WSL: 用你喜欢的编辑器
notepad .env    # Windows
nano .env       # Linux/WSL
```

### 2. 填写关键路径

`.env` 里每个变量指向什么、从哪里拿：

| 变量 | 指向什么 | 怎么拿到 |
|---|---|---|
| `FD_ROOT` | FD 安装目录（含 `toolchain/gcc/aarch64_linux/`） | 安路官网下载安装 |
| `TD_ROOT` | TD 6.2.1 安装目录（含 `license/`、`bin/`） | 同上 |
| `NPU_DEMO` | 厂家 NPU demo 解压目录（含 `boot/`、`soc_sdk/`、`soc_prj/`） | 米联客论坛，见 [00-快速上手](00-快速上手.md) |
| `SDK_LIBS` | 厂家 `face_detection/libs`（含 `armnn_lib/`、`ffmpeg_opencv4.7.0_aarch64/`） | 从 NPU demo 解压 |
| `FREETYPE_INC` | FreeType 头文件目录 | 从板上 `scp` 或官网源码包 |
| `BOARD_LIBS` | 板上库的本地拷贝目录（`libfreetype.so.6` 等） | 从板上 `scp` |

前两个是工具链；后四个是厂家资料和板上库，**自行获取、不入库**——不编译 PS 代码时可以留空，`ps/Makefile` 只在编 `des_app` / `test_calib` / `test_measure` / `test_npu` 时才检查它们。填完自检：

```powershell
.\scripts\test_env.ps1
```

### 3. 生成派生配置（可选）

```bash
# 为 Makefile 生成配置
bash scripts/generate_env_make.sh
```

## 使用方式

### PowerShell 脚本

**自动加载（推荐）**：脚本会自动检测并加载 `.env`

```powershell
# 直接运行即可
.\scripts\bootbin\make_bootbin.ps1 -Bit path/to/your.bit
```

**手动加载**：如果需要在当前会话使用环境变量

```powershell
. .\scripts\env_loader.ps1
# 现在 $env:FD_ROOT 等变量已可用
```

### Bash 脚本

**自动加载**：脚本会尝试自动加载 `.env`

```bash
# WSL 中运行
sudo bash scripts/sd_image/make_sd_image.sh
```

**手动加载**：

```bash
source scripts/env_loader.sh
# 现在 $FD_ROOT 等变量已可用
```

### Makefile

Makefile 会自动尝试 include `.env.make`（由 `generate_env_make.sh` 生成）。**它没有任何主机路径默认值**：没配就报错并告诉你下一步，不会默默去用某台机器上的目录。

```bash
# 生成 .env.make（首次或 .env 修改后运行）
bash scripts/generate_env_make.sh

# 然后正常使用 make
make -C ps all
```

或者直接命令行覆盖：

```bash
make -C ps CROSS=<工具链前缀> SDK_LIBS=<face_detection/libs 目录>
```

## 路径格式说明

### Windows 路径

在 `.env` 中统一使用**正斜杠**或**反斜杠**都可以，脚本会自动处理：

```bash
# 这两种写法都可以（<盘符> 指你实际的盘）
FD_ROOT=<盘符>:/目录/FD
FD_ROOT=<盘符>:\目录\FD
```

### WSL 路径

如果路径需要在 WSL 中使用，可以写 Windows 格式或 WSL 格式：

```bash
# Windows 格式（脚本会自动转换）
NPU_DEMO=<盘符>:/目录/demo

# WSL 格式（直接使用）
NPU_DEMO=/mnt/<盘符小写>/目录/demo

# 使用 $HOME（推荐，跨用户兼容）
DES_WORK_DIR=$HOME/des-work
```

## 环境变量优先级

1. **命令行参数**（最高优先级）
   ```powershell
   .\make_bootbin.ps1 -FdRoot "<FD 安装目录>"
   ```

2. **Shell 环境变量**
   ```bash
   export FD_ROOT=<FD 安装目录>
   ./script.sh
   ```

3. **.env 文件**
   ```bash
   FD_ROOT=<FD 安装目录>
   ```

4. **没有默认值**：`.env` 与命令行都没给时，`ps/Makefile` 直接报错并提示怎么配（不再硬编码某台机器的路径）；`scripts/` 下的脚本同理，缺变量会要求你先加载 `.env`。

## 配置验证

### 检查配置是否正确

**PowerShell**:
```powershell
. .\scripts\env_loader.ps1
# 会显示关键路径是否存在
```

**Bash**:
```bash
source scripts/env_loader.sh
# 会验证并显示路径状态
```

### 常见问题

**问题**: 提示"找不到 .env 文件"

**解决**: 
```bash
cp .env.example .env
# 然后编辑 .env
```

---

**问题**: 路径存在但提示"路径不存在"

**解决**: 检查路径格式，确保没有多余空格，Windows 路径使用正斜杠 `/`

---

**问题**: `make -C ps` 报 `FD_ROOT 未设置` 或 `SDK_LIBS 未设置或目录不存在`

**解决**: `ps/Makefile` 故意不留主机路径默认值，报错就是没配好。依次做：

```bash
cp .env.example .env          # 填好路径
bash scripts/generate_env_make.sh   # 重新生成 .env.make
```

报"目录不存在"说明 `.env` / `.env.make` 里那条路径在本机不成立（换了电脑、盘符变了、资料挪了位置）——改 `.env` 后**必须重新生成** `.env.make`。

---

**问题**: 为什么不直接改脚本 / Makefile 里的路径？

**解决**: 那样会产生大量 diff、和队友的改动冲突，而且换台电脑又得改一遍。路径统一写在**不入库**的 `.env` 里，每人一份；脚本与文档一律只用变量名引用（`$FD_ROOT`、`$SDK_LIBS`…），这也是 [AGENTS.md](../AGENTS.md) 硬性约定第 9 条。

---

**问题**: 换一台电脑怎么办？

**解决**: 克隆仓库 → `cp .env.example .env` → 填路径 → `scripts/test_env.ps1` 自检 → `bash scripts/generate_env_make.sh`。注意 `.env.make` 是**生成物**，换机后必须重新生成，它不会自动跟随 `.env`。

---

**问题**: CI / 无人值守环境怎么用？

**解决**: 不放 `.env`，直接设环境变量（优先级高于 `.env`）：

```bash
export FD_ROOT=<FD 安装目录> NPU_DEMO=<NPU demo 目录>
make -C ps all
```

## 团队协作建议

1. **`.env` 由 .gitignore 排除**，只留在本机
2. **更新 `.env.example`** 当新增配置项时
3. **在文档中只引用环境变量**，不写死路径
4. **CI/CD 中设置环境变量**而不是依赖 .env 文件
