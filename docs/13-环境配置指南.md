# 13 · 环境配置指南

> 解决硬编码路径问题，让项目可以在不同电脑上无缝运行

## 问题背景

项目早期直接在脚本和 Makefile 中硬编码了本机路径（如 `D:/ANLU/FD`），导致换台电脑后所有命令都需要手动修改路径。现在引入 `.env` 配置文件来统一管理。

## 配置系统组成

| 文件 | 作用 | 入库 |
|---|---|---|
| [.env.example](../.env.example) | 配置模板，列出全部配置项 | ✅ |
| `.env` | 你本机的实际路径 | ❌（`.gitignore` 已排除） |
| `.env.make` | 由 `.env` 生成，供 `ps/Makefile` include | ❌ |
| [scripts/env_loader.ps1](../scripts/env_loader.ps1) / [.sh](../scripts/env_loader.sh) | 手动加载进当前会话（`. .\scripts\env_loader.ps1` / `source scripts/env_loader.sh`），顺手报告各路径是否存在 | ✅ |
| [scripts/generate_env_make.sh](../scripts/generate_env_make.sh) | 从 `.env` 生成 `.env.make` | ✅ |
| [scripts/test_env.ps1](../scripts/test_env.ps1) | 逐项检查关键路径并给结论 | ✅ |

**自动加载 `.env` 的入口**（不需要手动 source）：[scripts/bootbin/make_bootbin.ps1](../scripts/bootbin/make_bootbin.ps1)、[scripts/sd_image/make_sd_image.sh](../scripts/sd_image/make_sd_image.sh)、`ps/Makefile`（`-include ../.env.make`）。命令行显式传参优先级最高。

## 快速开始

### 1. 创建配置文件

```bash
# 从模板复制
cp .env.example .env

# 编辑 .env 文件，填入你的本机路径
# Windows: 用记事本或 VS Code 打开
# Linux/WSL: 用你喜欢的编辑器
notepad .env    # Windows
nano .env       # Linux/WSL
```

### 2. 填写关键路径

在 `.env` 中至少配置以下路径：

```bash
# ===== 必填项 =====
# FD 工具安装目录（包含 toolchain/gcc/aarch64_linux）
FD_ROOT=C:/Anlogic/FD_2026.1_SP1

# TD 工具安装目录
TD_ROOT=C:/Anlogic/TD_Release_6.2.1

# NPU Demo 解压目录（包含 boot/soc_sdk/soc_prj）
NPU_DEMO=D:/Downloads/demo

# ===== PS 开发需要（如果你不编译 PS 代码可暂时跳过） =====
# SDK 库目录
SDK_LIBS=D:/work/face_detection/libs

# FreeType 头文件
FREETYPE_INC=D:/work/freetype2_include

# 板上库文件本地拷贝
BOARD_LIBS=D:/work/board_libs
```

### 3. 生成派生配置（可选）

```bash
# 为 Makefile 生成配置
bash scripts/generate_env_make.sh
```

## 使用方式

### PowerShell 脚本

**自动加载（推荐）**：脚本会自动检测并加载 `.env`

```powershell
# 直接运行即可
.\scripts\bootbin\make_bootbin.ps1 -Bit path/to/your.bit
```

**手动加载**：如果需要在当前会话使用环境变量

```powershell
. .\scripts\env_loader.ps1
# 现在 $env:FD_ROOT 等变量已可用
```

### Bash 脚本

**自动加载**：脚本会尝试自动加载 `.env`

```bash
# WSL 中运行
sudo bash scripts/sd_image/make_sd_image.sh
```

**手动加载**：

```bash
source scripts/env_loader.sh
# 现在 $FD_ROOT 等变量已可用
```

### Makefile

Makefile 会自动尝试 include `.env.make`（由 `generate_env_make.sh` 生成），如果不存在则使用默认值。

```bash
# 生成 .env.make（首次或 .env 修改后运行）
bash scripts/generate_env_make.sh

# 然后正常使用 make
make -C ps all
```

或者直接命令行覆盖：

```bash
make -C ps CROSS=/path/to/cross-gcc- SDK=/path/to/sdk
```

## 路径格式说明

### Windows 路径

在 `.env` 中统一使用**正斜杠**或**反斜杠**都可以，脚本会自动处理：

```bash
# 这两种写法都可以
FD_ROOT=C:/Anlogic/FD_2026.1_SP1
FD_ROOT=C:\Anlogic\FD_2026.1_SP1
```

### WSL 路径

如果路径需要在 WSL 中使用，可以写 Windows 格式或 WSL 格式：

```bash
# Windows 格式（脚本会自动转换）
NPU_DEMO=D:/ANLU/demo

# WSL 格式（直接使用）
NPU_DEMO=/mnt/d/ANLU/demo

# 使用 $HOME（推荐，跨用户兼容）
DES_WORK_DIR=$HOME/des-work
```

## 环境变量优先级

1. **命令行参数**（最高优先级）
   ```powershell
   .\make_bootbin.ps1 -FdRoot "E:/Tools/FD"
   ```

2. **Shell 环境变量**
   ```bash
   export FD_ROOT=/opt/anlogic/fd
   ./script.sh
   ```

3. **.env 文件**
   ```bash
   FD_ROOT=C:/Anlogic/FD
   ```

4. **脚本默认值**（最低优先级，兼容旧版本）

## 配置验证

### 检查配置是否正确

**PowerShell**:
```powershell
. .\scripts\env_loader.ps1
# 会显示关键路径是否存在
```

**Bash**:
```bash
source scripts/env_loader.sh
# 会验证并显示路径状态
```

### 常见问题

**问题**: 提示"找不到 .env 文件"

**解决**: 
```bash
cp .env.example .env
# 然后编辑 .env
```

---

**问题**: 路径存在但提示"路径不存在"

**解决**: 检查路径格式，确保没有多余空格，Windows 路径使用正斜杠 `/`

---

**问题**: Makefile 仍使用旧的硬编码路径

**解决**: 
```bash
bash scripts/generate_env_make.sh
# 重新生成 .env.make
```

---

**问题**: 为什么不直接改脚本 / Makefile 里的路径？

**解决**: 脚本里的路径是**回退默认值**（Makefile 用 `?=`），留着是为了没配 `.env` 时也能跑。改脚本会产生大量 diff，还会和队友的改动冲突；`.env` 不入库，每人一份，互不干扰。

---

**问题**: 换一台电脑怎么办？

**解决**: 克隆仓库 → `cp .env.example .env` → 填路径 → `scripts/test_env.ps1` 自检 → `bash scripts/generate_env_make.sh`。注意 `.env.make` 是**生成物**，换机后必须重新生成，它不会自动跟随 `.env`。

---

**问题**: CI / 无人值守环境怎么用？

**解决**: 不放 `.env`，直接设环境变量（优先级高于 `.env`）：

```bash
export FD_ROOT=/opt/anlogic/fd NPU_DEMO=/data/demo
make -C ps all
```

## 团队协作建议

1. **`.env` 由 .gitignore 排除**，只留在本机
2. **更新 `.env.example`** 当新增配置项时
3. **在文档中只引用环境变量**，不写死路径
4. **CI/CD 中设置环境变量**而不是依赖 .env 文件
